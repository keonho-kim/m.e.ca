# 설정과 대화 보존

[← README](../README.md)

전역 설정은 ~/.meca/config.toml, 대화와 세션별 선택은 프로젝트별 세션 DB, API Key는 OS 자격 증명 저장소에 보관한다.

## 화면 언어

최상위 `language`의 기본값은 `"auto"`다. `"ko"`·`"en"`은 시스템 로캘보다 우선하는 한국어·영어 설정이며 다른 값은 거절한다. !language에서 ←→로 선택한 뒤 Enter의 저장 확인에서 y를 누르면 전역 파일에 저장하고 현재 TUI에 즉시 적용한다. 저장 전에는 적용 중인 설정을 유지한다. 직접 파일을 수정하면 재시작 후 적용한다. 새 대화·이전 대화 선택 화면에도 이 값을 사용하며 모델 응답 언어는 사용자 요청을 따른다. 자동 선택 기준과 메뉴 조작은 [사용 가이드](usage.md#화면-언어)를 따른다.

## 모델 연결 재사용

!model의 저장 확인에서 y를 누르면 현재 대화의 선택을 저장한다. 저장 범위가 모든 대화의 기본값이면 config.toml의 [model]에도 provider·endpoint·name(서빙 ID)·credential_ref와 선택적 thinking·reasoning_effort를 기록한다. 추론 강도는 모델 연결에 묶인 선택이며 새 대화 연결 시 서버 메타데이터로 재검증한다. API Key 본문은 macOS Keychain 또는 Linux Secret Service에만 저장한다.

저장된 세션의 선택이 우선이며 선택이 없는 새 세션은 전역 [model]을 사용한다. 복원 시 모델 식별·기능을 다시 확인한다. 전역 기본 연결 저장에 실패해도 이미 저장된 현재 세션 연결은 유지하고 오류를 알린다. Thinking은 세션 선택 또는 전역 기본값을 따르며 생략하면 서버 설정을 사용한다. 원본 식별은 서버가 제공한 정보를 표시한다. [모델 연결](model-connections.md)을 참고한다.

### Linux 자격 증명 전송

공식 릴리스와 `install.sh`는 `godbus_no_tcp` 태그를 적용한다. Linux Secret Service의 DBus 연결에서 `tcp:`와 `nonce-tcp:` 전송 구현 및 nonce 파일 전송을 빌드에서 제외하고 `unix:` 연결을 유지한다. macOS Keychain과 모델 API·OpenRouter·셸 네트워크 동작은 유지한다.

보장 범위는 공식 MECA 바이너리의 DBus 의존성이 TCP 전송을 제공하지 않는다는 것이다. OS 전체의 외부 통신을 차단하거나 연결한 Unix 소켓의 서비스 신뢰성까지 보장하지 않는다. 태그 없는 일반 `go build`도 가능하므로 [수동 빌드](../README.md#빌드만-하기)에는 명시적 옵션이 필요하다. Linux에서 API Key를 저장하려면 접근 가능한 Unix 세션 버스와 Secret Service가 필요하며, 저장소를 사용할 수 없으면 오류를 반환한다.

## 메인 에이전트와 보조 역할의 추론 설정

메인 에이전트는 최상위 **[agent]**, 요약·연결 진단·독립 검토·독립 메모 압축은 [compaction]·[diagnostics]·[lat]·[lat_compaction]에서 설정한다. 역할별 공통 설정을 Provider 어댑터가 각 API 형식으로 변환한다. Bootstrap은 기본값을 기록하며 생략한 필드는 현재 기본값을 사용한다. 명시한 값은 자동 덮어쓰지 않으며 직접 수정은 재시작 후 적용한다.

```toml
language = "auto"
permission = "default"
context_length = 262144
# thinking = true 또는 false를 지정하면 전역 기본값을 덮어쓴다. 생략 시 서버 기본값.

[agent]
thinking = "inherit"
temperature = 1.0
max_output_tokens = 0

[compaction]
thinking = "off_if_supported"
temperature = 0.2
max_output_tokens = 8192
reserve_tokens = 16384
keep_recent_tokens = 20000
max_summary_bytes = 16777216
max_input_bytes = 16777216

[diagnostics]
thinking = "inherit"
temperature = 0.2
max_output_tokens = 12800

[lat]
thinking = "off_if_supported"
temperature = 0.2
max_output_tokens = 4096

[lat_compaction]
thinking = "off_if_supported"
temperature = 0.2
max_output_tokens = 2048
```

| 역할 | 용도 | temperature | 기본 출력 상한 |
| --- | --- | ---: | ---: |
| agent | 직접 도구 실행·대화·최종 응답 | 1.0 | context의 75% |
| compaction | 단일 호출 대화 요약 | 0.2 | 8192 |
| diagnostics | 모델 연결·Thinking·effort 진단 | 0.2 | 12800 |
| lat | 활성 LAT의 독립 작업 검토 | 0.2 | 4096 · 유효 문맥의 1/4 이내 |
| lat_compaction | 독립 원본 자료의 백그라운드 메모 요약 | 0.2 | 2048 · 유효 문맥의 1/4 이내 |

temperature는 유한한 0~2이며 명시한 0도 전송한다. max_output_tokens는 0~1073741824다. agent·compaction·diagnostics의 0은 유효 context length의 75%를 내림 계산하는 자동 모드이며 양수는 수동 상한이다. 서버가 공개한 context·출력 한도와 남은 입력 공간도 적용한다. 서버가 제시한 한도와 설정한 상한을 함께 지키며 모델 출력 한도 초과를 명시적으로 보고한다.

[lat]의 0은 4096, [lat_compaction]의 0은 2048의 기본 상한을 사용한다. 두 역할 모두 양수 설정도 유효 문맥의 1/4을 넘지 않는다. 두 섹션은 추론 인자만 저장하며 활성화는 !lat로 현재 대화 화면에서 전환한다. 새 화면은 OFF다. 자료 조회·요약 worker도 ON에서 실제 도구 작업이 있을 때만 동작한다.

메인 에이전트는 사용자의 Thinking/effort를 계승한다. Compaction·LAT 검토·LAT 메모 압축은 서버 메타데이터 또는 Provider API에 OFF 요청 규약이 있는 연결에서 Thinking을 끄며, 제어 규약이 없으면 사용자 선택을 유지한다. 실제 OFF 동작은 명시적 연결 진단으로 확인한다. 연결 진단은 사용자가 !model의 연결 진단 또는 meca --diagnose를 선택했을 때 ON/OFF·effort를 대조한다. 출력 상한과 전체 실행 예산은 별도다. Ollama에는 options.temperature, 호환 Chat·LM Studio Responses에는 temperature를 전송한다.

## 자동 승인과 실행 예산

최상위 `permission`은 `"default"` 또는 `"all_mighty"`다. 기본 `default`는 일반 작업을 자동 실행하고 승인 대상 작업만 사용자에게 묻는다. `all_mighty`는 외부 전송을 제외한 승인 대상 작업을 사용자에게 묻지 않고 자동 승인한다. !permission에서 ←→로 선택하고 Enter 뒤 y/N/Esc로 저장·취소·계속 편집한다. 저장한 값은 이후 요청과 새 대화·재개·비대화형 실행에 동일하게 적용한다. 실행 중인 요청은 시작 시 선택한 정책을 유지하며 작업 중에는 모드를 변경하지 않는다. 모드별 선택을 세션 DB에 중복 저장하지 않는다. 승인 기록은 직접 사용자 승인과 All Mighty 결정을 구분한다.

외부 전송은 모든 모드에서 직접 승인이 필요하다. 명시적 업로드·원격 실행·전송 인자가 포함된 요청은 All Mighty에서도 매번 직접 승인받고, 비대화형 실행에서는 수행하지 않는다. 목적지 허용 목록을 별도 설정하지 않는다. 일반 다운로드·개발 명령은 호스트 환경을 사용하며 직접 지정한 loopback HTTP 테스트는 전송 승인 예외다. 검사 대상과 보장 범위는 [외부 전송 승인](execution-boundary.md#외부-전송-승인)을 따른다.

config나 메뉴에 Scope 선택은 없다. 셸과 자식 프로그램은 호스트 사용자 권한으로 실행한다. 두 승인 모드 모두 보호 경로 차단·자격 증명 보호·인자·파일 버전 검사와 실제 실행 실패 반환을 유지한다. 전용 파일 도구의 대상·버전 검사와 셸의 OS 권한 범위는 [실행 경계](execution-boundary.md)를 따른다.

```toml
[loop]
max_model_calls = 1024
max_seconds = 14400
max_model_seconds = 600
max_context_bytes = 268435456
max_argument_bytes = 268435456
```

도구 호출 수는 실행 기록에 남기며 별도 횟수 상한을 두지 않는다. 모델은 완료했거나 해결할 다음 행동이 없으면 미완료 결과·구체적인 장애·필요한 사용자 입력을 최종 답변으로 설명하고 종료한다. 모델 요청과 전체 시간 예산은 별도로 유지하며 재시도·압축·LAT도 같은 요청의 예산을 사용한다.

max_model_seconds는 에이전트·압축·LAT 호출에서 데이터가 수신되지 않는 연속 대기 시간이다. 수신할 때마다 다시 세며 응답 전체의 시간 상한이나 셸 명령별 제한이 아니다. max_seconds는 전체 작업 예산이다. 메인·압축 응답은 다음 작업 경계에서 전체 시간 예산을 확인하며, 도구 실행과 선택적인 LAT 검토에는 전체 작업의 마감 시각을 적용한다. 시간·모델 요청 예산 또는 오류로 중단하면 실제 수행 결과와 이유를 기록한다.

## 프롬프트와 Compaction

일반 시작의 Bootstrap은 다음 파일을 누락한 경우에만 생성한다. 디렉터리는 0700, 파일은 0600이다. 실행 중 사용자 수정은 다음 요청에서 다시 읽는다. install·upgrade는 사용자 수정 여부와 관계없이 다섯 파일을 해당 배포의 기본본으로 교체하며, 내용이 이미 같은 파일은 다시 쓰지 않는다.

```text
~/.meca/prompts/
  system.md       에이전트 이름·직접 작업·응답·간결한 의사결정
  development.md  변경 전 검토·책임·배치·개발 원칙
  compaction.md   항목 중심 계속하기 요약
  lat.md          근거·영향·수정 방향 중심의 독립 작업 검토
  lat_compaction.md  원본 지시·실제 결과 중심의 독립 검토 메모
```

메인 에이전트는 system.md·development.md와 선택적인 프로젝트 루트 AGENTS.md를 한 요청의 스냅샷으로 받는다. 프로젝트 지침이 없거나 비어 있으면 빈 블록을 추가하지 않는다. AGENTS.md와 각 프롬프트의 본문 수용 한도는 16MiB다. 지침은 영어로 작성하며 진행 안내·질문·도구 실행 전후 설명·최종 답변과 요약은 최신 사용자 요청의 언어를 따르도록 안내한다. Thinking 언어는 제한하지 않는다. 코드·명령·식별자·인용·프로그램 출력과 사용자·프로젝트 원문은 번역하지 않는다.

기본 프롬프트는 범용 작업·개발 원칙을 담은 영어 Markdown이다. system.md·compaction.md·lat.md·lat_compaction.md의 배포 기본본은 100줄 이하로 유지하고 development.md에는 이 작성 기준을 적용하지 않는다. MECA의 소스 구조·고유 파일 헤더 템플릿·고정 줄 수·특정 언어 API·빌드 명령·하위 호환성 정책은 기본 본문에 넣지 않는다. 사용자 프로젝트의 고유 규칙은 해당 프로젝트 지침으로 전달한다. 파일당 수용 한도는 기본본·사용자 수정본 모두 16MiB이며 줄 수로 실행을 차단하지 않는다.

system.md는 에이전트 이름을 M.E.CA(Minimal Essentials Coding Agent)로 명시하고 연결된 모델·Provider의 이름과 구분하도록 안내한다. 요청 범위·간결한 판단·현재 작업 위치·도구 사용·오류 대응·종료와 보고도 다룬다. development.md는 우선순위 뒤의 `Define complete and serviceable outcomes` 절에서 요청 단계·사용자·핵심 흐름·사용 환경에 맞는 완료 기준을 먼저 정한다. 실제 구현 요청에는 동작에 필요한 보조 기능을 포함하고, 운영 중인 시스템의 변경은 영향을 받는 흐름과 필요한 의존성을 범위로 삼는다. 설계·골격·시제품 요청의 범위는 유지한다.

서비스 준비 기준은 적용 가능한 기능·실패 응답, 인증·권한·입력 경계, 데이터 내구성·일관성·초기화·변경·복구, 기동·상태 확인·종료·의존성 장애, 설정·진단·용량·과부하, 빌드·패키징·배포 또는 업그레이드 절차·사용 문서·검증을 다룬다. 요청한 흐름·정확성·보안·운영에 필요한 기능은 구현 범위로 보고 선택적인 확장은 구분한다. 모든 프로젝트에 인증·서버 인프라 등을 일괄 추가하지 않으며 외부 배포는 별도 사용자 권한 범위를 따른다. 마지막 `Verify serviceability and hand off accurately` 절은 이 완료 기준에 맞춰 실제 경계의 주요 흐름을 확인하고 미완료 기능·외부 전제·미검증 사항을 구분하도록 한다. 골격·개별 계층·빌드 성공만으로 동작하는 서비스의 완료를 주장하지 않는다. 완료 기준은 개발·검증·결과 보고에 적용하는 지침이다.

그다음 변경할 소스·호출자·계약·테스트를 검토한다. YAGNI·KISS·책임 분리와 기본 우선순위는 패턴 선택보다 우선한다. 현재 요구가 실제로 필요로 하는 책임·상태 소유권·수명·일관성·실패 경로·부하의 경계가 있을 때만 관련 패턴을 검토한다. 후보별 복잡도와 실행·메모리 비용을 비교하고 유용한 경계가 생기지 않으면 직접적인 함수·모듈을 선택한다. Strategy 패턴과 교체형 정책 객체 계층은 도입하지 않으며 간단한 분기·직접 함수로 변형을 표현한다. 대상 언어의 native 기능·표준 라이브러리·프로젝트 관례를 우선하고 import는 패키지·모듈 기준 절대 import 또는 프로젝트 alias를 사용한다. 공통 지침은 작업 경계, 책임·설계 선택, 구현 계약, 상태·부작용·자원 소유, 알고리즘·비용, 소스 설명, 검증으로 나누고 패턴별 예시에는 고유한 조건을 남긴다.

개발 작업 공간은 현재 프로젝트 루트와 하위 경로다. 소스·설정·스크립트·테스트·빌드 산출물·검토 결과물과 직접 만드는 임시 파일을 이 안에 두고, 임시 디렉터리·홈·다른 프로젝트·시스템 디렉터리 등 모든 외부 경로를 작업 공간이나 임시 작성 장소로 사용하지 않는다. 외부 작업 파일의 생성·변경·이동·삭제는 사용자가 목적지와 작업을 명시적으로 허용한 경우에 수행한다. 경로 별칭·심볼릭 링크와 출력 위치도 확인한다. 설치된 도구·설정된 의존성은 설치된 위치에서 사용하고 도구 자체가 관리하는 임시 파일·캐시는 해당 도구의 설정을 따른다. 이를 무관한 외부 탐색이나 전역 설정 변경의 허용으로 해석하지 않는다. 실제 실행 권한과 경로 검사는 [실행 경계](execution-boundary.md)를 따른다.

패턴 지침은 적용 조건·언어 중립 예시·실패와 정리 조건으로 구성한다. GoF 생성 5개·구조 7개·행위 11개와 확장 규칙·상태·오류 처리 5개, 구성·콘텐츠·판단·성능 8개, 동시성·상태 소유권 2개, 분산 전달·운영 안정성 8개를 구분해 총 46개를 다룬다. Strategy는 개념을 설명하되 별도 전략 계층 대신 간단한 분기·직접 함수를 사용하도록 안내한다. 추가로 Factory Function, Ports & Adapters, Dependency Injection / Composition Root, Pipeline, Repository / Unit of Work, Memoization / Cache-Aside를 다룬다. 이는 조건부 설계 예시이며 구성 요소나 프레임워크를 모두 도입하라는 지시가 아니다. 패턴 지침은 사용자 프로젝트의 설계 선택에 적용한다.

병렬 처리는 독립된 작업에 제한된 동시 실행 수를 적용하고 충돌하는 변경은 순서를 보존한다. 레이스·재진입·교착·부분 실패·취소·합류·자원 반환을 검토한다. 알고리즘과 자료구조는 입력 규모와 시간·공간 복잡도로 선택하며 측정 근거가 있는 고급 알고리즘·캐시·병렬화·증분 처리로 개선한다. 할당·복사·전체 적재·대기열·캐시의 보존 비용과 장기 수명을 확인한다.

작성·수정하는 소스와 스크립트의 상단에는 사용자 언어로 목적·주요 기능·연동 파일과 역할을 주석으로 기록한다. 필수 실행·컴파일·라이선스 지시문 다음에 배치하고 주석을 지원하지 않는 형식과 생성 파일의 원래 제약을 존중한다. 함수·메서드·클래스 등은 Google 스타일의 요약·인자·반환·예외·부작용·제약·소유권 구조를 해당 언어의 표준 문서 주석 문법으로 작성한다. 주요 흐름·상태 전이·경계 조건·실패 처리·동기화·비직관적 알고리즘과 메모리 결정은 경력 약 2년의 백엔드 개발자가 이해할 수 있게 설명한다. 식별자·API 이름·경로·명령·인용 원문은 유지한다.

해결되지 않은 검토 의견은 관측으로 요약에 보존하고 이후 수정으로 대체된 의견은 다시 과제로 만들지 않는다.

lat.md와 lat_compaction.md는 LAT가 켜진 요청에서만 읽으며 메인·대화 압축 문맥에 넣지 않는다. lat_compaction.md는 기존 LAT 메모와 시간순 원본 사용자 지시·실제 결과를 한 번에 정리하고 요구·변경 상태·실제 확인·실패·미해결 사항을 짧은 항목으로 보존한다. 메인의 요약·답변·Thinking을 근거로 넣지 않으며 메모의 형식·목표 분량을 합격·불합격 조건으로 사용하지 않는다. 검토는 프로젝트 지침·현재 요청 원문·독립 메모·이후 원본 증분·답변 초안을 도구 없는 별도 문맥으로 받는다. 입력이 부족하면 압축하고, 필수 지시를 넣을 수 없으면 원본을 보존하며 검토 불가를 알린다. 검토 의견·실패·최신 독립 메모는 같은 세션 DB에 보관하고 별도 보고 파일은 만들지 않는다. [LAT 사용 범위](usage.md#lat-독립-검토)를 따른다.

compaction.md는 이전 메모와 현재 요청·관측을 한 번에 합치고, 결과와 열린 작업 가지·의존 관계를 구분하여 다음 행동에 필요한 정보에 집중한다. 짧은 항목·현재 상태·결정·실제 확인·장애·다음 행동을 우선하며 도구 호출 원장·원문 코드·추론 과정은 반복하지 않는다. 형식·분량은 지침이며 별도 합격·불합격 검사로 사용하지 않는다. 프롬프트 수정과 관계없이 승인 정책·Scope·버전 검사는 실행기가 소유한다.

추론 인자와 압축 발동·용량 설정은 위 예시처럼 하나의 [compaction] 섹션에 함께 기록한다.

압축 발동 기준은 현재 문맥의 점유량이다. 마지막 메인 모델 요청의 실제 INPUT+OUTPUT에 그 측정 이후 추가된 도구 결과·사용자 입력·관측의 UTF-8 바이트 추정을 더한다. 생성된 assistant 출력은 이미 OUTPUT에 포함되므로 다시 더하지 않는다. 재시도별 마지막 수신량도 별도로 보존한다. Compaction·연결 진단·별도 LAT 검토·LAT 메모 압축 입력은 발동 샘플에서 제외한다. 검토 의견이 메인의 다음 문맥에 들어가면 그 호출의 실제 입력으로 집계한다. 같은 작은 문맥을 여러 번 보내도 비용 누적만으로 압축하지 않는다.

유효 context는 설정과 서버 한도 중 작은 값이다. 기본 reserve_tokens=16384를 남기는 시점에 압축하고 keep_recent_tokens=20000을 최근 원문 선택 목표로 사용한다. 작은 context에서는 두 예산을 최대 context의 1/4로 줄인다. 최근 선택은 토큰당 UTF-8 3바이트의 근사 예산이며 native 호출·결과 묶음을 쪼개지 않는다.

usage가 없으면 해당 요청 메시지·도구 정의와 수신 응답·Thinking·인자의 UTF-8 바이트 합을 3으로 나눠 올림한다. 이 추정은 압축 판단에만 쓰며 UI INPUT/OUTPUT·TPS는 실제 수신값만 사용한다. 응답을 받지 못한 실패에는 점유량을 추가하지 않는다.

압축은 다음 결정의 안전한 경계에서 이전 메모·현재 요청·실제 결과를 하나의 입력으로 요약한다. 기본 출력은 8192토큰이다. 실제 입력 선택 예산은 유효 모델 context에서 요약 출력 여유를 뺀 값의 UTF-8 3바이트/토큰 근사와 max_input_bytes 중 작은 값이다. 여기서 압축 지침·이전 메모·현재 요청과 전송 형식의 여유를 먼저 제외한다. 필수 사용자 지시는 원문을 유지하고 작업 결과·실패를 일반 관측보다 우선한다. 큰 관측은 예산 안에서 앞뒤를 발췌한다. 필수 내용 자체가 들어가지 않으면 원본과 이전 메모를 보존하고 입력·출력 예산 또는 모델 context 조정이 필요함을 반환한다. 최신 요청이 최근 원문에서 빠졌으면 각 모델 문맥의 요약 뒤에 요청 원문을 한 번 넣는다. 저장 이력에 복제하지 않는다. 원본 기록은 DB에 남고 요약할 prefix가 없으면 저장된 메모를 유지한다.

서버의 명시적인 context 오류와 vLLM 사전 토큰화의 입력 초과는 같은 용량 오류 계약을 사용한다. 연속 실패 구간에서는 강제 압축 복구를 한 번 허용하고, 정상 모델 응답 후 새 구간으로 초기화한다. 실측 context 한도가 더 작으면 현재 실행의 압축 예산에도 반영한다. 요약 요청 자체가 실측 토큰 수로 거절되면 선택량을 한 번 줄여 재시도하며 여러 성공 요약을 연쇄 생성하지 않는다. UI 사용량은 실제 수신 usage만 표시한다. 도구를 재실행하지 않는다. 입력·출력 16MiB는 수용 한도이며 문맥 선택 예산과 구분한다.

## 세션 저장과 복원

세션 DB는 ~/.meca/sessions/<project-key>/<session-id>.db다. 정규화된 프로젝트 경로의 basename과 SHA-256 앞 32자리로 프로젝트 폴더를 만들고 해당 디렉터리의 DB 파일명에서 ID를 찾는다. 각 DB는 정확히 한 세션을 소유하며 별도 ID 레지스트리는 없다.

세션 DB의 형식 버전은 **schema 22**이다. 대화·Thinking·도구 결과·실제 명령과 종료 코드·파일 버전·사용량·요약을 시간순으로 저장한다. 큰 본문·원본 출력·도구 인자는 같은 DB의 내용 해시 기반 payload로 분리한다. 새 payload는 Zstandard 압축 결과가 원문보다 작을 때 압축해 저장하고, 그 외에는 원문으로 저장한다. 전체 복원은 저장된 codec에 따라 원문·gzip·Zstandard를 해석하고 길이·SHA-256·JSON 무결성을 검사한다. LAT의 발췌 조회는 같은 원문의 전체 길이·SHA-256을 확인하며 필요한 앞부분만 일반 텍스트로 반환한다. 동일한 본문은 재사용하며 일반 이력·사용량 조회·요약 준비는 필요한 작은 필드를 읽는다. 모델 문맥·원본 내보내기는 payload를 복원한다. 미지원 DB는 자동 변환·삭제·재생성 없이 원본을 보존하고 오류를 반환한다.

체크포인트는 run_states의 실행별 최신 상태 한 건을 원자적으로 갱신하며 큰 구조화 상태도 압축한다. 실행 사건·native 응답은 계속 보존하고 종료 시 작은 상태·통계 이벤트를 남긴다. 원본 내보내기는 종료 이벤트에 해당 실행의 전체 상태를 복원한다. 체크포인트에 도구 인자·출력·누적 명령 사본을 넣지 않으며 파일 관측은 실행 시점과 버전에 연결한다. 셸 실행 뒤 파일 관측은 오래된 상태로 표시한다. LAT 의견은 원본 이벤트 한 건에서 메인 문맥과 압축용 관측을 구성한다. 독립 검토 메모는 lat_memory의 세션별 최신 한 건으로 저장하며, 원본 처리 경계와 무결성을 확인하고 메인 memories 테이블과 분리한다. 화면 이력은 숨은 호출 본문·이미지·체크포인트 중간 상태를 읽지 않고 표시할 필드만 복원한다.

!new는 현재 작업과 DB 자원을 정리한 뒤 새 파일을 만들며 전역 모델 연결을 유지한다. 일반 시작은 현재 프로젝트 대화를, meca resume은 모든 프로젝트 대화를 나열한다. 목록 화면에 진입할 때 DB 파일을 읽기 전용 SQLite 연결 하나로 순서대로 조회해 스냅샷을 한 번 만들고 화면 수명 동안 페이지를 전환한다. 별도 세션 레지스트리나 상시 조회 worker를 만들지 않는다. 새 대화가 맨 위에서 기본 선택된다. 복원은 중단된 native 기록을 짝지어 보존하며 부작용을 자동 재생하지 않는다.

Esc 또는 응답 실패 시 수신한 Thinking은 화면·DB의 실행 이벤트에 보존하고 다음 모델 요청에는 넣지 않는다. 부분 답변에는 미완성 상태를 기록하며 재개 문맥에서는 인용된 초안으로, 압축 입력에서는 미완성 초안으로 구분한다. 사용자 요청·실제 도구 결과·새 사용자 지시는 이어받고 완료된 응답의 reasoning은 Provider 규약에 따라 유지한다.

.db.lock은 열린 핸들에 연결된 프로세스 잠금 파일이다. 파일이 남아 있다는 사실만으로 실행 중인 프로세스가 있다고 판단하지 않는다. !quit·Ctrl+C는 worker·자식 프로세스·클라이언트를 정리한 뒤 잠금과 DB를 닫는다.

## 본문 한도

TOML 파서는 알 수 없는 키·잘못된 타입을 거절하고 각 설정 소유자가 값의 범위를 검사한다. 프롬프트 편집은 일반 실행 중 유지하며 install·upgrade를 실행하면 배포 기본본으로 갱신한다. 모델 연결과 나머지 설정·대화는 프롬프트 갱신으로 변경하지 않는다.

프로젝트 지침·프롬프트·압축 입력·요약은 각각 16MiB다. 모델 응답·실행 문맥·인자는 기본 256MiB, 중첩 JSON 저장 이벤트는 512MiB 수용 한도를 둔다. 이는 미리 할당하는 크기나 모델에 매번 보내는 양이 아니다. 경로·ID·열거값·배열 개수와 화면 발췌 예산은 별도다. 실제 모델 context·출력 한도와 바이트 수용 상한을 혼동하지 않는다.

## 이미지 입력 상태

이미지 지원 여부는 config.toml의 수동 모델 프로파일로 지정하지 않는다. 연결 때 메타데이터 또는 작은 이미지 요청으로 확인하고 세션의 모델 선택에 근거를 보관한다. 재연결은 저장된 판정만 믿지 않고 다시 확인한다. 상태·지원 형식·자원 한도는 [이미지 입력](images.md)을 따른다.
