# 설정과 대화 보존

[← README](../README.md)

`~/.v`의 역할별 추론 설정, 프롬프트, Compaction과 세션 저장을 설명합니다.

## 모델 연결 재사용

`!model`에서 연결 진단과 모델 선택이 성공하면 세션 DB에 선택을 저장하고, 마지막으로 직접 선택한 연결을 `~/.v/config.toml`의 `[model]`에 기록한다. 기록하는 값은 provider, endpoint, name(서빙 모델 ID), credential_ref뿐이다. API Key 본문은 OS 자격 증명 저장소에만 보관한다.

기존 세션의 모델 선택이 최우선이며, 선택이 없는 새 세션은 `[model]`을 사용한다. 복원 시 식별 정보와 기능을 다시 검증하고, 성공하면 해당 세션에도 선택을 저장한다. 이전 세션 복원 시 새 세션용 기본 연결은 유지한다. 기본 연결을 저장하지 못했더라도 이미 저장된 현재 세션 연결은 유지하고 오류를 알린다. Thinking은 기존 세션 설정 또는 전역 기본값을 따르며, 프로파일·강도 기본값은 기존 정확한 모델 매핑을 사용한다.

## 세션 잠금 파일

`~/.v/sessions/<project-key>/<session-id>.db.lock`은 프로세스 간 잠금에 사용하는 고정 파일이다. 파일이 남아 있다는 사실은 잠금이 잡혀 있거나 백그라운드 프로세스가 살아 있다는 뜻이 아니다. 실제 잠금은 열린 파일 핸들에 묶이며 종료 시 해제된다. 다른 프로세스가 기다리는 동안 파일을 삭제·재생성하면 서로 다른 파일을 잠글 수 있으므로 정상 종료에서도 파일은 삭제하지 않는다.

`!quit`·Ctrl+C는 작업을 취소하고 worker와 연결 클라이언트를 정리한 뒤 호출자에게 반환한다. 이어서 세션 잠금 핸들과 DB를 닫는다. 다시 실행할 때 실제 잠금 오류가 발생한다면 잔존 파일이 아닌 다른 프로세스의 점유 여부와 오류 문구를 확인해야 한다.

## 역할별 추론 설정

추론 인자는 Provider가 아니라 호출 역할이 결정한다. 새 `~/.v/config.toml`에는 아래 기본값이 모두 기록된다. 기존 파일의 사용자 값은 덮어쓰지 않으며, 생략한 항목은 현재 기본값을 사용한다. 설정을 저장할 때는 적용된 역할별 값도 기록한다. TOML 직접 수정은 앱을 다시 시작하면 적용된다.

| 역할 키 | 용도 | temperature | max_output_tokens |
| --- | --- | ---: | ---: |
| `agent` | 메인 에이전트의 행동 선택·직접 응답 | 0.7 | 25600 |
| `plan` | 승인받을 Plan 초안·수정 | 0.7 | 12800 |
| `conclave` | 후보 판정과 참조가 있는 거절 사유 | 0.4 | 12800 |
| `compaction` | 대화 압축·근거 보존 | 0.2 | 12800 |
| `diagnostic` | 연결·Thinking·effort 진단 | 0.2 | 12800 |

예를 들어 다음 항목을 변경한다. 이 값은 Provider·서빙 별칭·모델 프로파일과 독립적으로 역할별 설정을 따른다.

```toml
[inference.agent]
temperature = 0.7
max_output_tokens = 25600

[inference.conclave]
thinking = "off_if_supported"
temperature = 0.4
max_output_tokens = 12800

[inference.compaction]
thinking = "off_if_supported"
temperature = 0.2
max_output_tokens = 12800
```

`temperature`는 유한한 0~2, `max_output_tokens`는 1~65536이다. 명시한 `temperature = 0`은 생략과 구분하여 전송한다. 메인 Thinking/effort는 사용자 선택을 계승한다. Conclave·Compaction의 thinking 기본값은 `off_if_supported`이며 OFF가 검증된 조합에서만 끈다. `inherit`는 사용자 선택을 유지한다. 진단은 기능 확인을 위해 ON/OFF를 명시적으로 대조한다. 출력 토큰 한도는 모델의 reasoning 사용분도 고려해야 하며, 서빙 한도·전체 실행 예산과 별도로 적용된다. 일반 응답은 기존 16KiB 제한 대신 모델 응답 공통 한도인 4MiB 안에서 수신하며, 내부 구조화 결과·도구 인자의 검증 한도는 유지한다. Provider는 확인된 출력·컨텍스트 용량 안에서 요청 한도를 제한할 수 있다.

`top_p`, `top_k`, `min_p`, penalty, seed는 서버 기본값을 사용한다. 재시도에서도 선택된 역할 인자를 그대로 사용한다. 서버가 인자를 거절하면 요청 인자를 유지한 채 제한된 재시도를 수행하고, 실패 원인을 오류로 반환한다. 서버 내부 적용 여부는 요청 수락과 별도의 검증 대상이다.

Conclave는 pass/reject/needs_context JSON을 반환한다. 거절에는 후보 경로·줄 또는 요청 참조와 구체적인 사유가 필요하다. 정상 심사는 1회이며 형식 교정·문맥 보강은 합쳐 1회 추가할 수 있다. 사용자 요청·프로젝트 지침·경로·코드의 원문은 보존한다. Plan은 native submit_plan을 통해 사용자 승인 대상으로 제출한다.

역할 선택은 `agent/inference`, API 형식 변환은 `provider/protocol`이 담당한다. Ollama에는 `options.temperature`, 호환 Chat/LM Studio Responses에는 `temperature`를 전송한다. API 계약 근거: [Ollama Chat](https://docs.ollama.com/api/chat), [LM Studio Responses](https://lmstudio.ai/docs/developer/openai-compat/responses).

## 프롬프트 파일과 Compaction

Bootstrap은 다음 Markdown 프롬프트를 누락된 경우에만 생성한다. 디렉터리는 `0700`, 파일은 `0600`이며 기존 수정본은 보존한다. 다음 사용자 작업에서 다시 읽는다.

```text
~/.v/prompts/
  system.md       기본 시스템 프롬프트 + 프로젝트 AGENTS.md 결합
  compaction.md   항목 중심 대화 요약 프롬프트
  conclave.md     영어 심사·거절 사유 지침
```

원본은 저장소의 `internal/agent/prompt/defaults/`에 포함한다. 내부 역할에는 각 전용 프롬프트와 프로젝트 제약을 결합하고, 메인 에이전트의 도구 선택·출력 프로토콜은 메인 호출에 한정한다. 내부 응답 형식·언어 지침은 프로젝트의 응답 표현 선호보다 우선하지만 Scope·승인 제약을 대체하지 않는다. `system.md`를 수정해도 Scope·Permission·승인 검사는 코드에서 계속 적용한다.

기본 프롬프트는 이 저장소 AGENTS.md의 언어 공통 원칙을 담는다. 수정 대상·호출자·계약·테스트를 먼저 검토하고, 배치와 디자인 패턴을 판단한 뒤 구현·검증·단순화한다. 대상 언어의 native 문법·기본 기능·표준 라이브러리·관용적 방식을 우선하는 언어 공통 지침으로 구성한다. 저장소 전용 Go 구조와 명령은 프로젝트 지침에서 다룬다. 업데이트 시에도 기존 `~/.v/prompts/system.md`를 보존한다.

기본 발동 조건은 마지막 성공한 압축 이후 **200,000 누적 토큰**이다. `~/.v/config.toml`에서 변경할 수 있다.

```toml
[compaction]
threshold_tokens = 200000
keep_recent_bytes = 16384
max_summary_bytes = 16384
max_input_bytes = 65536
```

단일 요청 INPUT에 따른 조기 압축 조건은 제거했다. 다만 명시적인 context_length_exceeded 계열 오류에는 안전한 경계에서 압축하고 모델 요청만 한 번 재시도한다. 요약할 prefix가 없거나 고정 지침이 한도를 넘으면 원인을 반환한다.

누적량은 일반 에이전트·Plan·Conclave의 각 요청 시도에서 마지막으로 수신한 실제 INPUT+OUTPUT 합이다. 중간 usage는 교체하고, 재시도·중단 시 마지막 값을 한 번 확정한다. 같은 문맥을 다시 전송한 입력도 해당 호출의 사용량이므로 포함한다. 압축 자체의 호출과 연결 진단은 발동 누적량에서 제외한다. 사용량을 전혀 받지 않은 호출은 메시지·도구 정의를 포함한 요청과 수신 응답·Thinking·도구 인자의 UTF-8 바이트 합을 3바이트당 1토큰으로 환산하여 올림한다. 200,000 기준은 약 600,000바이트(586KiB)이며 토크나이저 실측이 아닌 혼합 언어용 근삿값이다. 응답을 전혀 받지 못한 실패에는 추정 사용량을 더하지 않는다. UI는 이 추정을 사용하지 않고 실제 usage만 표시한다.

압축 임계값은 다음 결정 문맥을 구성하는 안전한 경계에서 확인한다. native 호출 수신·self-grounding·승인 대기·도구 실행 중에는 현재 문맥을 유지한다. 마지막 응답이 임계값을 넘기면 다음 문맥이 필요한 시점에 실행한다. `keep_recent_bytes`는 최근 원문 메시지의 보존 예산이며 토큰 추정값이 아니다. 메시지를 쪼개지 않으므로 마지막 메시지 하나만으로 예산을 넘을 수 있다. 기본 16KiB에 해당하는 최근 메시지를 남기고 오래된 prefix만 요약한다. 0이면 최근 구간 보존을 끈다. 요약할 오래된 구간이 없으면 기존 메모리를 유지한다. 소스 조각을 입력 예산 내에서 묶어 순서대로 병합하며 압축 호출도 Ralph의 모델 호출·시간 예산에 포함한다.

요약에는 다음 고정 섹션을 쓰며 본문은 글머리 항목으로 제한한다. 기본 템플릿은 한 줄에 한 사실을 `상태 | 내용 | 근거`처럼 섹션별 필드 순서로 작성한다. 일반 섹션은 1–3개 항목을 목표로 하되 변경 파일과 미완료 가지는 필요한 만큼 보존한다. 같은 사실은 한 섹션에만 기록하고 다른 섹션에서는 노드·원본 ID로 참조한다. 완료 이력과 반복 관측은 합치고, 실패 원인·제약·검증 불확실성은 남긴다. 이는 프롬프트 지침이며 필드의 의미나 항목 수를 강제하거나 정보를 잘라내는 규칙은 아니다. 값은 사용자 언어로, 경로·명령·오류·ID는 원문으로 보존한다.

요약 프롬프트는 대화를 **frontier tree**로 분석한다. 원래 목표를 루트로, 하위 작업·Plan revision·스텝을 가지로 두고 실행·변경 파일·검증 근거를 해당 노드에 연결한다. 각 가지의 가장 깊은 미완료 노드와 부모 자체의 남은 요구를 frontier로 보존한다. 차단·중단·불명·미승인 노드도 포함하며, 의존 관계는 노드 참조로 표현한다. 완료한 가지는 근거와 변경 내역을 남겨 짧게 정리하고 회귀가 발견되면 다시 연다. 매 소스 조각을 병합할 때 다른 가지의 frontier를 유지하며, 관계가 불명확한 사실은 추측하지 않고 미배정 항목으로 남긴다. 아래 섹션 안의 중첩 항목과 동일한 노드 참조로 트리·현재 진행 지점을 이어간다. 이는 모델 분석 지침이며 트리 관계의 의미적 정확성을 런타임에서 강제하는 기능은 아니다.

- Requests: 원래 목표, 달성·부분 달성·미완료·불명 상태와 근거
- Run history: 수행 내역, 결과, 관측과 원본 참조
- Steps and changed files: Plan revision·스텝, 실제 변경 파일과 이동 대상, 미실행 의도 구분
- Verification: 검사 명령, 성공·실패·중단·미실행, 남은 불확실성
- Decisions and constraints: 사용자 결정·요구사항·거절한 접근·제약
- Pending work and blockers: 미완료 작업, 차단 원인, 필요한 정보
- Continuation: 현재 목표, 다음 작업, 미승인 계획과 중단 상태

모델 요약과 별도로 실제 run status, Plan·스텝, 변경 파일·작업, 검증 여부와 원본 ID를 구조화된 ledger로 보존한다. 이 ledger와 요약은 다음 모델 문맥의 `ConversationMemory`에 제공한다. 현재 목표·AGENTS.md·Scope·Permission·승인 상태와 인자 초안은 요약과 별도로 유지한다. 요약의 완료 주장은 런타임 완료 판정이 아니다.

압축 후에도 원본 메시지·도구 기록·파일 내용을 보존한다. 성공 시에만 새 revision과 압축한 원본·사용량 범위를 원자적으로 확정한다. 취소, 잘못된 형식, 과대 요약, 호출 한도 또는 충돌이면 이전 요약과 원본을 유지한다. 원본 코드와 긴 출력은 기록에서 참조하고, 정보나 정확한 파일 목록을 버려야 한도에 들어가는 경우에는 조용히 생략하지 않고 오류로 중단한다. 모델 요약의 의미적 충실도는 실제 모델 평가가 추가로 필요하다.

## 세션 저장

SQLite는 `~/.v/sessions/<프로젝트 키>/<세션 ID>.db`에 **세션당 한 파일**로 저장한다. 메시지·도구 이벤트·실행 상태·Conclave·Plan·Compaction·사용량·모델 선택·정책 설정은 모두 해당 DB에 들어간다. 프로젝트 키는 정규화된 실제 프로젝트 경로의 SHA-256 앞 32자리와 읽을 수 있는 폴더명으로 만든다. 같은 이름의 다른 경로는 분리하고 심볼릭 링크 별칭은 같은 폴더를 사용한다. 세션 ID와 목록은 프로젝트 폴더 안의 `session_*.db` 파일명에서 찾으며 별도 SQLite 인덱스나 중앙 DB를 만들지 않는다. 목록의 제목·프로젝트·갱신 시각은 각 DB에서 읽기 전용으로 조회하고 즉시 닫는다. `v resume`는 모든 프로젝트 폴더의 대화를 합쳐 표시한다. 일반 시작 목록은 현재 프로젝트 폴더만 조회하며 다른 프로젝트의 DB를 열지 않는다. 파일 내부 프로젝트 경로가 저장 폴더와 맞지 않으면 거부한다. 기존 평면 `sessions/session_*.db`는 자동 이동·삭제하지 않으며 전체 목록 조회 시 미지원 배치 오류를 표시한다.

세션 디렉터리는 `0700`, DB는 `0600`이다. 새 DB는 임시 파일에 스키마와 단일 세션 메타데이터를 완성하고 닫은 뒤 원자적으로 공개한다. 실행 중에는 같은 세션의 `.db-wal`·`.db-shm`, 소유권 잠금용 `.db.lock`이 생길 수 있으며 목록에서 제외한다. 파일 하나를 옮길 때는 해당 세션을 종료해 WAL 내용이 DB에 반영된 뒤 옮긴다. 파일명과 내부 ID 불일치·심볼릭 링크·손상 DB는 명시적 오류로 처리한다.

`Current session` 정책 변경은 현재 세션에만 저장한다. 같은 프로젝트라도 새 세션은 전역 기본값을 사용하고, 기존 세션을 이어갈 때는 그 세션의 재정의가 복구된다. 전역 기본값은 계속 `config.toml`이 소유한다.

현재 형식만 지원한다. 세션 DB의 현재 스키마는 version 6다. 이전 버전·미버전 DB는 원본을 보존하고 미지원 오류를 반환한다. 기존 통합 `~/.v/v.db`는 그대로 보존하지만 새 목록에는 포함하거나 자동 분리하지 않는다.

## 이전 설정 정리

현재 DB 스키마는 version 6이며 기존 DB 파일은 보존하고 미지원 오류를 반환한다. 자동 변환은 제공하지 않는다.

이전 config.toml의 `inference.goal`, `inference.grounding`, `inference.report`, `inference.pfc_value`, `inference.pfc_content` 섹션은 수동으로 제거한다. 모델 연결·credential_ref와 나머지 사용자 설정은 유지한다. 역할 기본값은 Agent 25600, 나머지 12800이며 명시한 사용자 값은 유지한다.

기존 프롬프트도 자동 덮어쓰지 않는다. 저장소의 `internal/agent/prompt/defaults/`와 비교해 system.md·conclave.md·compaction.md를 현재 계약으로 갱신한다. 과거 goal.md·grounding.md·pfc.md는 읽거나 새로 생성하지 않는다. 이전 프롬프트의 Goal 분해·PFC·3행 grounding·0/1 투표·DONE/WAIT/CONTINUE 지시는 현재 규약에서 제거했다.

reason은 256문자·1024바이트 이내의 한 줄이며 Conclave JSON은 8KiB 이내다. 프롬프트의 의미적 정확성은 모델 평가 대상이고 Scope·승인·snapshot은 코드가 강제한다.

### 제거된 설정

`compaction.target_input_tokens`, `session.restore_last`, `ui.theme`은 제거했다. 기존 config.toml에서는 이 항목과 빈 `[session]`을 직접 제거한다. 미지원 키를 자동 변환하거나 무시하지 않는다. 새 설정의 압축 누적량은 `request` 종류의 호출별 기록만 집계하며 이전 방식의 user/model/tool 카운터는 재해석·변환하지 않는다. 기존 대화·요약·화면 usage 기록은 보존하고 새 호출부터 새로운 발동 누적량을 쌓는다. 실제 사용 중인 모델 연결·정책·역할별 추론·실행 예산·입력 크기 설정은 유지한다.

### 전역 context length

```toml
# 최상위 키: 모든 모델과 추론 역할에 적용. [model] 등 테이블 밖에 둔다.
context_length = 262144
```

기본값은 262,144 토큰이며 허용 범위는 1,024–1,073,741,824이다. 서버가 더 작은 현재 context 한도를 보고하면 두 값의 최솟값을 적용하고, 미제공이면 설정값을 기본 예산으로 사용한다. 연결 진단·일반 생성·심사·압축에 같은 클라이언트 설정을 적용한다. `!model`의 모델 정보에서 서버 선언과 설정·적용 예산을 구분하여 표시한다. 변경은 앱 재시작 후 연결에 적용된다.

이 값은 서버 모델 로딩 설정을 변경하지 않는다. Ollama에는 적용 예산을 `num_ctx`로 전송한다. 서버 context가 확인된 vLLM에서는 `/tokenize`의 실제 입력 수와 설정·서버 한도 중 최솟값으로 출력 여유를 계산한다. 그 외 API에는 임의의 context 필드를 전송하지 않고 출력 예산 제한에 사용하며 서버의 최종 입력 한도 검증을 따른다. 공통 API에 정확한 입력 토큰 사전 계산 기능이 없으므로 모든 Provider에서 입력+출력 합계를 사전에 강제한다는 의미는 아니다. 압축의 누적 200,000 기준과 모델의 한 번 요청 context 예산은 서로 별개다.
