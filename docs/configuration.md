# 설정과 대화 보존

[← README](../README.md) · [모델 연결](model-connections.md) · [서버 API](server.md)

아래 경로는 `~/.meca` 기준이다. tui와 full은 설정·대화·스킬·모델 인증정보를 공유한다. full의 서버 파일은 해당 기능을 사용할 때 준비한다. [배포 종류 변경](cli.md#업데이트)

| 저장 위치 | 현재 책임 |
| --- | --- |
| `config.toml` | 언어·승인 모드·모델 기본값·역할별 추론·실행/압축 예산 |
| `prompts/single/`, `prompts/team/` | 실행 프로필별 지침 |
| `sessions/` | 프로젝트별 사용자 대화와 팀 개인 DB |
| `credentials.db` | 암호화한 모델 API Key |
| `credential-keys/keys.db` | API Key 버전별 암호화 키 레코드. 디렉터리 0700·DB 0600 |
| `server.token` | 기본 서버 인증 토큰. 사용자 지정 경로는 `--token-file` |
| `server-requests/<project-scope>/requests.db` | 프로젝트별 native 작업 접수 digest·세션·종료 상태 |
| `logs/` | 로컬 진단 로그 |
| `skills/<name>/SKILL.md` | 개인 스킬. 프로젝트·공유 경로와의 우선순위는 [스킬 문서](skills.md) |

언어·승인 모드·기본 모델을 저장할 때는 최신 설정에서 선택한 항목만 바꾼다. 서버의 listen·protocol·TLS·Host·Origin은 시작 옵션으로 전달한다. [서버 설정과 한도](server.md)

로그 레벨은 `MECA_LOG_LEVEL`로 지정한다. 스킬 파일의 배포와 초기화는 기본 스킬 문서에서 확인한다. [이벤트와 운영 로그](diagnostics.md) · [기본 스킬 배포](builtin-skills.md#배포와-초기화)

## 화면 언어

최상위 `language`의 기본값은 `"auto"`다. `"ko"`·`"en"`은 시스템 로캘보다 우선하는 한국어·영어 설정이며 다른 값은 거절한다. !language에서 ←→로 선택한 뒤 Enter의 저장 확인에서 y를 누르면 전역 파일에 저장하고 현재 TUI에 즉시 적용한다. 저장 전에는 적용 중인 설정을 유지한다. 직접 파일을 수정하면 재시작 후 적용한다. 새 대화·이전 대화 선택 화면에도 이 값을 사용하며 모델 응답 언어는 사용자 요청을 따른다. 자동 선택 기준과 메뉴 조작은 [사용 가이드](usage.md#화면-언어)를 따른다.

## 모델 연결 재사용

!model의 저장 확인에서 y를 누르면 현재 대화의 선택을 저장한다. 저장 범위가 모든 대화의 기본값이면 config.toml의 [model]에도 provider·endpoint·name(서빙 ID)·credential_ref와 선택적 thinking·reasoning_effort를 기록한다. 추론 강도는 모델 연결에 묶인 선택이며 새 대화 연결 시 서버 메타데이터로 재검증한다. API Key 본문은 별도의 credentials.db에서만 암호화해 보관하고 config.toml·대화 DB에는 포함하지 않는다.

WebUI의 설정 → 모델은 대화를 열기 전에도 전역 `[model]`을 조회하고 저장한다. 저장된 세션의 선택이 우선이며 서버는 개별 모델을 지정하지 않은 대화의 다음 요청에 현재 전역 기본값을 적용한다. 복원 시 모델 식별·기능을 다시 확인한다. 모델 저장은 TUI 입력 루프 밖에서 수행한다. 취소했더라도 DB에서 저장 완료를 확인하면 해당 연결을 적용한다. 저장 오류는 실제 DB 값을 다시 읽어 판정하며, 확인할 수 없으면 현재 연결을 해제하고 재연결을 요구한다. 확실히 거부된 저장은 기존 연결을 유지한다. 전역 기본 연결 저장에 실패해도 이미 저장된 현재 세션 연결은 유지하고 오류를 알린다. Thinking은 세션 선택 또는 전역 기본값을 따르며 생략하면 서버 설정을 사용한다. 원본 식별은 서버가 제공한 정보를 표시한다. [모델 연결](model-connections.md)을 참고한다.

### API Key 암호화와 복구

저장한 API Key는 `credentials.db`에 AES-256-GCM으로 암호화한다. 버전별 암호화 키는 `credential-keys/keys.db`에 모아서 보관한다. 키 저장소는 4096바이트 페이지를 사용하며 최대 16MiB다. `meca install`은 키 디렉터리를 준비하고 실제 키 저장 어댑터로 원자적 생성·저장·조회 및 권한을 검증한다. macOS·Linux·WSL·SSH·컨테이너에서 같은 로컬 저장 방식을 사용한다.

`~/.meca`와 키 디렉터리는 0700, 키 DB는 0600 권한으로 소유자의 접근을 허용한다. 키 DB에는 복호화에 필요한 키 원문이 들어 있으므로 상태 디렉터리 전체에 접근할 수 있는 사용자나 프로세스는 API Key를 복호화할 수 있다. API Key 본문은 설정·대화 DB·키 DB에 평문으로 기록하지 않는다.

백업은 MECA를 종료한 뒤 `credentials.db`와 `credential-keys/keys.db`를 함께 보존한다. 정상 종료 후 `~/.meca` 전체를 복사해 다른 장치에서도 복원할 수 있다. 복원 시 디렉터리 0700·두 DB의 0600 권한 및 실행 계정의 소유권을 적용한다. 암호화 키의 교체 후에도 이전 키 레코드를 보관해 과거 DB 백업의 복호화를 지원한다. 필요한 키 레코드와 백업을 모두 잃으면 API Key를 다시 입력해야 한다.

권한·소유권 오류는 해당 디렉터리나 DB의 권한을 확인하도록 안내한다. 키 누락은 백업 복구를, 저장 실패는 디스크 공간·권한·파일시스템 지원 확인을 안내하며 원인 오류를 유지한다. 키 DB 쓰기 도중 프로세스가 종료되면 다음 접근에서 SQLite 저널 복구를 수행한다.

`meca uninstall`은 `~/.meca`의 모든 데이터와 저장된 API Key 및 암호화 키를 제거한다. 일반 디렉터리는 함께 삭제하고, `~/.meca` 자체가 볼륨 마운트 지점이면 내부가 비었음을 확인한 뒤 빈 디렉터리를 남기고 완료한다. 내부 파일 삭제 실패나 남은 하위 마운트는 성공으로 처리하지 않는다. 읽기 전용·권한 오류는 표시된 경로의 쓰기 권한과 소유권을 복구한 뒤 `meca uninstall`을 다시 실행한다. 제거가 중단되면 다시 실행해 완료하며, 제거 중에는 일반 시작과 설치를 차단한다.

## 메인 에이전트와 보조 역할의 추론 설정

메인 에이전트는 최상위 **[agent]**, 요약·연결 진단은 [compaction]·[diagnostics]에서 설정한다. 역할별 공통 설정을 Provider 어댑터가 각 API 형식으로 변환한다. Bootstrap은 기본값을 기록하며 생략한 필드는 현재 기본값을 사용한다. 명시한 값은 자동 덮어쓰지 않으며 직접 수정은 재시작 후 적용한다.

```toml
language = "auto"
permission = "default"
context_length = 262144
# thinking = true 또는 false를 지정하면 전역 기본값을 덮어쓴다. 생략 시 서버 기본값.

[agent]
thinking = "inherit"
temperature = 1.0
max_output_tokens = 0

[compaction]
thinking = "off_if_supported"
temperature = 0.2
max_output_tokens = 0
keep_recent_tokens = 20000
max_summary_bytes = 16777216
max_input_bytes = 16777216

[diagnostics]
thinking = "inherit"
temperature = 0.2
max_output_tokens = 12800
```

| 역할 | 용도 | temperature | 기본 출력 상한 |
| --- | --- | ---: | ---: |
| agent | 직접 도구 실행·대화·최종 응답 | 1.0 | 유효 컨텍스트 창의 75% |
| compaction | 단일 호출 대화 요약 | 0.2 | 유효 컨텍스트 창의 7% |
| diagnostics | 모델 연결·Thinking·effort 진단 | 0.2 | 12800 |

temperature는 유한한 0~2이며 지원되는 Provider에는 명시한 0도 전송한다. OpenAI·Claude는 모델마다 sampling 지원이 달라 이 값을 전송하지 않고 공급자 기본값을 사용한다. Gemini는 generationConfig.temperature를 사용한다. `max_output_tokens`는 0~1073741824다. 양수는 수동 상한이다. `0`이면 유효 컨텍스트 창에서 `compaction`은 7%, `agent`와 `diagnostics`는 75%를 내림한 값을 사용한다. Provider의 출력 상한과 남은 컨텍스트 공간도 적용한다. 모델 출력 한도 초과를 명시적으로 보고한다.

Provider가 생성 전 HTTP 400·422에서 요청과 일치하는 토큰 예산 거절을 보고하거나 컨텍스트 초과 코드를 반환하면, 에이전트는 해당 결정을 중단하고 압축 가능한 이전 이력을 요약한다. 확인된 출력 예약량은 해당 거절에서 복구할 때 최근 원문 보존량을 줄이는 데 사용한다. 요약과 최근 대화로 문맥을 다시 만든 뒤 원래 출력 설정으로 작업을 이어간다. 연속된 용량 거절에는 한 번만 복구하며, 압축 가능한 이력이 없으면 이유를 표시한다.

메인 에이전트는 사용자의 Thinking/effort를 계승한다. Compaction은 서버 메타데이터 또는 Provider API에 OFF 요청 규약이 있는 연결에서 Thinking을 끄며, 제어 규약이 없으면 사용자 선택을 유지한다. 실제 OFF 동작은 명시적 연결 진단으로 확인한다. 연결 진단은 사용자가 !model의 연결 진단 또는 meca --diagnose를 선택했을 때 ON/OFF·effort를 대조한다. 출력 상한과 전체 실행 예산은 별도다. Ollama에는 options.temperature, 호환 Chat·LM Studio Responses에는 temperature를 전송한다.

## 자동 승인과 실행 예산

최상위 `permission`은 `"default"` 또는 `"all_mighty"`다. 기본 `default`는 승인 대상 도구 호출을 사용자에게 묻는다. `all_mighty`는 외부 전송을 포함한 승인 대상을 모두 자동 승인한다. `!permission`에서 ←→로 선택하고 Enter 뒤 y/N/Esc로 저장·취소·계속 편집한다. 저장한 값은 이후 요청·새 대화·재개·비대화형 실행에 적용한다. 실행 중에는 시작 시 선택한 모드를 사용한다. 승인 기록에 사용자 승인과 자동 승인 출처를 남긴다.

명시적 업로드·원격 실행·전송 인자를 검사하며 일반 다운로드와 직접 지정한 loopback HTTP 테스트에는 기본 허용 정책을 적용한다. [외부 전송 승인](execution-boundary.md#외부-전송-승인)

config나 메뉴에 Scope 선택은 없다. 셸과 자식 프로그램은 호스트 사용자 권한으로 실행한다. 두 승인 모드 모두 보호 경로 차단·자격 증명 보호·인자·파일 버전 검사와 실제 실행 실패 반환을 유지한다. 전용 파일 도구의 대상·버전 검사와 셸의 OS 권한 범위는 [실행 경계](execution-boundary.md)를 따른다.

```toml
[loop]
max_model_calls = 1024
max_seconds = 14400
max_model_seconds = 600
max_context_bytes = 268435456
max_argument_bytes = 268435456
```

도구 호출 수는 실행 기록에 남기며 별도 횟수 상한을 두지 않는다. 모델은 완료했거나 해결할 다음 행동이 없으면 미완료 결과·구체적인 장애·필요한 사용자 입력을 최종 답변으로 설명하고 종료한다. 모델 요청과 전체 시간 예산은 별도로 유지하며 재시도·압축도 같은 요청의 예산을 사용한다. 팀 모드에서는 모든 참여자가 같은 모델 요청 수·마감 시각을 공유한다.

max_model_seconds는 에이전트·압축 호출에서 데이터가 수신되지 않는 연속 대기 시간이다. 수신할 때마다 다시 세며 응답 전체의 시간 상한이나 셸 명령별 제한이 아니다. max_seconds는 전체 작업 예산이다. 메인·압축 응답은 다음 작업 경계에서 전체 시간 예산을 확인하며, 도구 실행에는 전체 작업의 마감 시각을 적용한다. 시간·모델 요청 예산 또는 오류로 중단하면 실제 수행 결과와 이유를 기록한다.

## 프롬프트와 Compaction

일반 시작은 누락된 기본 프롬프트만 생성한다. 각 실행 프로필의 지침은 다음 파일에서 편집할 수 있다.

```text
~/.meca/prompts/
  single/
    system.md
    compaction.md
  team/
    system.md
    compaction.md
```

`system.md`는 대화에서 사용자의 의도와 범위를 이해하고 필요한 응답·행동·완료 기준을 결정하도록 안내한다. `compaction.md`는 그 의도와 합의, 실제 결과, 답변을 기다리는 결정을 보존한다. 각 프로필은 독립된 파일을 사용한다. `codemode`와 `tools.*`의 호출·반환·자동 전달 계약은 카탈로그에서 생성한 Code Mode 명세가 소유하며 사용자 프롬프트 파일에 별도 도구 목록을 등록하지 않는다. 프로젝트별 지침은 프로젝트 루트의 `AGENTS.md`에 둔다. [코드와 도구 계약](codemode.md#코드와-도구-계약)

개발 방향·설계·구현 지침은 `~/.meca/skills/development/SKILL.md`와 그 참고 자료에서 편집한다. 싱글·팀이 같은 개발 스킬을 사용하며, 팀의 협업 규칙은 팀 시스템 프롬프트에 둔다. [통합 개발 가이드](builtin-skills.md#개발-방향과-참고-자료)

실행 중 수정한 프롬프트는 다음 요청에서 다시 읽는다. **install·upgrade는 배포 기본 프롬프트와 기본 스킬의 배포 파일을 사용자 수정 여부와 관계없이 갱신**한다. 유지할 개인 지침은 프로젝트 `AGENTS.md`나 별도 스킬에 둔다. 일반 시작은 기존 내용을 유지하고 누락된 배포 파일만 생성한다. [기본 스킬 설치](builtin-skills.md#배포와-초기화)

다음 모델 호출을 준비할 때 현재 입력이 유효 컨텍스트 창의 75%에 도달하면 압축 가능한 이전 이력을 요약한다. 이후 호출과 새 사용자 요청은 저장한 요약과 경계 이후의 원문으로 시작한다. 이미 생성 중인 Thinking·답변의 출력 토큰은 그 호출에 배정된 출력 예산을 사용한다. 262,144토큰 창의 발동선은 196,608토큰이다. `keep_recent_tokens`는 최근 원문 보존량, `max_input_bytes`·`max_summary_bytes`는 압축 입력·요약의 바이트 예산이다.

자동 압축은 다음 모델 요청을 보내기 전에 판단한다. vLLM에서 현재 텍스트 요청의 토큰 수를 확인할 수 있으면 그 수치와 서버의 유효 컨텍스트 창을 사용한다. 현재 토큰 수를 확인할 수 없으면 마지막 요청의 사용량 또는 추정값에 이후에 추가된 문맥의 추정치를 더한다. 압축을 결정하면 요약을 저장하고 새 문맥으로 요청을 다시 준비한다.

`!compact`는 현재 대화가 유휴 상태일 때 수동으로 실행한다. 자동 압축의 발동 기준과 최근 원문 보존 예산을 적용하지 않고, 요약 가능한 이력을 현재 모델로 압축한다. 다음 요청부터 저장한 요약을 사용한다. 아직 모델이 읽지 않은 이미지·브라우저 관찰과 연결된 도구 호출은 원문 문맥에 보전한다. 팀 모드에서는 선택한 대화의 문맥을 압축하며 팀원은 각자의 문맥을 관리한다. 압축할 새 이력이 없으면 모델을 호출하기 전에 알린다.

압축은 최신 요청·실제 결과·도구 호출과 응답의 관계를 보존하며 원본 대화 DB를 삭제하지 않는다. 필수 내용이 예산에 들어가지 않거나 압축이 실패하면 원본을 유지하고 오류를 반환한다. 문맥 판단용 추정값과 화면에 표시하는 실제 토큰 사용량은 구분한다.

활성 세션의 브라우저 관찰과 웹 문서는 압축 뒤 최신 커서에서 이어 읽는다. [관찰 결과와 이어 읽기](tools.md#관찰-결과와-이어-읽기)

## 세션 저장과 복원

사용자 대화는 `~/.meca/sessions/<project-key>/<session-id>.db`에 저장한다. 팀 개인 기록은 해당 프로젝트의 `.team/<사용자 세션 ID>/` 아래에 보관하므로 백업에 이 하위 폴더도 포함한다.

대화·Thinking·도구 결과·사용량과 재개에 필요한 상태를 저장한다. 큰 원문은 압축·참조할 수 있으며 화면용 이력과 전체 원문 내보내기는 읽는 범위가 다르다. 파일을 직접 수정하거나 일부 DB만 분리해서 옮기지 않는다.

안전한 백업은 MECA를 종료한 뒤 관련 세션 폴더 전체를 복사하는 방식이다. 자격 증명은 [별도의 백업 조건](#api-key-암호화와-복구)을 따른다. 대화 삭제는 해당 대화와 소유한 팀 기록을 제거하며 프로젝트 작업 파일은 삭제하지 않는다.

중단된 요청은 저장 상태와 실제 부분 효과를 확인해 재개한다. 부작용을 자동 재실행하거나 저장 불확실 상태를 정상 완료로 바꾸지 않는다. 지원하지 않는 저장 형식은 원본을 보존하고 열기를 거절하며 자동 변환·삭제·초기화를 하지 않는다.

## 본문 한도

TOML 설정은 정의된 키·타입·범위에 맞아야 한다.

프로젝트 지침·프롬프트·압축 입력·요약은 각각 16MiB다. 모델 응답·실행 문맥·인자는 기본 256MiB, 중첩 JSON 저장 이벤트는 512MiB 수용 한도를 둔다. 이는 미리 할당하는 크기나 모델에 매번 보내는 양이 아니다. 경로·ID·열거값·배열 개수와 화면 발췌 예산은 별도다. 실제 모델 context·출력 한도와 바이트 수용 상한을 혼동하지 않는다.

모델 응답은 답변·Thinking·native 상태·완료 호출을 합산하고 추가 전에 검사한다. OpenAI·Claude·Gemini 프레임과 continuation에도 256MiB를 적용한다. 이미지 Base64만으로 요청 상한을 넘으면 변환 전에 거부한다. 서버의 native 제어 17MiB·입력 텍스트 16MiB와 이미지당 64MiB·64M픽셀은 이 모델/저장 상한과 별개다. [서버 계약](server.md#이벤트재접속수명)과 [이미지 입력](images.md)을 따른다.

## 이미지 입력 상태

이미지 지원 여부는 config.toml의 수동 모델 프로파일로 지정하지 않는다. 연결 때 메타데이터 또는 작은 이미지 요청으로 확인하고 세션의 모델 선택에 근거를 보관한다. 재연결은 저장된 판정만 믿지 않고 다시 확인한다. 상태·지원 형식·자원 한도는 [이미지 입력](images.md)을 따른다.
