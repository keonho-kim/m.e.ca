# 호스트 실행과 승인 경계

[현재 실행 구조](runtime.md) · [설정](configuration.md) · [플랫폼 검증](development.md#플랫폼-실행-검증)

MECA는 설치된 호스트 셸과 개발 도구를 실행 사용자 권한으로 사용한다. 프로젝트 경로는 기본 작업 위치이며 OS 보안 경계가 아니다. 위험 작업은 필수 사용자 승인을 거친다.

## 셸과 개발 환경

- execute_command는 /bin/sh -c로 실행하며 매 호출을 현재 세션의 정규화한 프로젝트 디렉터리에서 시작한다. cd는 해당 호출에만 적용된다.
- HOME·PATH·TMPDIR·개발 설정·프록시·인증 에이전트 등 부모 프로세스 환경을 그대로 전달한다. 셸 별칭·함수·대화형 초기화 파일을 재현하는 계약은 아니다.
- DNS 설정과 마운트·네트워크·사용자 캐시를 호스트 상태 그대로 사용한다. 언어별 실행기나 캐시 경로 예외를 만들지 않는다.
- 파일 접근·삭제·하드링크·소켓은 OS 사용자 권한을 따른다. 프로젝트 밖 경로도 명령과 자식 프로그램이 접근할 수 있다.
- MECA는 명령 전에 프로젝트나 캐시 전체를 순회하지 않는다.

명령 문자열 검사와 사용자 승인은 자식 프로그램 전체에 대한 파일시스템 격리가 아니다. 빌드·테스트·패키지 설치도 호출된 코드의 부작용을 가질 수 있다. 강한 격리가 필요한 작업은 사용자가 별도로 격리한 실행 환경에서 MECA를 실행한다. MECA는 그 환경의 OS 권한을 우회하거나 승격하지 않는다.

## 자동 승인과 파일 도구

일반 작업은 자동 승인으로 고정하며 승인 모드를 선택하지 않는다. 현재 세션의 정규화한 프로젝트 루트 아래로 확정된 일반 파일·폴더 삭제와 내부 경로 간 이동은 자동 승인한다. 프로젝트 외부 또는 미확정 대상의 삭제·이동, 파괴적·원격 Git 작업, 프로젝트 밖 직접 변경과 분석이 불확실한 위험 작업은 승인을 요구한다. 필수 승인 시 실제 명령과 작업 디렉터리 또는 준비한 파일 변경을 사용자에게 제시하고 거절 시 실행하지 않는다. 준비한 operation은 한 번만 실행한다. 비대화형 실행에서는 필요한 승인을 자동으로 허용하지 않고 중단한다.

프로젝트 루트는 현재 세션의 `project_root`다. 새 대화는 meca를 실행한 폴더 또는 `meca <path>`의 지정 폴더를 사용하고, 기존 대화를 선택하면 그 세션의 저장된 프로젝트를 사용한다. 개별 셸 호출에서 `cd`해도 삭제·이동 정책의 기준 프로젝트는 바뀌지 않는다.

다른 위험 동작이 없는 명령을 `~/workspace/v/t1` 세션에서 실행하는 예시다. 보호 경로 차단은 승인 요청보다 우선하며, Git 작업 등 별도 승인 사유는 함께 적용한다.

| 명령 | 판정 |
| --- | --- |
| `rm sample.py`, `rm -rf src` | 내부 하위 경로 삭제: 자동 승인 |
| `rm ../t2/sample.py` | 외부 경로 삭제: 승인 요청 |
| `rm -rf .`, `rm -rf ..` | 프로젝트 루트 자체·상위 경로 삭제: 차단 |
| `rm *.tmp`, `rm "$(cat target.txt)"` | 실행 전 삭제 대상을 확정할 수 없음: 승인 요청 |
| `mv a.txt b.txt`, `mv src/a.txt .` | 출발지·실제 도착지가 내부 하위 경로: 자동 승인 |
| `mv a.txt ../t2/a.txt` | 외부 경로로 이동: 승인 요청 |
| `mv . ../backup` | 프로젝트 루트 자체 이동: 차단 |
| `git rm sample.py` | 실제 Git 변경: 내부 파일이어도 승인 요청 |

전용 파일 도구도 system Scope에서 호스트의 일반 경로를 사용할 수 있다. 상대 경로는 프로젝트를 기준으로 해석한다. 대상 정규화·symlink 해석·원본 버전·정확한 부분 수정·승인된 diff 연결은 파일 도구가 소유한다. 파일 저장은 같은 디렉터리의 임시 파일을 원자적으로 교체한다. 이동은 부모 descriptor와 대상 독점 생성을 사용한다.

전용 파일 도구와 파일 탐색기는 MECA 상태 및 알려진 개인 비밀 경로에 대한 직접 접근을 거절한다. 프로젝트 루트나 보호 경로의 상위 디렉터리를 이동하지 않는다. 이 방어는 호스트 셸·그 자식 프로그램까지 강제하는 보안 격리가 아니다. 로그·저장·모델 문맥·표시의 자격 증명 제거도 별도로 유지한다.

Scope는 애플리케이션에서 system으로 고정되며 메뉴나 설정으로 선택하지 않는다. 하위 파일 어댑터의 directory 계약은 파일 대상에만 적용한다. 해당 계약으로 임의 호스트 셸을 실행하려 하면 실행 전에 거절한다.

## 셸 구문 분석과 사고 방지

준비 시와 실행 직전에 셸 명령을 mvdan/sh의 AST로 파싱하여 인용·이스케이프·연결·파이프·리다이렉션·중첩 실행을 구분한다. 명령 이름을 먼저 확정하고, 단일 정밀 검사 목록에 등록된 명령의 인자만 해석한다. 목록 밖 실행 파일에는 같은 기본 허용 규칙을 적용하며 그 인자·내부 실행·하위 프로세스 동작은 추적하지 않는다. 분석 중 명령·명령 치환을 실행하거나 glob을 실제 파일 목록으로 확장하지 않는다.

관리 대상은 [정밀 검사 목록](../internal/policy/command/inspection.go) 하나다. 별도 허용 목록이나 명령 종류별 예외는 두지 않는다. 목록 밖 명령에 전달된 문자열은 실행 코드로 추측하지 않는다. 반면 같은 셸이 별도 단계로 실행하는 검사 대상 명령, 실행 가능한 명령 치환·함수 본문·리다이렉션은 공통으로 검사한다. 임의 실행 파일과 그 하위 코드의 안전성을 인증하는 기능은 아니다.

| 검사 대상 | 세부 판단 |
| --- | --- |
| rm·rmdir·unlink | 내부 하위 경로 삭제 자동 승인·외부/미확정 대상 승인·보호 루트 차단 |
| mv | 출발지·실제 도착지가 내부이면 자동 승인·외부/미확정 대상 승인·보호 경로 차단 |
| cp·install·ln·mkdir·touch·truncate·tee·리다이렉션 | 실제 쓰기 대상 |
| sed·gsed | 스크립트 효과·in-place 대상·백업 파일·별도 파일 출력·명령 실행 |
| find·xargs | 조회 인자와 삭제·출력 파일·하위 명령 구분 |
| git | 하위 명령·옵션·실행 설정에 따른 파괴 작업과 원격 변경 |
| chmod·chown·chgrp·시스템 명령 | 권한·소유자·디스크·마운트 작업 |
| 셸·env·command·eval 등 | 실제 실행 대상, 중첩 프로그램과 작업 경로 |

리터럴 명령명은 분석 중 변수가 미확정이 되어도 유지한다. 경로 합류로 PWD가 미확정이어도 단어 확장 준비용 조회만으로 고정된 명령 이름을 미확정 처리하지 않는다. 명시적인 $PWD 확장이나 상대 변경 대상은 실제 의존성에 따라 따로 판단한다. read·변수 지정·산술식은 영향받는 값만 갱신하고, 반복문 자체에는 승인을 요구하지 않는다. 반복해서 바뀔 수 있는 값·작업 경로는 본문 검사 전에 미확정으로 합친다. `&&`는 앞 단계 성공 상태를 다음 단계에 전달하고 파이프 양쪽의 셸 상태는 분리한다. 인용된 동적 값 한 개와 필드 분리로 여러 실행 인자가 될 수 있는 값도 구분한다.

분기나 `cd` 성공·실패 뒤의 작업 디렉터리가 서로 달라도, 알고 있는 경로 후보는 보존해 상대 변경 대상을 각각 검사한다. 모든 후보가 프로젝트 내부의 허용 대상이면 자동 승인하고, 외부 후보가 있으면 승인을 요구하며, 보호 경로 후보가 있으면 차단한다. 예를 들어 `cd src; touch result.txt`는 프로젝트 루트와 src 아래의 두 후보를 검사하므로 추가 승인이 필요 없다. `cd /etc; touch result.txt`는 보호 경로 후보 때문에 차단한다. 실제 셸 명령을 고치거나 실행 위치를 임의의 프로젝트 경로로 대체하지 않는다.

경로 후보는 분석 비용을 제한하기 위해 최대 32개를 보존한다. 후보 수를 넘거나 변수·명령 치환·반복 등으로 위치를 알 수 없으면 상대 변경 작업에 계속 승인을 요구한다. 이는 분석 상태의 한도이며 실제 프로젝트의 폴더 수나 실행 횟수를 제한하지 않는다. 절대 경로 대상은 작업 위치가 미확정이어도 독립적으로 검사한다. find의 -execdir처럼 위치를 추적할 수 없는 호출에서는 이전 PWD·OLDPWD 값도 확정값으로 재사용하지 않는다.

`echo 'rm -rf /etc'`는 데이터이며 `sh -c 'rm -rf /etc'`는 중첩 실행이다. 셸 구문이 잘못되면 invalid_command, 확인된 보호 경로 변경·권한 상승이면 command_blocked를 모델에 반환한다. 값 하나를 해석하지 못했다는 사실을 명령 전체의 이름 미확정으로 확산하지 않는다. 실제 명령 이름·위험 작업 대상·실행 코드가 불명확한 경우에는 사용자 승인을 요구한다.

- `/`, 홈 전체, `~/bin`, 시스템 경로, 프로젝트 루트 자체·상위 경로에 대한 명시적인 파괴 작업은 차단한다. 하위 경로 삭제는 자동 승인하지만 부모까지 제거하는 rmdir -p도 실제 부모 경로를 검사한다. `/dev/null`로의 일반 출력은 허용한다.
- `sudo`·`su`·`doas`·`pkexec` 호출과 root 사용자의 에이전트 시작을 차단한다. 도움말·설치·삭제 명령은 에이전트 실행이 아니다.
- 프로젝트 내부의 알려진 파일에 대한 일반 sed 치환은 자동 허용한다. GNU의 -i·-i.bak와 BSD의 -i '' 형식을 구분한다. -f 스크립트·미지원 구문·동적으로 생성되는 실행 코드는 검토를 요구하며, 확인된 별도 출력·백업 경로에도 같은 경로 정책을 적용한다.
- find -delete는 프로젝트 루트가 삭제 대상에 포함될 수 있으면 차단하며, 루트 제외 조건과 삭제 액션의 순서를 구분한다. 필터로 선택되는 대상이나 링크를 따라가는 삭제는 경로를 확정할 수 없어 승인을 요구한다. find·xargs의 하위 명령에도 같은 검사 목록을 적용한다. 실행 시 결정되는 인자가 변경 대상이나 실행 코드로 사용되면 해당 검사기가 판정하며, 단순 데이터의 미확정 자체에는 승인을 요구하지 않는다. find의 동적 파일을 실제로 확인한 경로처럼 취급하지 않는다.
- Git 분기 생성·clean/rm/mv의 명시적 dry-run·비실행성 표시 설정과 파괴 동작을 구분한다. 실제 git rm/mv는 승인을 요구한다. 프로젝트 내부의 단순 chmod +x·u+x·a+x는 경로 검사로 판단하고, 광범위 권한·소유자 변경은 승인을 요구한다.
- 필수 승인 사유가 있는 복합 명령은 전체 실행 전에 한 번 승인받는다. 모든 단계가 자동 승인 대상이면 질문 없이 실행한다. 승인 화면은 검토가 필요한 하위 명령·사유·대상과 실제 전체 명령을 보여준다. 개별 파일이 미정이면 확인한 디렉터리 범위를 표시하며 가상의 파일명을 만들지 않는다. 사용자 거절 시 앞의 정상 단계도 실행하지 않으며 같은 작업을 다른 명령으로 우회하지 않는다.
- 실제 삭제는 마지막 심볼릭 링크 자체를 지우는 동작과 그 링크를 경유하는 동작을 구분한다. 내부 링크 자체의 삭제는 자동 승인할 수 있지만, 링크를 경유한 실제 대상이 외부이면 승인을 요구하고 보호 경로이면 차단한다. 기존 경로의 링크와 `..` 해석 순서를 보존한다.
- 이동은 출발지와 실제 도착 항목을 모두 검사한다. mv a dir은 기존 디렉터리 dir 자체가 아니라 dir/a를 도착지로 검사한다. -t·-T와 목적지 디렉터리 링크를 구분하고, 해석하지 못하는 이동 옵션은 검토를 요구한다. 기존 대상 덮어쓰기에도 같은 경로 정책을 적용한다.
- 명령에 전달할 환경은 준비 시 고정한다. 실행 직전에 정책·대상 경로·관측한 파일 정체성을 재검사하고 달라졌다면 실행을 거절한다. 현재 대상을 확인해 새로 요청하면 그때의 정책으로 승인 필요 여부를 다시 판정한다. 고정한 환경 스냅샷 전체는 승인 내용이나 세션 기록에 저장하지 않으며, 표시할 대상에서는 비밀값을 제거한다.
- 전용 파일 변경도 같은 보호 경로·프로젝트 밖 변경 정책을 적용한다. 기존 디렉터리의 무변경 `mkdir -p` 결과에 추가 승인을 요구하지 않는다.

이 정책은 명시적인 위험 동작을 막는 사고 방지 장치다. 임의 실행 파일·외부 스크립트·빌드 훅·패키지 설치 코드 내부의 모든 효과를 해석하거나 통제하지 않으며, 승인 뒤 실행 중 경로가 바뀌는 경쟁을 OS 수준으로 차단하지 않는다. 그런 보장이 필요하면 별도 격리 환경에서 실행한다. 언어별 캐시 예외나 새 Scope 설정은 추가하지 않는다.

## 실행 사실과 출력

- 명령·시작 여부·stdout·stderr·종료 코드·실행 순서를 호출 ID에 연결해 저장한다.
- 명령 시작 실패와 실행 후 비정상 종료·사용자 취소를 구분한다.
- 실패·취소 전에 부분 효과가 있을 수 있으며 자동 재실행하지 않는다.
- 셸 실행 뒤 기존 파일 관측을 오래된 상태로 표시하고 관측하지 않은 변경을 추측하지 않는다.
- 출력 발췌·종료 상태·재조회 로그 경로를 제공한다. 정제한 수집 원본은 세션 이벤트에 한 번 보존한다.

원본 수집·모델과 TUI의 표시 한도는 [실행 구조](runtime.md#출력과-저장)가 소유한다. 현재 Executor의 재조회 로그는 종료 시 제거한다. 사용자 프로젝트와 공용 캐시는 정리하지 않는다.

## 프로세스 수명과 검증

프로세스 어댑터가 자식 프로세스 그룹·출력 pipe·종료 대기를 소유한다. Esc·실패·앱 종료 시 요청 worker를 합류하고 실행 중인 프로세스 그룹을 종료한다. 별도 세션으로 완전히 분리한 daemon의 정리까지 보장하지 않는다.

회귀 검사는 임시 HOME에서 캐시 생성, 기존 하드링크가 있는 프로젝트, 호스트 DNS 설정 파일 접근, 실제 설치 도구와 자식 실행, 로컬 HTTP, 승인 거절, 부분 출력과 취소를 다룬다. 호스트 DNS 설정을 읽을 수 있다는 사실과 실제 외부 도메인 조회·다운로드 성공은 별도 검증이다.

Linux·WSL·macOS의 실제 DNS·네트워크·인증 서비스·터미널 동작은 해당 환경에서 [검증 절차](development.md#플랫폼-실행-검증)를 수행한다. 교차 빌드는 네이티브 실행 검증을 대신하지 않는다.
