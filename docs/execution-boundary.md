# 호스트 개발 환경과 파일 실행 경계

[현재 실행 구조](runtime.md) · [설정](configuration.md#추가-쓰기-경로) · [플랫폼 검증](development.md#플랫폼-실행-검증)

메인 에이전트는 설치된 셸·개발 도구를 사용한다. Python·Node·Go별 실행기나 삭제 명령 변환기를 만들지 않는다. 모든 셸과 전용 파일 도구는 같은 신뢰된 경로 정책을 사용하고, Permission은 실행 승인 여부를 별도로 결정한다.

## 접근 정책

| 자원 | 권한 |
| --- | --- |
| 정규화한 프로젝트 | 읽기·실행·생성·수정·삭제 |
| V 소유 명령 임시 공간 | 해당 명령에 필요한 읽기·쓰기·실행 |
| 호스트 실행 파일·SDK·라이브러리·인증서·일반 개발 설정 | 읽기·실행 |
| 프로젝트 밖 일반 경로 | 쓰기·삭제 차단 |
| 전역 execution.writable_paths | 지정한 기존 디렉터리에 한정한 읽기·쓰기 |
| V 상태와 보호한 개인 비밀 경로 | 접근 차단 |

보호 경로에는 V 상태와 홈의 .v·.ssh·.gnupg·.aws·.azure·.kube·.docker·.colima·.orbstack·.netrc·일부 자격 증명 설정·macOS Keychains가 포함된다. 모든 개인 파일의 비밀 여부를 자동 식별하는 기능은 아니다. 전역 추가 쓰기 경로는 보호 정책을 우회하지 못한다.

프로젝트·추가 경로는 canonical 경로와 디렉터리 identity에 연결한다. 루트·홈 전체·시스템 디렉터리·보호 경로 및 이를 포괄하는 예외를 거절한다. 추가 경로의 중복은 합치고 상위 루트로 기존 경계를 덮는 설정은 거절한다. 모델 인자·프로젝트 문서·환경변수로 쓰기 권한을 추가하지 않는다.

전용 파일 도구는 os.Root를 사용하며 실행 직전 경로·원본 버전을 재검사한다. 이동은 양쪽 부모 descriptor를 고정하고 기존 대상을 원자적으로 덮어쓰지 않는다. 경계 루트와 보호 경로의 상위 디렉터리를 이동할 수 없다.

## 환경과 네트워크

- V가 받은 실제 HOME·PATH와 개발 설정을 보존한다. 별칭·함수·로그인 셸 초기화를 재현하는 계약은 아니다.
- /bin/sh를 사용한다. 언어별 실행 경로·캐시 탐색·XDG·npm·Go·uv 설정 덮어쓰기를 추가하지 않는다.
- TMPDIR·TMP·TEMP만 V 소유 임시 디렉터리로 설정한다. V 내부 환경 값과 인증 에이전트·제어 소켓 연결 값, 동적 로더 제어 값(LD_*·DYLD_*)은 격리 준비 전 코드 주입을 막기 위해 제외한다. 필요한 프로그램별 로더 설정은 승인된 명령 안에서 지정할 수 있다.
- macOS의 선택된 Apple 개발 도구는 검증 후 DEVELOPER_DIR로 전달한다.
- DNS·다운로드·로컬 TCP/UDP 시험에는 호스트 네트워크를 사용한다. 호스트 제어 소켓은 일반 인터넷 연결과 구분한다.

외부 패키지 캐시에 쓰기가 필요하면 사용자가 정확한 기존 디렉터리를 전역 설정에 추가한다. 터미널에서 도구가 검색된다는 사실이 모든 명령의 의존성·캐시·네트워크 조건을 보장하지는 않는다. 오류는 실제 출력과 함께 반환한다.

파일 경계는 네트워크를 통한 외부 서비스 변경까지 제한하는 VM 경계가 아니다. 임의 환경변수에 담긴 모든 비밀을 식별하지도 않는다. 권한을 가진 로컬 HTTP 서비스는 별도의 신뢰 경계다.

## OS 강제

Linux는 private user/mount/PID/IPC/UTS namespace, Landlock ABI 3 이상, seccomp와 capability 제거를 사용한다. 호스트 네트워크를 유지하고 인터넷 소켓과 제어 소켓을 구분한다. 기존 마운트를 재귀 bind하지 않고 중첩 마운트를 제외한 읽기 전용 호스트 뷰를 만든다. HOME·PATH가 별도 마운트에 있으면 필요한 mount root만 읽기 전용으로 추가하고 그 하위 마운트는 다시 제외한다. 쓰기 루트는 고정한 inode identity와 대조한 뒤 별도 연결한다. DNS 설정의 /run 대상만 명시적으로 노출하며 호스트 /run·/sys와 /proc는 그대로 가져오지 않는다.

macOS는 Seatbelt로 광범위한 읽기와 제한된 쓰기를 구분한다. 보호 경로의 읽기·쓰기·실행, 새로운 하드링크와 호스트 제어 소켓을 제한한다. 시작 상태 pipe로 정책 준비 실패와 실제 명령 시작을 구분한다.

두 플랫폼 모두 기존 write tree의 공유 inode·외부 파일시스템을 검사한다. 이름을 가진 Unix 소켓 연결은 OS에서 제한하며, 기존 소켓 파일의 삭제와 연결 권한을 구분한다. 전용 파일 대상에도 공유 inode와 mount 경계를 검사한다. Linux는 같은 device의 bind mount도 mount identity로 구분한다. 보호를 확정할 수 없는 조건은 실행 전에 거절한다. 공유 inode가 발견되면 사용자가 일반 복사본으로 정리해야 하며 조용히 링크를 끊어 의미를 바꾸지 않는다.

격리 준비 실패는 scope_unavailable이며 명령을 시작하지 않는다. 무격리 실행·권한 상승·보안 기능 생략으로 재시도하지 않는다. allow-all도 동일한 OS 파일 경계를 사용한다.

## 도구·승인·관측

저장 형식은 schema 18이다. 미지원 DB는 변환·삭제하지 않고 원본을 보존한 채 오류를 반환한다.

현재 도구는 execute_command·create_directory·write_file·edit_file·move_file이다. 파일 삭제는 rm·rmdir·unlink·find -delete·git rm 등 실제 셸이 처리한다. 바이너리·빈 폴더·복수·재귀 삭제도 같은 파일 경계를 따른다.

본문 생성·편집·이동에는 diff와 원본 검사를 제공하는 전용 도구를 안내한다. 셸의 생성·수정·이동도 허용하며 OS 파일 경계와 Permission으로 제어한다. 실행 중 실패한 복합 명령에는 앞선 부분 효과가 있을 수 있다.

approve에서 셸 승인은 실제 명령·작업 루트·고정한 추가 쓰기 경계에 연결한다. 파일 승인은 정규화한 후보·원본 버전과 diff에 연결한다. 일반 셸이 건드리는 전체 파일의 사전 diff를 제공하지 않는다.

- 호출 ID에 실행 인자와 결과를 연결해 저장한다.
- 명령 시작 여부·stdout·stderr·종료 코드·실행 순서를 실제 사실로 기록한다.
- 셸 실행 뒤 기존 파일 관측을 오래된 상태로 표시하며 관측하지 않은 변경을 추측하지 않는다.
- 동일 명령을 명시적으로 다시 호출할 수 있으며 매 실행의 결과를 따로 남긴다.
- 실패·취소 뒤의 부분 효과도 저장하고 자동 재생하지 않는다.
- TUI와 모델에는 출력 발췌·종료 상태·재조회 위치를 제공한다. 큰 수집 원본은 세션 이벤트에 한 번 보존하고 현재 세션의 재조회 파일은 Executor 종료 시 정리한다.

파일 경계는 프로젝트 안의 실수까지 복원하는 백업 기능이 아니다. 외부에서 동시 변경하는 호스트 프로세스에 대한 파일시스템 전체 트랜잭션도 제공하지 않는다.

## 수명과 검증 범위

명령은 독립 파일 작업과 겹쳐 실행하지 않는다. 프로세스 어댑터가 출력·자식 프로세스 그룹·descriptor·임시 공간을 소유한다. 취소·종료에는 worker를 합류하고 V 소유 자원만 제거한다. 사용자 공용 캐시·설치된 도구는 정리하지 않는다.

Linux의 PID namespace 종료는 분리된 자손까지 정리한다. macOS는 프로세스 그룹을 종료한다. 별도 세션으로 완전히 분리한 daemon에 대해 Linux PID namespace와 같은 정리 보장을 주장하지 않는다.

2026-10-18 macOS 네이티브 검사에서 내부·외부 삭제, 바이너리·재귀·부분 실패, 추가 쓰기 경로, 보호 경로, 실제 Go·Node·Python 자식 실행과 로컬 HTTP를 확인했다. 언어 이름은 검증 사례이며 제품 실행 분기가 아니다. 전체 코드 검사의 결과와 Linux·WSL 네이티브 검증은 구분한다. Linux·WSL의 실제 kernel·namespace·중첩 mount 및 배포판 정책은 해당 환경에서 [검증 절차](development.md#플랫폼-실행-검증)를 수행해야 한다.
