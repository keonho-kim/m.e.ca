# 에이전트 작동 방식

[← README](../README.md)

V는 사용자 요청 하나를 한 실행 루프에서 처리한다. 내부 Goal/Task 분해와 별도 최종 보고 호출을 제거하고, 메인 모델이 첫 native 호출부터 실제 작업을 진행한다.

## 실행 흐름

1. 프로젝트 루트의 선택적 AGENTS.md, 대화 이력, 현재 Scope·읽기 전용에서 가능한 도구를 전달한다.
2. 일반 답변이면 턴을 마친다. 도구가 있으면 응답 내 native 호출 전체를 검증한다.
3. 호출의 짧은 reason을 실행 인자와 분리하고, 호출 ID·인자 해시에 묶어 self-grounding으로 저장한다.
4. Scope·Permission·snapshot을 검사하고 실제 변경 후보를 고정한다.
5. 내용 변경이면 Conclave 심사를 거친 뒤 사용자 승인 정책을 적용한다.
6. 실행 직전 파일 버전·승인 바인딩을 확인하고 한 번 실행한다.
7. 결과·실행 순서·변경 revision을 저장한 뒤 다음 행동을 요청한다.

메인 응답은 평문이고 진행 설명은 native 호출과 함께 온 본문을 표시한다. 과거의 DONE/WAIT/CONTINUE 제어 헤더는 사용 대상에서 제거했다. 분석만 요청하면 해당 사용자 지시를 따르며 별도 접근 모드로 전환하지 않는다. 각 변경의 사용자 승인은 유지한다.

## Native 도구와 근거

Chat Completions·Ollama의 tool_calls, Responses의 function_call을 사용한다. 도구 목록과 JSON Schema는 매 결정 요청에 제공한다. 스트림이 끝나고 전체 인자 검증이 통과한 뒤 실행을 준비한다. 다중 호출의 인자와 정책을 먼저 검사하고 독립 파일 작업을 최대 4개씩 병렬 실행한다. 같은 경로·상하위 경로·파일 별칭과 셸 명령은 순서를 지킨다. 잘못된 호출이 포함되면 어느 것도 실행하지 않고 연결된 오류를 반환한다.

모든 도구에는 필수 reason 문자열이 있다. UTF-8 32MiB 이내로 현재 요청이나 관측 근거를 설명하며 정상 개행·탭을 허용한다. 간결함은 프롬프트 지침이며 짧은 글자 수를 강제하지 않는다. 근거는 native 이력과 별도 감사 기록으로 보존하며, 별도 모델 호출은 없다. 근거는 모델의 주장이고 승인이나 검증 결과와 구별된다.

execute_command는 command 인자로 검색·목록·프로세스 작업을 받으며 purpose 분류는 사용하지 않는다. search_files·list_directory·grep 전용 도구는 제거했다. 실제 명령·종료 코드·출력·파일 변경과 실행 순서는 이벤트 기록으로 유지한다.

## Conclave

내용 변경 후보 하나에 동일 모델로 심사 1회를 수행한다. 형식 교정 또는 추가 문맥 확보에 1회를 더 쓸 수 있다. 전송 재시도도 전체 모델 호출 예산에 포함한다.

심사 입력은 사용자 요청, 프로젝트 지침, 짧은 의도, frozen diff와 파일 메타데이터다. 파일 전체 인자와 같은 diff를 중복 전송하지 않는다. 줄 수와 EOF 개행 여부는 실행기가 계산한다. 내용 없는 생성·변경량 0인 후보는 심사를 생략한다.

반환 계약은 다음과 같다.

- pass: 지적 없는 통과.
- reject: 최대 3개의 구체적인 사유. 후보 경로와 before/after 줄 또는 request의 line=0을 지정한다.
- needs_context: 최대 2개의 scoped read_file 요청. offset/limit은 바이트이며 각 limit은 최대 8,192다.

엄격한 로컬 JSON 파서가 계약과 참조를 검사한다. 현재는 모든 Provider에서 이 계약을 사용하며 서버 문법 강제 기능을 자동 협상하지 않는다. 추가 조회·교정 후에도 판정이 불완전하거나 오류가 생기면 실행을 차단한다. 실행 전 심사는 후보를 판단하고 실제 적용·테스트는 실행 이후에 수행한다.

동일 요청·지침·모델·파일 delta·관측 상태에 대한 거절은 실행 내 최대 32개까지 재사용한다. 새 Call ID나 reason만 바꿔 반복해도 재심사 비용이 추가되지 않는다. 승인과 실제 파일 버전 검사는 매번 적용한다.

Monitor는 기존 실행 worker에서 제안·심사·승인·시작·결과를 순서대로 저장한다. 별도 관측 goroutine과 모델 호출은 없다. UI에는 Conclave Pass/Fail과 부결 안내를 표시한다. 부결 시 모든 거절 사유를 파일 경로·줄 번호·변경 전후 위치와 함께 들여쓴 목록으로 보여준다. 심사 오류도 마스킹한 진단과 함께 표시하며, 실시간과 저장된 대화 복원에 동일한 표시 규칙을 적용한다.

## 검증과 종료

작업 결과는 완료한 변경·실제로 수행한 확인·미검증 또는 미완료 사항을 구분해 보고한다. 검사 실행 여부나 성공을 최종 답변의 필수 조건으로 강제하지 않는다.

명령의 종료 상태와 출력은 실제 관측값으로 전달한다. 성공한 명령 하나를 전체 구현의 정확성으로 승격하지 않는다. 별도 필수 검사 목록과 변경 후 검사 게이트는 두지 않는다.

최종 답변을 일반 검증 실패 문구로 대체하거나 검증만을 위한 재호출을 강제하지 않는다. 정상 보고는 answered, 실행 전 심사가 해결되지 않은 종료는 stopped이며 후보 실행은 계속 차단한다. 취소는 interrupted다.

기본 3회 무진전에는 최대 2회의 복구 기회를 준다. 동일 관측, 파일 내용 순환, 실패 반복을 기준으로 하며 Call ID·reason 변경은 진전으로 세지 않는다. 이미 시작한 동일 부작용은 자동 재실행하지 않는다. 사용자 승인 거절과 취소는 실행을 멈춘다.

## 문맥과 예산

압축 전 전체 대화와 호출·결과 쌍을 유지한다. 고아 호출은 실행 가능한 이력 대신 인용 관측으로 남긴다. 반복 조회도 Scope와 실제 파일을 확인하되, 동일 본문이 현재 문맥에 남아 있으면 unchanged와 원본 호출 참조를 반환한다. 원본이 압축됐다면 본문을 다시 제공한다.

마지막 성공한 압축 이후 모델 요청별 실제 INPUT+OUTPUT 누적 200,000 토큰이 압축 기준이다. 압축 자체의 호출은 발동 누적량에서 제외한다. 사용량 미수신 호출은 요청·응답 UTF-8 바이트 합을 3으로 나누어 올림한 값을 대신 사용한다. 압축 입력은 중복 감사 기록을 제외하고 발췌·우선순위 선택으로 구성하여 모델 요청 한 번으로 요약한다. 명시적인 context_length_exceeded 계열 오류에는 안전한 경계에서 압축하고 모델 요청만 한 번 재시도한다. 임의 오류 문구를 문맥 초과로 추측하지 않는다. 상세 설정은 [설정 문서](configuration.md)를 따른다.

기본 실행 한도는 다음과 같다.

| 설정 | 기본값 |
| --- | ---: |
| max_iterations | 128 |
| max_model_calls | 1024 |
| max_seconds | 14400 |
| max_model_seconds | 600 |
| max_context_bytes | 268435456 |
| max_argument_bytes | 268435456 |
| stall_iterations | 3 |

max_model_seconds는 무수신 제한이다. 데이터가 계속 오는 모델 호출은 완료까지 수신하고 다음 작업 전에 전체 시간 예산을 다시 검사한다. 승인·도구 실행은 남은 실행 시간 내에서 처리한다. Ctrl+C 또는 !quit은 작업을 취소하고 자원을 정리한다.

HTTP·스트림 오류는 기존 최대 3회 전송 시도와 명시적 최종 오류를 유지한다. 실패한 스트림의 부분 응답은 다음 시도에 이어 붙이지 않으며 도구를 재생하지 않는다. INPUT/OUTPUT 표시는 Provider가 실제 보낸 usage만 합산한다.

## 구현 경계

agent/run은 수명과 순서, agent/tool은 호출·실행 사실, agent/conclave는 심사, agent/context는 문맥, agent/verification은 검사 상태, agent/compact는 요약을 소유한다. 저장 계약과 SQLite 어댑터는 분리한다. 모델군의 특화는 provider/profile에서 관리한다.

단기 로컬 사례의 측정 결과는 장시간 수렴이나 모델 전체의 성공률을 보장하지 않는다. 비교 평가는 같은 모델·서버 설정에서 실제 성공 여부와 수신 토큰·호출 수를 함께 확인한다.

## 파일 형식과 검증 명령의 보호

read_file은 실제 FinalNewline과 읽은 범위의 RangeLineEndings(lf/crlf/mixed/none/unknown)를 반환한다. 화면용 줄바꿈과 원본 바이트를 구분한다.

write_file·edit_file의 format_policy 기본값은 preserve다. 기존 파일의 마지막 개행이 빠진 비어 있지 않은 결과에는 기존 종결자를 보충한다. 기존에 없던 EOF 개행 추가나 줄바꿈 형식 변경은 명시적 literal 정책이 필요하다. 빈 파일 생성·내용 전체 삭제는 요청한 빈 내용을 유지한다. partial edit의 균일한 CRLF 범위는 preserve에서 기존 형식으로 처리한다. literal은 의도적인 형식 변경을 허용하며 여전히 실제 diff 심사와 사용자 승인을 거친다.

정규화는 후보 고정 전에 끝낸다. Conclave는 실제 결과의 형식 메타데이터와 diff를 받고, 승인 후에는 그 바이트를 기록한다. 공백과 꼬리 빈 줄을 일괄 삭제하지 않는다. 새로 유입된 줄 번호·해시 표시 패턴은 기본적으로 소스 복사 오류로 거부한다. 해당 표식 자체가 요청된 파일 내용이면 literal로 명시한다. 도구 실패 직후 다시 읽을 때는 동일 본문이라도 원문과 앵커를 반환한다.

명령은 목적 분류 없이 공통 셸 정책을 따른다. 격리 초기화 실패는 scope_unavailable로 반환하며 실행된 명령으로 취급하지 않는다. 종료 코드와 출력은 관측값으로 보존한다.

## 플랫폼 실행 환경

macOS는 명시된 DEVELOPER_DIR 또는 xcode-select -p로 선택된 설치 경로를 검사한다. 해당 설치와 부모 경로의 필요한 메타데이터만 접근시키고 도구 설치는 읽기·실행 전용으로 유지한다. Xcode 앱 경로는 Contents/Developer로 해석한다. 설치가 없는 경우 일반 실행 환경을 유지하며, 잘못 지정된 경로나 보호 경로와의 충돌은 준비 오류로 처리한다. 전역 개발 도구 선택 변경이나 자동 설치는 수행하지 않는다.

프로젝트 격리는 Git의 시스템·사용자 전역 설정을 제외하고 프로젝트 로컬 설정을 사용한다. GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_GLOBAL=/dev/null을 지정한다. 공통 환경의 XDG 설정·캐시와 임시 파일은 실행용 임시 경로를 사용한다.

Linux의 ~/.local/bin과 ~/.local/share/uv/python은 명시적 읽기 전용 런타임 경로다. PATH 보완과 UV_PYTHON_INSTALL_DIR 지정, 디렉터리 우회 심볼릭 링크 거부, 마운트·Landlock 규칙을 함께 적용한다. 지원 범위 밖의 임의 PATH 경로를 통째로 노출하지 않는다. 네임스페이스·마운트·Landlock을 사용할 수 없는 환경에서는 명령 실행 없이 원인을 반환한다.


## WSL의 하위 마운트와 실행 실패 표시

Linux는 격리 시작 시 private mount namespace의 mountinfo를 읽는다. 명시적으로 허용된 시스템 런타임 루트에 하위 마운트가 있으면 그 지점은 빈 자리로 남기고, 나머지 디렉터리·파일만 읽기 전용으로 구성한다. 잠긴 하위 마운트 아래의 파일이나 마운트로 가려진 원래 내용은 가져오지 않는다. 심볼릭 링크는 원래 링크 텍스트를 유지하고 격리된 파일 트리 안에서 해석한다. 재귀 bind로 호스트의 하위 마운트 전체를 들여오는 방식은 사용하지 않는다.

이 처리는 특정 WSL 버전이나 /usr/lib/wsl 경로 문자열에 의존하지 않는다. 최대 8 MiB/65,536개 mountinfo 항목과 8,192개 런타임 투영 항목, 깊이 128을 제한으로 두며 초과 시 실행 없이 오류를 반환한다. kernel API·Scope·Landlock·seccomp 조건은 그대로 유지한다. GPU 등 별도 마운트에 있는 런타임 리소스는 자동 허용 대상이 아니다.

검증 명령의 격리 준비가 실패하면 체크포인트에 실제 차단 사유를 보존한다. 작업 완료를 검증하지 못했을 때 사용자 응답과 다음 모델 문맥에도 이 원인을 표시한다. 검증이 수행되지 않은 상태를 성공으로 바꾸지 않는다.

### 반복 수정과 종료 안내

반복 수정 횟수에 따른 검사 명령 강제는 제거한다. 파일 내용 순환과 동일 부작용의 중복 실행 감지는 유지하며, 실패한 실행 결과는 다음 판단의 관측 자료로 전달한다.

파일 내용이 이미 관측한 상태로 돌아오는 순환은 즉시 기존의 최대 두 차례 복구 흐름에 반영한다. 중간 읽기가 있어도 순환 사실을 지우지 않는다. 복구 한도를 넘으면 미완료 상태와 마지막 관측을 반환한다. 원본 버전으로 자동 되돌리거나 최선의 버전을 추측하지 않는다.

변경 이후 모델에는 완료한 변경·실제 확인·미검증 사항을 구분하도록 안내한다. 사용자 요구가 충족되면 결과를 보고하고 추가 수정은 구체적인 미충족 요구나 관측된 결함에 근거한다. 전체 반복·시간·모델 호출 예산은 유지한다.


## 검색 명령과 셸 실행

설치된 find·ls·rg·grep을 execute_command로 실행한다. 모든 요청에 같은 셸과 옵션 의미를 적용하며, 파이프와 리다이렉션을 사용할 수 있다. Permission 승인과 프로세스 취소·출력 한도를 적용한다. 파일 생성·수정·삭제·이동은 전용 도구를 사용하고 read_file은 줄 번호·앵커를 제공한다. find의 -delete·-fprint·-fls·-exec·-ok와 rg의 --pre 등 직접 파일 작업이나 우회 실행은 기존 정책으로 검사한다. 파일 브라우저의 내부 Directory API는 유지한다.

### 원래 사용자 요청의 보존

현재 사용자 요청 원문을 실행 체크포인트에 보존하고 매 추론의 현재 문맥에 제공한다. 도구에 요청 전체의 접근 모드나 완료 기준을 등록하는 인자는 없다. 종료 Conclave는 원문 요청·프로젝트 요구·실제 실행 결과를 직접 대조한다. 일반 대화에는 별도 명세 생성이나 종료 심사를 강제하지 않는다. 달라진 관측과 남은 요청만 이어가며, 별도 Goal/Task·ToDo 도구·준비용 모델 호출을 추가하지 않는다.

Bootstrap은 기존 사용자 프롬프트를 덮어쓰지 않는다. 다른 컴퓨터에 바이너리만 교체하면 기존 ~/.v/prompts/system.md의 지침은 유지된다.


### 병렬 native 호출

모델 응답 하나에 최대 32개 호출을 받을 수 있고, 기존 반복 예산은 호출 수만큼 사용한다. 실행 단위는 최대 4개이며 실제로 겹쳐 실행하는 부분은 준비된 도구의 Execute뿐이다. self-grounding·Scope 검사·후보 고정·Conclave·사용자 승인은 호출별로 순서대로 수행한다. 승인 후 경로 독립성을 다시 확인하고, 각 실행은 원본 버전과 Scope를 재검사한다.

같은 경로, 부모/자식 경로, symlink나 hardlink로 연결된 동일 파일은 직렬화한다. 생성될 부모 폴더와 하위 파일도 순서대로 준비하므로 후속 후보는 앞선 결과를 본다. 셸 명령과 독립성을 판정할 수 없는 실행기는 직렬 처리한다. 모델이 앞선 출력으로 인자를 계산해야 하는 작업은 다음 모델 턴에 호출해야 한다.

한 실행 단위의 준비·심사·승인 중 하나라도 실패하면 해당 단위는 실행하지 않는다. 실행 중 실패하면 이미 함께 실행 중인 독립 작업은 종료까지 기다려 실제 결과를 보존하고, 뒤에 남은 호출은 미실행 결과를 반환한다. 이전 단위에서 완료된 변경을 자동으로 되돌리지는 않는다. 취소도 모든 시작한 작업을 join하고 결과를 저장한다. 원본 assistant 호출 배열과 호출 순서의 tool 결과를 유지하며, 저장·TUI 이벤트·사용량·진행 상태는 병렬 작업에서 직접 수정하지 않는다.

Chat Completions와 Responses 요청은 parallel_tool_calls=true를 전송한다. Ollama는 해당 필드 없이 native tool_calls 배열을 처리한다. 실제 모델의 여러 호출 생성 여부는 모델과 서버의 native parser 지원에 따른다.


### 압축 후 현재 요청과 생성 결과

현재 실행의 요청 원문은 압축 요청의 ActiveRequest로 별도 전달하고, 메인 모델의 마지막 판단 메시지 끝에도 항상 고정한다. 과거 요약이나 중단된 요청은 현재 요청을 대체하지 않는다. 가장 최근 성공한 파일 변경은 768바이트 이내 발췌로 체크포인트에 유지하여 이후 조회가 관측 문구를 바꿔도 다음 문맥에서 확인할 수 있다. 이는 해당 실행 당시의 결과이며 현재 파일 상태나 전체 작업 완료를 증명하는 게이트가 아니다.

파일 생성·수정 결과는 action과 size_bytes를 제공하므로 빈 파일의 0바이트를 명시한다. 성공한 생성 결과 자체가 생성 작업의 관측이며 별도 확인 명령을 강제하지 않는다. 반복 관측은 명령 실행 횟수 때문에 새 진전으로 계산하지 않는다. 동일 명령·대상·결과를 다시 받으면 무진전으로 기록하고, 실제 파일 변경이나 원본 변경 충돌이 있으면 기존 관측 캐시를 비워 필요한 재확인을 허용한다.

디렉터리 생성은 `create_directory({"paths":["src/app","tests/unit"]})`처럼 요청한다. 누락된 부모를 포함해 한 호출에서 최대 64개 경로를 검사하며 기존 폴더는 그대로 성공한다. 전체 경로를 사전 검사하고 승인 시 생성 대상 목록을 고정한다. 공유하는 미생성 부모가 있는 호출은 순차 처리한다. 실행 중 실패하면 이미 생성한 경로를 실제 변경 기록에 남기며 자동 삭제하지 않는다.


### 요청 명세·작업 기억·종료 Conclave

현재 사용자 요청 원문을 실행 체크포인트에 보존하고 매 추론의 현재 문맥에 제공한다. 도구에 요청 전체의 접근 모드나 완료 기준을 등록하는 인자는 없다. 종료 Conclave는 원문 요청·프로젝트 요구·실제 실행 결과를 직접 대조한다. 일반 대화에는 별도 명세 생성이나 종료 심사를 강제하지 않는다.

실행 전 completes 선언은 제거했다. 실행기는 현재 요청의 실제 도구 결과·종료 코드·대상·출력과 실패를 모두 보존한다. 최근 32개 기준의 제거는 없으며 전체 근거 JSON의 256MiB 자원 상한을 넘으면 원본 이벤트를 보존하고 명시적으로 중단한다. 파일 관측은 버전에 연결하고, 명령 실행 뒤와 종료 판단 전에 알려진 파일을 다시 확인한다. 내용이 같은 근거는 유지하고 변경·미확인 파일 근거만 stale로 표시한다. 명령 결과는 그 시점의 실행 사실이며 이후 소스의 정확성을 증명하지 않는다. 압축은 이 상태를 재생성하지 않고 체크포인트가 따로 보존한다.

메인 모델의 최종 답변 초안 또는 반복 징후에서 agent/completion이 별도 종료 Conclave를 호출한다. 실제 모델·연결은 같지만 영어 completion.md 프롬프트, inference.completion 역할(temperature=0.2, max_output_tokens=2048, thinking=off_if_supported)을 사용한다. 전체 대화·Thinking 대신 원래 요청·유효성 표시된 결과·초안·미해결 변경 심사 상태를 전달하고 도구는 제공하지 않는다. 응답은 complete/continue/blocked이며 사유와 실제 근거 ID(또는 request)가 필요하다. continue의 unmet에는 원래 요청 중 미충족 결과를 구체적인 문자열 목록으로 설명한다. 숫자 ID 등록은 필요 없다. complete가 실패·오래된 근거 또는 미해결 변경 심사를 인용하면 거절한다. 모델 판단은 독립적인 정확성 증명이 아니다.

통과한 최종 초안은 추가 재작성 호출 없이 확정한다. continue는 구체적인 미충족 사항만 다음 추론에 넣고, blocked·심사 오류·동일 상태 재제안·예산 소진은 도구 없는 미완료 보고로 끝낸다. 심사 형식 오류는 원문과 오류를 넣어 한 번만 교정하며 Provider 재시도는 기존 공유 예산 안에서 수행한다. 반복 감지는 모든 배치 결과가 기록된 경계에서만 종료 심사로 전환한다. 종료 심사는 사용자 승인을 대체하지 않는다.

!plan 명령과 계획 승인·단계 실행·저장 기능, 요청별 읽기 전용 모드와 access 인자는 제거했다. 모든 요청은 동일한 Permission 정책과 셸 실행 경로를 사용한다. 분석만 해 달라는 요청은 사용자 지시로 따르며 별도 모드 비트로 강제하지 않는다. 모델이 도구 인자로 Permission을 바꾸거나 승인을 선언할 수 없다.

SQLite schema는 9이다. 기존 DB는 변환·삭제하지 않고 미지원 오류로 보존한다. 기존 config.toml의 [inference.plan]은 수동으로 제거해야 하며, 새 설정에는 [inference.completion] 기본값이 기록된다. bootstrap은 새 completion.md만 없는 경우 생성하고 기존 개인 프롬프트를 덮어쓰지 않는다.

### 실행·심사 경계 정렬

도구 선택은 카탈로그·runtime 시스템 지침·정책 실패의 Next 안내에 동일한 역할 구분을 사용한다. 직접 mkdir/touch는 create_directory(paths)/write_file(path, content)로 안내하고, 첫 읽기와 그 결과에 의존하는 편집은 다른 응답에서 수행한다. 기본 preserve 편집은 저장된 범위의 다음 줄 경계와 개행 형식을 보존한다. literal은 명시적 형식 변경이며 앵커 혼입 오류의 우회 방법으로 안내하지 않는다.

모든 native reason·grounding·변경 심사의 사유와 추가 문맥 사유·종료 심사 사유는 tool.CheckReason의 32MiB UTF-8 규칙을 공유한다. 256자 제한은 제거하고 개행·탭을 허용한다. 경로·ID 제한 및 전체 자원 상한은 별도다. 원본 사유는 잘라 바꾸지 않는다. 상태 요약과 표시용 발췌는 원본 이벤트와 구분한다.

변경·종료 심사는 응답 전체를 감싼 단일 JSON 코드 블록만 공통 정규화한다. 임의 본문에서 JSON을 추출하지 않는다. 종료 심사는 유효성 오류를 한 번 교정하며 근거를 추측해 채우지 않는다. 각 시도의 마스킹된 원문(최대 16MiB, 초과 표시)과 오류를 review_attempt로 저장한다. 교정과 Provider 재시도는 공유 예산을 소비한다. 변경 심사 자체가 복구 후 실패하면 코드 재작성을 요구하지 않고 중단 보고한다.

병렬 배치는 모든 후보를 먼저 고정한다. 개별 변경 심사에는 미실행 형제 후보 경로를 제공하고, 추가 조회가 그 경로를 가리키면 proposed delta로 반환한다. 이를 실제 실행 결과로 취급하지 않는다. Scope·버전·개별 승인·실행 직전 충돌 검사는 유지한다.

디렉터리 존재 근거는 경로별로 분리한다. 하위 파일 추가는 부모 존재를 무효화하지 않는다. 삭제·이동·교체되는 대상 및 상위 경로는 관련 존재 근거를 무효화한다. 알려진 파일의 실제 버전을 대조하고 확인할 수 없는 파일 상태는 유효하다고 추정하지 않는다. 과거 명령의 실행 사실은 별도로 유지한다. 실행 실패와 미실행은 성공 근거가 아니다.

stopped 상태는 추가 모델 호출 없이 기록된 사실로 보고한다. 성공한 실행·실패/미실행·현재 상태를 보장하지 못하는 과거 근거·중단 사유를 구분한다. 작업 응답의 비-native 도구 문법은 실행하지 않고 한 번 교정한 후 반복되면 중단한다. 형식 교정은 성공한 실제 도구 실행 이후 새 구간에서 다시 허용한다.

### 도구 인자와 권한의 소유

모든 native 도구는 호출별 self-grounding을 위한 reason을 필수로 받는다. 그 외 인자는 실제 실행 결과나 읽기 범위를 결정하는 값만 남긴다.

| 도구 | 필수 실행 인자 | 선택 실행 인자 |
| --- | --- | --- |
| read_file | path | offset, limit |
| create_directory | paths | 없음 |
| write_file | path, content | format_policy |
| edit_file | path, start_anchor, end_anchor, new_text | format_policy |
| delete_file | path | 없음 |
| move_file | path, destination | 없음 |
| execute_command | command | 없음 |

access와 completion_criteria는 도구 계약과 체크포인트에서 제거했다. purpose·completes·승인 여부·Permission 설정도 도구 인자로 받지 않는다. 미등록 인자를 포함한 배치는 준비·실행 전에 전체 거절한다. 원래 사용자 요청은 체크포인트와 현재 문맥에 유지하며, 종료 심사의 unmet은 미충족 요청 내용을 설명하는 문자열 목록이다. 새 요청 분류 모델 호출이나 계획 도구는 추가하지 않는다.

Permission은 세션 설정의 단일 정책이다. 읽기는 개별 변경 승인이 필요 없고, 변경·셸은 approve일 때 실제 후보에 대한 승인을 받는다. allow-all은 그 승인 질문만 생략한다. 준비와 실행 직전의 정책·파일 버전 검사, 변경 Conclave, 취소 및 실행 결과 보존은 유지한다. 읽기 전용 요청 상태와 내장 조회 에뮬레이터는 제거했으며, OS 샌드박스의 읽기 전용 마운트나 SQLite 목록 조회용 읽기 전용 연결은 각 어댑터의 독립적인 기능이다.

format_policy는 단순 설명 메타데이터가 아니라 최종 파일 바이트를 결정한다. preserve는 기존 개행 형식을 보존하고, literal은 사용자가 의도한 실제 형식 변경에 사용한다. 읽기 offset/limit와 편집 앵커도 범위·위치를 결정하므로 유지한다.

### 종료·작업 문맥 계약 정렬

잘못된 native 호출과 배치 거절도 실패 관측으로 보존한다. 실행 결과가 없다는 이유로 일반 대화 분기에 넣지 않으며, 실패 뒤 완료 주장은 종료 심사를 거친다. 종료 심사에는 잘라내지 않은 최종 답변 전체를 전달하고, 통과한 동일 본문을 확정한다. 답변 없이 완료 판단에 도달한 경우에는 실제 실행 기록으로 결과를 표시하고 미심사 답변을 새로 생성하지 않는다.

응답 본문은 도구 사용 후에도 스트리밍한다. 심사에서 추가 작업이 필요하면 표시 중인 초안을 지우고 작업을 이어간다. 최종 대화 기록은 통과 후 확정하며, 심사 중 취소한 초안은 미완료 메모로 남겨 다음 입력에서 참고할 수 있다.

기본 프롬프트와 문맥에는 작업 지침·원래 요청·관측 결과·미충족 작업만 제공한다. 실행기 구조, 완료 심사 절차, 내부 체크포인트·심사 식별자를 메인 모델에 설명하지 않는다. 변경 심사·종료 판단·요약 프롬프트는 각각 해당 작업과 필요한 응답 형식만 지시한다. 사용자 프로젝트 지침과 실제 도구 오류는 작업 자료로 유지한다.

압축 입력과 요약은 각각 16MiB까지 수용하고 저장·복원에도 같은 요약 한도를 적용한다. 셸의 stdout/stderr 캡처와 파일·변경 미리보기, HTTP 오류 본문도 16MiB까지 수용한다. 기존 32MiB 사유와 더 큰 JSON 봉투 한도는 유지한다. 읽기 기본 페이지·최근 원문 보존량은 선택량이고, 경로·ID·개수는 의미적 제약이므로 본문 수용 상한과 구분한다. 모델의 실제 context 및 출력 토큰 예산은 별도로 적용된다. 새 bootstrap 설정에는 확대된 기본값을 기록하고 기존 사용자 설정·프롬프트는 덮어쓰지 않는다.
