# 에이전트 작동 방식

[← README](../README.md) · [설정](configuration.md) · [사용 가이드](usage.md)

메인 에이전트 하나가 사용자 요청을 이해하고 파일·셸 도구로 직접 작업하며 결과를 보고한다.

## 실행 흐름

1. system.md·development.md와 선택적인 프로젝트 루트 AGENTS.md를 준비한다.
2. 전체 대화·현재 요청·현재 파일 관측·요약과 native 도구 정의를 모델에 전달한다.
3. 완성된 인자를 검증하고 reason을 정확한 인자에 연결해 저장한다.
4. 접근 정책·현재 원문·후보를 확인하고 Permission 승인과 실행 직전 버전 검사를 수행한다.
5. 도구의 실제 결과·명령·종료 코드·출력·파일 변경을 같은 호출 ID에 연결해 저장한다.
6. 필요한 작업을 이어가거나 완료한 변경·실제 확인·미검증 사항을 구분해 답한다.

일반 대화는 바로 답한다. 요청 분석·완료 판정을 위한 별도 모델 호출이나 강제 검증 완료 게이트는 없다. 메인 추론 설정은 [agent]이며 요약·연결 진단은 각각 [compaction]·[diagnotics]를 사용한다.

## Native 도구와 self-grounding

Chat Completions·Ollama는 tool_calls, Responses는 function_call을 사용한다. 매 결정 요청에 고정 도구 설명과 JSON Schema를 전달한다. assistant 본문의 JSON은 실행하지 않는다. 잘못된 인자가 포함된 배치는 준비·실행 전에 전체 거절한다.

| 도구 | 실행 계약 |
| --- | --- |
| execute_command | 조회·검색·목록·빌드·테스트·패키지 관리·셸 삭제. 실제 stdout·stderr·종료 상태 반환 |
| create_directory | 복수 경로와 누락된 부모 생성. 기존 디렉터리 허용 |
| write_file | UTF-8 본문 생성·전체 교체. 누락된 부모 생성 |
| edit_file | 현재 원문에서 유일하게 일치하는 1~64개의 부분 수정. 겹침 거절 |
| move_file | 파일·디렉터리를 존재하지 않는 대상으로 이동 |

공통 reason은 준비 전에 저장하는 모델의 주장이다. UTF-8 32MiB 이내로 받고 실행 인자와 바인딩하며 승인·검증 증거로 사용하지 않는다. 나머지는 실제 실행 값을 결정하는 인자다.

파일 조회는 cat·sed·head/tail·nl·grep·rg·find·ls를 사용한다. 직접 mkdir/mv·파일 리다이렉션·in-place sed 등 알려진 변경 호출은 전용 도구로 안내한다. 이 분류는 임의 코드의 모든 부작용을 증명하지 않는다.

## 승인과 실행 순서

모든 도구는 프로젝트·명시한 추가 쓰기 경로의 공통 보호 정책을 사용하며 Permission은 approve 또는 기본 allow-all이다. allow-all은 승인 질문만 생략하며 파일 버전 검사·권한 상승과 별개다. 셸 승인은 실제 명령·작업 루트·고정한 추가 쓰기 경계에, 파일 승인은 정규화한 실제 후보·대상·원본 버전에 연결한다.

edit_file의 각 old_text는 같은 현재 원본에서 한 곳에 일치해야 한다. 여러 수정이 겹치거나 원본이 바뀌면 후보 전체를 거절한다. format_policy=preserve는 기존 LF/CRLF·EOF를 보존하고 literal은 의도한 바이트 변경에 사용한다. 결과에는 실제 변경 전후 줄 위치를 반환한다.

독립 파일 작업만 최대 네 개씩 병렬 실행한다. 후보 준비·승인·충돌 검사는 요청 소유자가 수행한다. 같은 경로·상하위 경로·symlink·inode 별칭과 셸 명령은 직렬로 처리한다. 취소 시 worker를 모두 합류하고 결과는 원래 순서로 기록한다.

실행된 부분 효과와 미실행 작업을 구분한다. 도구 실패에는 실제 원인과 다음 행동을 반환하며 이미 적용한 부작용을 자동 재생하지 않는다.

## 현재 결과와 종료

실행 사실은 agent/tool, 현재 파일·명령 상태는 agent/completion, 파일 상태 순환은 agent/progress가 소유한다. 관측에는 버전을 연결하고 다음 결정 전과 최종 답변 생성 후 재확인한다. 모델에는 필요한 경로·존재·변경·오래됨 상태를 제공하고 내부 해시·실행 ID·revision은 저장 원본에 유지한다.

과거 명령 성공은 이후 코드의 정확성을 증명하지 않는다. 디렉터리 존재는 하위 파일 전체의 관측이 아니다. 후속 요청에도 알려진 파일을 이어받고 최신 상태를 확인한다.

answered는 답변 전달, stopped는 예산·정체 중단, interrupted는 취소다. answered가 테스트 통과나 기능 정확성을 보장하지 않는다. 최종 답변은 완성된 본문을 추가 재작성 없이 저장한다.

무진전은 한 모델 응답의 전체 도구 결과를 기록한 뒤 한 번 센다. 같은 알려진 파일 상태에서는 새 명령과 새 관측이 함께 있어야 명령 진전으로 계산한다. 기본 세 번 무진전 또는 파일 상태 순환은 추가 평가 호출 없이 실제 결과·사유를 보고하고 중단한다.

같은 변경은 이전 성공과 현재 대상 버전이 일치할 때 already_applied 결과로 재사용한다. 불확실한 부작용은 자동 재시도하지 않는다. 사용자 승인 거절은 현재 요청을 중단한다.

## 문맥·Compaction·복원

압축 전 전체 대화와 native 호출·결과 쌍을 순서대로 유지한다. 중단·압축으로 짝이 없는 기록은 실행 가능한 native 결과 대신 인용 관측으로 제공한다. 현재 요청은 압축 뒤에도 별도로 유지한다.

압축은 이전 메모·현재 요청·순서 있는 실제 결과를 한 번 요약하고 최근 필요한 원문은 함께 보존한다. 원본 DB 기록을 삭제하지 않는다. 발동량·선택 예산·본문 한도는 [설정 문서](configuration.md#프롬프트와-compaction)가 소유한다.

전송 재시도·압축도 같은 요청의 모델·시간 예산을 사용한다. 명시적인 context 한도 오류에는 안전한 경계에서 압축 후 모델 요청만 한 번 재시도한다. 저장된 도구 실행은 재개 시 자동 반복하지 않는다.

실행 ID·예산·진전 상태는 매 사용자 요청이 소유한다. agent/session이 요청을 준비하고 agent/run이 실행·승인·예산을 조율한다. TUI는 화면과 worker 수명을 관리하며 I/O 결과를 이벤트 루프에서 반영한다. 저장 기능은 session·history·recovery 계약과 SQLite 어댑터로 구분한다.

## 플랫폼 실행 경계

모든 셸은 [공통 파일 경계](execution-boundary.md)를 OS에서 적용한다. Linux는 private namespace·Landlock·seccomp, macOS는 Seatbelt를 사용한다. 언어별 실행기나 환경 주입 없이 실제 HOME·PATH와 기존 설정을 전달한다. 프로젝트·V 임시 공간·[execution].writable_paths 밖의 쓰기와 보호한 비밀 경로 접근을 차단한다.

rm 등 삭제 명령은 일반 셸로 실행한다. 알려진 파일의 실제 실행 전후 버전을 비교해 삭제·변경을 기록하며, 반복된 부재를 새 변경으로 세지 않는다. 실행 중 외부 경로에서 거절되어도 앞선 부분 효과는 보존한다. 일반 셸의 모든 대상 diff나 전체 트리 관측을 제공한다고 해석하지 않는다.

다운로드·DNS·로컬 HTTP에는 호스트 네트워크를 사용하며 제어 소켓은 별도 제한한다. 격리 준비 실패는 scope_unavailable로 반환하고 호스트 실행으로 재시도하지 않는다. [플랫폼 검증](development.md#플랫폼-실행-검증)은 빌드·모의 검사와 네이티브 실행을 구분한다.
