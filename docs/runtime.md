# 에이전트 작동 방식

[← README](../README.md) · [설정](configuration.md) · [사용 가이드](usage.md)

## 실행 흐름

메인 에이전트 하나가 `사용자 입력 → 문맥 → 모델 응답 → 도구 실행 → 결과 → 다음 응답 또는 종료`를 수행한다. system.md·development.md와 선택적인 프로젝트 AGENTS.md를 한 요청의 지침으로 준비한다. 모델의 정상적인 도구 없는 응답을 그대로 최종 답변으로 저장한다. 모델은 작업 완료 또는 진행 불가 사유를 이 응답으로 설명한다. 도구 호출 수는 기록하되 별도 횟수 상한으로 실행을 중단하지 않는다. 모델 요청·시간 예산과 사용자 중지는 별도로 유지한다.

native 인자를 검증한 뒤 접근 정책·원본·Permission 승인·실행 직전 버전을 확인한다. 결과·명령·종료 코드·파일 변경을 호출 ID에 연결한다. 실패 결과는 실제 원인과 함께 모델에 돌아간다. 취소된 부작용은 자동 재실행하지 않는다.

시스템·개발 프롬프트는 작업 원칙과 결과 보고만 다루고, 도구 설명은 실행 방법·필수 입력·반환 결과·실제 제약을 설명한다. 실행 단계·예산·저장 구조 설명이나 임의의 추가 질문을 모델 지침으로 주입하지 않는다. 실제 실패 원인과 중단 관측은 작업 이력으로 보존한다.

## Native 도구

Chat Completions·Ollama는 tool_calls, Responses는 function_call을 사용한다. 매 요청에 고정 도구 설명과 JSON Schema를 전달하며 assistant 본문의 JSON은 일반 텍스트다. 인자는 실제 실행 값만 받는다. 잘못된 native 인자가 포함된 배치는 실행 전에 전체 거절한다.

| 도구 | 실행 계약 |
| --- | --- |
| execute_command | POSIX 셸 명령. 조회·검색·빌드·테스트·패키지 관리·생성·변경·이동·삭제 |
| create_directory | 복수 경로와 누락된 부모 생성. 기존 디렉터리 허용 |
| write_file | UTF-8 본문 생성·전체 교체. 누락된 부모 생성 |
| edit_file | 같은 원본에 대한 유일한 1~64개 정확한 부분 수정. 겹침 거절 |
| move_file | 파일·디렉터리를 존재하지 않는 대상으로 이동 |

소스 변경에는 diff와 원본 검사를 제공하는 파일 도구를 권장한다. 셸도 같은 OS 경계를 사용하며 명령별 도구 전환 파서는 두지 않는다. 파일 조회는 cat·sed·nl·rg·find·ls 등을 사용한다. cwd 변경은 그 셸 호출에만 적용된다.

edit_file은 모든 old_text가 같은 원본에서 한 곳에 일치해야 한다. format_policy=preserve는 기존 LF/CRLF·EOF를 보존하며 literal은 의도한 바이트 변경에 사용한다. 파일 승인은 정규화한 후보·대상·원본 버전에 연결한다.

## 실행·승인·관측

Permission은 approve 또는 기본 allow-all이다. allow-all은 승인 질문만 생략한다. 셸 승인은 실제 명령·작업 루트·추가 쓰기 경계에 연결하며 일반 셸의 전체 사전 diff는 제공하지 않는다.

독립 파일 작업은 최대 네 개씩 병렬로 실행한다. 준비·승인·충돌 검사·결과 저장은 요청 소유자가 조율한다. 같은 경로·상하위·inode 별칭과 명령은 직렬이다. 취소 시 모든 worker를 합류하고 결과는 원래 순서로 기록한다.

명시적인 재호출은 새 작업이다. 동일 명령 재확인·의도적인 수정 되돌리기를 자동 차단하거나, 성공한 과거 도구 결과로 대신 실행하지 않는다. 전송 재시도는 모델 요청만 재시도한다. 불확실한 부분 효과는 모델이 원본 결과와 현재 파일을 확인해 판단한다.

파일 관측은 실행 당시 사실이다. 셸 실행 후 이전 파일 관측을 오래된 상태로 표시하며 다음 결정마다 전체 알려진 파일을 재해시하지 않는다. 수정 직전 원본 검사는 유지한다. 정상 응답은 answered, 예산·오류 중단은 stopped, 사용자 취소는 interrupted다. answered는 프로그램 정확성 인증이 아니다.

## 출력과 저장

도구 결과 원문·실행 이벤트는 세션에 보존한다. 체크포인트는 작은 재개 상태와 파일 관측을 저장하며 과거 출력·명령 이력 사본을 누적하지 않는다.

명령 stdout·stderr는 각각 16MiB의 앞뒤 수집 한도를 가지며 초과 시 생략을 표시한다. 큰 정제된 수집 원본은 이벤트의 capture에 한 번 저장한다. 모델에는 스트림별 32KiB 앞뒤 발췌와 현재 세션에서 cat·sed로 읽을 로그 경로를 전달한다. 로그는 Executor 종료 시 제거하며 원본 수집 기록은 DB·export에 남는다. 재조회도 OS 파일 보호와 승인 정책을 따른다.

TUI는 짧은 출력을 그대로 표시하고 큰 명령 출력을 접는다. Ctrl+O로 큰 출력을 펼친다. Thinking 표시는 유지한다. 원본 capture는 TUI와 압축의 일반 조회에서 제외한다.

## 문맥·압축·재개

압축 전 실제 대화와 native 호출·결과 쌍을 순서대로 전달한다. 원문에 있는 최신 요청을 중복 삽입하지 않는다. 중단·압축으로 짝이 없는 기록은 인용 관측으로 전달한다. 최신 요청이 최근 원문에서 빠졌으면 각 모델 문맥의 요약 뒤에 요청 원문을 한 번 넣는다. 저장 이력에 복제하지 않는다.

압축은 현재 문맥과 여유 토큰으로 판단하고 이전 메모·최신 요청·필요한 실제 결과를 한 번 요약한다. 최근 원문과 호출·결과 묶음을 보존한다. 원본 기록은 DB에 유지한다. [설정](configuration.md#프롬프트와-compaction)이 발동·선택·수용 한도를 소유한다.

Enter로 전달한 방향 수정은 실행 중인 응답·도구를 마친 안전한 경계에서 다음 판단에 반영한다. Tab 후속 요청은 현재 요청이 끝난 뒤 별도로 실행한다. 미전달 입력은 중지·실패·종료 시 초안으로 복구한다. Esc는 현재 작업을 취소한다.

## 비대화형 실행

--print는 최종 답변, --mode json은 JSONL 이벤트를 출력한다. 첫 JSON session 이벤트는 session_id와 프로젝트 경로를 제공한다. 동일한 agent/session 요청 경로와 도구·저장을 사용한다. --session ID는 현재 프로젝트 세션을 선택하고 --export는 원본 이력을 시간순 JSONL로 내보낸다. stdout은 선택한 형식만 사용하며 실패는 비정상 종료 코드로 알린다. 비대화형 approve 요청은 실행을 차단한다.

## 플랫폼 실행 경계

모든 셸은 [공통 파일 경계](execution-boundary.md)를 적용한다. Linux는 namespace·Landlock·seccomp, macOS는 Seatbelt를 사용한다. 실제 HOME·PATH·개발 설정을 전달하고 프로젝트·명시한 추가 경로 밖의 쓰기와 보호 경로 접근을 차단한다. 호스트 네트워크를 사용하고 제어 소켓을 제한한다. 격리 준비 실패는 scope_unavailable이며 무격리 실행으로 재시도하지 않는다.
