# 에이전트 작동 방식

[문서 목록](README.md) · [제품 명세](../SYSTEM.md) · [실행 경계](execution-boundary.md)

TUI·CLI·서버·WebUI는 같은 모델 요청·도구·승인·저장 흐름을 사용한다. 화면과 전송 방식은 요청 실행의 소유권을 바꾸지 않는다.

## 실행 흐름

1. 사용자 요청, 프로젝트 위치와 지침, 스킬, 저장된 대화를 준비한다.
2. 모델의 답변·Thinking을 스트리밍하고 native 도구 호출을 수집한다.
3. 완성된 호출을 검사하고 필요한 승인을 받는다.
4. 실행 결과와 상태를 저장한 뒤 모델 판단을 이어간다.
5. 남은 실행을 정리하고 최종 답변·사용량·중단 사유를 전달한다.

실제 관측과 모델의 설명은 구분한다. 답변이 끝났다는 사실만으로 테스트 통과나 구현 정확성을 보장하지 않는다.

## 모델 요청 준비

설정한 Provider·모델과 현재 대화를 사용한다. 프로젝트 지침·스킬은 요청에 적용되는 범위로 읽고 원문 이력과 출처를 유지한다. 팀 참여자는 독립 문맥을 가지며 공용 대화만 공유한다.

인코딩·문맥 재사용은 요청 실행이 소유하고 모델·내용 변경에서 무효화한다. 재사용 때문에 필요한 메시지나 도구 결과를 전송에서 누락하지 않는다. 설정과 지원 기능은 [모델 연결](model-connections.md)을 따른다.

## Native 도구

도구는 모델의 native function calling으로만 실행한다. 일반 텍스트를 셸이나 JSON 명령으로 추측하지 않으며, 끊긴 스트림의 미완성 호출은 실행하지 않는다.

| 도구 | 목적 |
| --- | --- |
| `execute_command` | 호스트 셸 명령 실행 |
| `list_command_runs`, `wait_command`, `cancel_command` | 장기 명령의 조회·대기·취소 |
| `create_directory`, `write_file`, `edit_file` | 승인과 원본 검사를 거친 파일 변경 |
| `view_image` | 비전 지원 모델에 이미지 스냅샷 전달 |
| `list_skills`, `load_skill`, `read_skill_file` | 스킬 목록·지침·참고 자료 읽기 |

조회·검색·패키지 작업은 호스트 도구를 사용한다. 파일 변경은 현재 대상과 승인한 내용을 다시 확인하고, 호출·결과의 연결을 보존한다. 팀 전용 도구는 [팀 모드](team.md#대화와-도구), 이미지 형식과 조건은 [이미지 입력](images.md)을 따른다.

## 오래 실행되는 명령

`execute_command`는 관측 창 안에 끝나지 않은 명령에 내부 `command_id`와 현재 상태·출력을 반환한다. 이는 프로세스 종료나 실패를 뜻하지 않는다. 모델은 관리 도구로 추가 대기·결과 수집·취소를 수행하며 시스템 PID를 직접 지정하지 않는다.

대기 시간 만료는 명령 취소와 다르다. 최종 답변 전에 활성 명령과 미수집 결과를 확인한다. 사용자 취소·실패·종료 시 소유한 프로세스와 출력을 정리하고 확인한 부분 효과를 보존한다. 분리된 daemon까지 관리하는 OS 격리 기능은 아니다.

## 실행·승인·관측

독립 작업은 병렬로 수행할 수 있지만 같은 대상의 변경과 공유 자원은 실행 경계에서 조율한다. 승인 전에 준비한 후보가 실행 시점에도 유효한지 확인한다. 셸 프로그램 내부의 모든 파일 효과를 추정하지 않는다.

새 사용자 지시는 안전한 판단 경계에서 반영하고 아직 실행하지 않은 후보를 다시 검토한다. 이미 시작한 효과는 결과를 수집한 뒤 다음 판단에 사용한다. 승인 요청·허용 범위는 [호스트 실행과 승인](execution-boundary.md)을 따른다.

전송 재시도는 모델 요청에 적용하며 이미 실행한 도구를 자동 재생하지 않는다. 연결 실패와 모델·입력 오류의 처리 범위는 [Provider 복구](usage.md#provider-스트림과-복구)를 따른다.

## 출력과 저장

답변·Thinking·도구 결과·사용량은 세션 기록에 보존한다. 관련 실행 결과와 체크포인트를 일관되게 확정하고, 저장 실패를 정상 완료로 표시하지 않는다.

화면용 이력·원문 조회·모델 문맥은 서로 다른 투영이다. 완료 통계에는 상태와 검증한 숫자만 전달하고 답변·팀 발언·자유 형식 오류 본문을 섞지 않는다. [사용량 표시](usage.md#화면과-사용량)와 [이벤트 계약](diagnostics.md)을 따른다.

## 문맥·압축·재개

대화 압축은 다음 판단에 필요한 문맥을 정리하며 원본 DB를 삭제하지 않는다. 최신 요청·실제 도구 결과·호출 관계를 유지하고 실패·취소한 부분과 완료한 결과를 구분한다. 발동 조건과 설정은 [Compaction](configuration.md#프롬프트와-compaction)을 따른다.

저장 대화를 재개하면 해당 프로젝트·선택·기록을 복원한다. 중단된 프로세스에 임의로 재연결하거나 불확실한 파일 효과를 다시 실행하지 않는다. 후속 예약은 화면 수명의 별도 요청이며 중지·실패 때 처리는 [사용 가이드](usage.md#중지와-후속-요청)를 따른다.

## 비대화형 실행

`--print`는 최종 답변, `--mode json`은 순서 있는 이벤트, `--export`는 저장 원문을 제공한다. 같은 실행·저장 정책을 사용하지만 대화형 승인을 받을 수 없는 작업은 해당 정책에 따라 중단한다. [CLI 사용](usage.md#큰-출력과-자동화)을 따른다.

## 서버 실행

서버는 접수한 작업을 관찰 연결과 독립적으로 실행한다. 접수 키·작업 ID·저장 상태로 중복과 불확실한 결과를 구분한다. 구독 종료는 작업 취소가 아니며 재접속이 작업 재제출로 이어지지 않는다. [서버 API](server.md)를 따른다.

## 플랫폼 실행 경계

명령·파일 접근은 호스트 사용자 권한과 환경을 사용한다. OS·클립보드·터미널별 동작은 해당 어댑터가 담당하며 교차 빌드 성공과 실제 실행 지원 검증은 구분한다. [플랫폼 검증](development.md#플랫폼-실행-검증)을 따른다.
