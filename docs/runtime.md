# 에이전트 작동 방식

[← README](../README.md) · [설정](configuration.md) · [사용 가이드](usage.md)

## 실행 흐름

메인 에이전트 하나가 `사용자 입력 → 문맥 → 모델 응답 → 도구 실행 → 결과 → 다음 응답 또는 종료`를 수행한다. system.md·development.md와 선택적인 프로젝트 AGENTS.md를 한 요청의 지침으로 준비한다. 시작한 명령의 종료·취소 결과를 확인한 뒤 모델의 정상적인 도구 없는 응답을 최종 답변으로 저장한다. 모델은 작업 완료 또는 진행 불가 사유를 이 응답으로 설명한다. 도구 호출 수는 기록하되 별도 횟수 상한으로 실행을 중단하지 않는다. 모델 요청·시간 예산과 사용자 중지는 별도로 유지한다.

TUI와 비대화형 실행은 공통 요청 생성 함수를 사용한다. 선택된 세션이 프로젝트 경로를 소유하며 모델·Thinking·추론 강도·역할별 추론 설정·실행 예산·유효 문맥 크기·압축 설정을 같은 규칙으로 전달한다.

native 인자를 검증한 뒤 접근 정책·원본·필수 사용자 승인·실행 직전 버전을 확인한다. 결과·명령·종료 코드·파일 변경을 호출 ID에 연결한다. 실패 결과는 실제 원인과 함께 모델에 돌아간다. 취소된 부작용은 자동 재실행하지 않는다.

시스템·개발 프롬프트는 작업 원칙과 결과 보고만 다루고, 도구 설명은 실행 방법·필수 입력·반환 결과·실제 제약을 설명한다. 현재 세션의 정규화한 프로젝트 디렉터리(project_root)는 압축·재개와 관계없이 매 요청의 시스템 문맥에 제공한다. 파일 검색은 그 디렉터리에서 시작하고 요청한 경로나 관측한 의존성에 필요한 경우 외부로 넓힌다. 실행 단계·예산·저장 구조 설명이나 임의의 추가 질문을 모델 지침으로 주입하지 않는다. 실제 실패 원인과 중단 관측은 작업 이력으로 보존한다.

## 모델 요청 준비

한 사용자 요청의 실행은 전용 Provider 인코더를 소유한다. 큰 텍스트 대화에서는 native 이력을 Provider 형식으로 변환하기 전에 불변 텍스트와 인자·추론 상태의 내용 해시를 비교한다. 변경되지 않은 메시지의 JSON 조각을 재사용하고 바뀐 위치부터 다시 구성한다. 추론 설정·도구 정의·서버 한도는 매번 반영하며 전체 미압축 대화와 압축 메모의 전달 규칙은 유지한다. 이는 로컬 요청 준비 비용을 줄이는 기능이며 입력 토큰이나 네트워크 전송량을 줄이지 않는다.

모델·Provider 변경과 이력 축소는 캐시를 해제하고 메시지 내용 변경은 해당 위치 이후를 다시 구성한다. Compaction의 요약 입력과 요약 후 대화도 실제 메시지로 비교한다. 이미지·native 결과 그룹도 순서를 유지하며 최종 인코딩을 재사용한다. 소유권을 인수한 native 바이트의 지문은 한 번 계산하고 값 교체 시 무효화하며, 일반 가변 입력은 내용 해시를 유지한다. 작은 대화·보유 예산을 넘는 이력은 캐시를 유지하지 않고 동일한 Provider 형식으로 전송한다. 캐시는 영속 저장하지 않으며 완료·오류·사용자 취소 시 생성 worker가 끝난 뒤 해제한다. 수용 한도와 캐시 예산은 [개발 가이드](development.md#성능과-장시간-수명)를 따른다.

HTTP 본문은 정확한 길이와 독립된 읽기 커서를 제공한다. 전송 재시도와 리다이렉트는 같은 불변 본문을 처음부터 읽으며 이미 실행한 도구를 재실행하지 않는다. vLLM의 정확한 토큰 수 사전 검사는 메시지 JSON 조각을 재사용하는 별도 요청으로 수행한다. 실제 usage가 없으면 전송 본문 바이트 수를 압축 판단에 사용하고, 그 값도 없으면 이미지 본문을 제외한 텍스트 크기를 근사한다. 이 계산을 위해 전체 요청을 다시 직렬화하지 않으며 화면 토큰·비용은 실제 수신값만 표시한다.

## Native 도구

Chat Completions·Ollama는 tool_calls, Responses는 function_call을 사용한다. 매 요청에 고정 도구 설명과 JSON Schema를 전달하며 assistant 본문의 JSON은 일반 텍스트다. 인자는 실제 실행 값만 받는다. 잘못된 native 인자가 포함된 배치는 실행 전에 전체 거절한다.

| 도구 | 실행 계약 |
| --- | --- |
| execute_command | POSIX 셸 명령. 조회·검색·빌드·테스트·패키지 관리·생성·변경·이동·삭제 |
| list_command_runs | 현재 세션에서 시작한 활성 명령과 아직 수집하지 않은 종료 결과의 메타데이터 조회 |
| wait_command | command_id의 완료를 최대 wait_seconds만큼 대기. 기본 180초, 0은 즉시 조회, 범위 0~86400초 |
| cancel_command | command_id의 명령과 일반 자식 프로세스 그룹을 종료하고 실제 상태·부분 출력 반환 |
| read_image | 이미지 입력이 확인된 모델에 제공. 경로 하나로 읽기 전용 이미지 스냅샷 전달. [형식·검사·저장](images.md) |
| create_directory | 복수 경로와 누락된 부모 생성. 이미 존재하는 디렉터리는 변경 없이 성공 처리 |
| write_file | UTF-8 본문 생성·전체 교체. 누락된 부모 생성 |
| edit_file | 같은 원본에 대한 유일한 1~64개 정확한 부분 수정. 겹침 거절 |

소스 생성·본문 수정에는 diff와 원본 검사를 제공하는 파일 도구를 권장한다. 파일·디렉터리 이동은 execute_command에서 mv를 사용한다. 셸은 호스트 사용자 권한과 선택한 승인 정책을 사용하며 셸 명령의 효과는 실행 경계의 공통 정책으로 검사한다. 파일 조회는 cat·sed·nl·rg·find·ls 등을 사용한다. cwd 변경은 그 셸 호출에만 적용된다.

edit_file은 모든 old_text가 같은 원본에서 한 곳에 일치해야 한다. format_policy=preserve는 원본 LF/CRLF·EOF를 보존하며 literal은 의도한 바이트 변경에 사용한다. 파일 승인은 정규화한 후보·대상·원본 버전에 연결한다.

## 오래 실행되는 명령

execute_command는 기본 30초까지 완료를 기다린다. 먼저 끝나면 즉시 종료 결과를 반환하고, 대기 창이 끝나면 running과 내부 command_id·현재 출력 발췌를 반환한다. 모델이 받는 결과의 next 필드에는 같은 ID로 wait_command를 호출해 추가 대기·출력 조회, cancel_command로 중지, list_command_runs로 세션 명령 목록·ID 조회가 가능하다고 안내한다. 상태 확인을 위해 같은 명령을 재실행하지 않도록 설명하며 이 안내는 TUI 원문 출력에 노출하지 않는다. running은 성공·실패 판정이 아니며 종료 코드를 제공하지 않는다. wait_command의 기본 대기는 180초이고 대기 만료만으로 명령을 종료하거나 전체 실행 예산을 갱신하지 않는다. 목록·대기·취소는 이 실행기가 시작한 명령만 다루고 OS PID를 인자로 받지 않는다.

프로세스마다 Wait는 한 번만 수행하고 여러 조회는 완료 신호를 기다린다. 같은 모델 응답에서 묶인 독립 명령은 최대 4개까지 시작한다. 별도 예약 큐는 없으며 활성 수용량이 찼으면 현재 명령을 기다리거나 취소하도록 결과를 반환한다. 셸 명령은 임의의 부작용이 있으므로 독립성은 모델이 선행 조건·공유 환경·변경 대상을 확인해 판단한다. 명령이 활성 상태인 동안 전용 파일 도구의 변경은 대기하도록 거절한다. 명령 제어 도구는 파일 작업과 섞어 병렬 실행하지 않는다.

진행 중인 도구는 호출 ID별로 표시한다. TUI의 1초 타이머가 명령별 경과 시간·마지막 출력 시점을 갱신하며 다른 도구·안내 문구를 덮어쓰지 않는다. 경과 시간은 실행 시작 기준이고 마지막 출력은 실제 stdout·stderr 중 가장 최근 수신 기준이다. 출력이 없으면 마지막 출력 값은 null이며 화면에는 아직 출력 없음으로 표시한다. 긴 명령은 실행 중에도 전체를 줄바꿈해 표시한다. 별도 모델 호출이나 초 단위 저장 기록은 추가하지 않는다. 명령이 끝나면 출력 버퍼를 해제하고 정제한 결과를 실행기 소유 파일에 보관한다. 런타임은 다음 판단 경계와 명령이 남은 모델 요청 중에 완료 결과를 수집해 세션 DB에 확정한다. 결과를 수집한 활성 핸들은 제거하고 같은 실행기 수명 동안은 저장된 결과로 재조회할 수 있다.

모델이 최종 답변을 내더라도 미완료 명령이나 새로 도착한 결과가 있으면 그 상태를 다음 판단에 전달한다. 명령의 종료·취소 결과를 확인한 뒤 답변을 확정한다. 이는 프로세스 수명 처리이며 테스트 통과나 기능 완성을 별도로 평가하지 않는다. Esc·요청 실패·세션 변경·앱 종료는 남은 명령을 취소하고 Wait를 합류한 뒤 부분 결과를 저장한다. 재시작 후 저장된 DB의 PID에 재연결하거나 부작용을 자동 재실행하지 않는다.

## 실행·승인·관측

승인 모드는 전역 설정의 기본과 All Mighty다. 기본은 승인 대상 작업을 사용자에게 확인하고 All Mighty는 외부 전송 외 승인 대상을 자동 승인한다. 외부 전송은 모든 모드에서 매 호출 직접 승인받는다. TUI·비대화형 실행은 요청 시작 시 같은 정책 스냅샷을 사용한다. 아래 승인 필요 조건은 기본 모드를 기준으로 하며 보호 경로·인자·원본 검사는 두 모드 모두 유지한다. 현재 프로젝트의 확정된 하위 파일·폴더에 대한 일반 삭제와 내부 경로 간 이동은 자동 승인한다. 파괴적·원격 Git 작업은 내부 경로에서도 별도 승인을 요구한다. 외부·미확정 대상의 삭제·이동, 그 밖의 위험 작업 승인과 보호 경로 차단은 [실행 경계](execution-boundary.md)를 따른다. 셸 승인은 실제 전체 명령·작업 디렉터리·검토 단계별 명령과 대상에 연결하며 일반 셸의 전체 사전 diff는 제공하지 않는다. &&·파이프·중첩 실행을 구조로 구분하고 단일 검사 목록의 명령만 인자를 정밀 검사한다. 목록 밖 명령은 같은 기본 허용 규칙을 적용한다. 잘못된 셸 구문과 보호 대상 차단은 각각 invalid_command·command_blocked로 반환한다.

AST 판정의 `UserRequired`는 준비한 승인과 실행 직전 재검사에 보존한다. 이 표식이 있으면 런타임은 승인 모드와 관계없이 실제 사용자 응답을 기다린다. 승인·거절은 `user`, 일반 자동 승인은 `all_mighty` 출처로 저장한다. 거절하거나 승인을 받을 수 없으면 native 도구 결과를 기록하고 실행을 중단한다. 승인 불가는 저장 실패와 구분하며 같은 작업을 자동으로 다시 시도하지 않는다.

독립 파일 작업은 최대 16개씩 병렬로 실행하고 셸 명령 묶음은 최대 4개다. 이미지 읽기는 디코딩 메모리를 제한하도록 한 번에 한 개씩 실행하며 파일 변경으로 집계하지 않는다. 원본·인자 크기로 추정한 64MiB 준비 예산에 따라 더 작은 묶음으로 실행하며, 이 예산을 넘는 단일 호출도 거절하지 않는다. 경로·inode 정보는 파일 묶음 계획당 한 번 수집하고 승인 후 다시 확인한다. 준비·승인·충돌 검사·결과 저장은 요청 소유자가 조율한다. 같은 경로·상하위·inode 별칭의 파일 작업과 명령 제어 호출은 직렬이다. 호출 순서상 앞에서부터 결과가 준비된 구간은 나머지 작업 전체의 종료를 기다리지 않고 저장한 뒤 화면에 전달한다. 뒤의 결과가 먼저 끝났으면 앞선 호출의 결과를 기다려 원래 순서를 유지한다. 취소·저장 실패 시에도 모든 worker를 합류한다.

명시적인 재호출은 새 작업이다. 동일 명령 재확인·의도적인 수정 되돌리기를 자동 차단하거나, 성공한 과거 도구 결과로 대신 실행하지 않는다. 전송 재시도는 모델 요청만 재시도한다. 일시적 연결 오류와 HTTP 408·425·429·5xx는 최대 3회 시도한다. 인증·인자 오류는 같은 요청으로 반복하지 않는다. 명시적인 컨텍스트 초과는 압축 후 재요청하고 잘못된 도구 호출·출력 한도는 메인 루프에서 피드백으로 처리한다. 불확실한 부분 효과는 모델이 원본 결과와 현재 파일을 확인해 판단한다.

파일 관측은 실행 당시 사실이다. 셸 실행 후 이전 파일 관측을 오래된 상태로 표시하며 다음 결정마다 전체 알려진 파일을 재해시하지 않는다. 수정 직전 원본 검사는 유지한다. 정상 응답은 answered, 예산·오류 중단은 stopped, 사용자 취소는 interrupted다. answered는 프로그램 정확성 인증이 아니다.

## 출력과 저장

도구 결과 원문·실행 이벤트는 세션에 보존한다. 실행 결과·native 도구 응답·최신 체크포인트 갱신은 한 트랜잭션으로 저장한 뒤 화면에 전달한다. 중단 복구의 도구 응답과 중단 이벤트도 함께 저장하며 반복 복구로 중복 기록하지 않는다. 임의의 셸 부작용을 DB 트랜잭션과 원자화하거나 자동 재실행하지 않는다. 체크포인트는 실행별 최신 상태 한 건과 종료 이벤트로 보관하고 과거 인자·출력·명령 이력 사본을 누적하지 않는다. 화면은 표시할 사건·필드를 먼저 선택하고 페이지 바이트 예산을 확인한 뒤 필요한 payload만 복원한다. 모델 문맥과 원본 내보내기는 별도 투영을 사용한다.

종료 체크포인트 이벤트에는 해당 요청의 총 시간·실측 토큰 합계·선택적인 OpenRouter 보고 비용 합계·사용량을 수신한 호출들의 측정 시간 합계를 저장한다. 재시도·대화 압축·활성 LAT 검토·LAT 메모 압축을 포함하고 세션 누계와 분리하며, 원래 usage 이벤트를 복제하거나 다시 집계하지 않는다. TUI는 이 값을 마지막 응답 아래의 흐린 가운데 요약으로 투영하고, 상단 세션 사용량은 확정된 usage 이벤트에서 복원한다. 모델 문맥·압축은 이 표시용 통계를 사용하지 않는다. 계산·표시 기준은 [사용 가이드](usage.md#화면과-사용량)를 따른다.

실행 중 명령의 상태 조회는 출력 본문을 복사하지 않는다. 출력 내용이 바뀐 스트림만 복사·마스킹해 발췌와 로그를 갱신하며, 결과 수집과 요청·실행기 종료에서 해당 표시 캐시를 해제한다.

명령 stdout·stderr는 스트림별로 앞·뒤 각각 8MiB, 총 16MiB를 수집하며 초과 시 생략을 표시한다. 1MiB를 넘는 활성 출력은 실행기가 소유한 제한 크기의 임시 파일로 옮기며, 메모리에만 보유하는 임시 키와 AES-GCM 블록 인증으로 원문을 보호한다. 명령 실행·Wait는 병렬로 유지하고 최종 출력 구체화·마스킹·보관만 하나씩 처리한다. 완료된 병렬 결과는 작은 발췌로 대기하며 전체 capture는 호출 순서상 저장할 차례에 한 건씩 읽는다. DB 커밋 후 capture·핸들을 해제하고 재조회용 정제 로그는 실행기 종료까지 유지한다. 캡처 파일의 읽기·쓰기·무결성 실패는 명시적인 오류로 반환한다. 디스크 I/O 비용이 있으므로 작은 출력은 메모리 경로를 사용한다.

정제한 수집 원본은 이벤트의 capture에 한 번 저장한다. 모델에는 스트림별 32KiB 앞뒤 발췌와 현재 세션에서 cat·sed로 읽을 로그 경로를 전달한다. 로그는 Executor 종료 시 제거하며 원본 수집 기록은 DB·export에 남는다. 재조회도 호스트 사용자 권한과 승인 정책을 따른다.

모든 완료된 도구 결과는 기본으로 펼쳐 보인다. Ctrl+O는 명령·파일 생성·수정·폴더 생성 결과 전체를 접거나 펼친다. 접힌 결과에는 도구 이름·대상·실행 상태 또는 변경 요약과 펼치기 안내를 남긴다. 명령 상태는 펼침·접기 모두 UI 언어에 맞는 실행 성공·실패·중단·시간 초과로 표시하고 숫자 종료 코드는 생략한다. 실제 stdout·stderr와 실행 오류 원인은 유지하며 같은 상태를 반복하는 내부 요약은 생략한다. 종료 코드는 모델 전달 결과·원본 DB·export에 그대로 보존한다. 전환 상태는 입력창 위에 표시한다. 도구 결과가 있을 때 하단 키맵 안내를 제공하며 일반 키 보고와 확장 키 보고의 Ctrl 문자 키 표현을 통일한다. 접을 때 읽던 도구 블록을 유지하고 새 결과와 이전 이력에도 현재 접기 상태를 적용한다. Thinking·사용자 입력·에이전트 응답은 접지 않는다. 표시용 스트림은 현재 생성의 최신 미소비 스냅샷 하나를 유지한다. 재시도·도구 결과·승인·완료·사용량은 순서를 지키며 병합하지 않는다. 최종 응답·Thinking 원문 기록은 유지한다. 원본 capture는 TUI와 압축의 일반 조회에서 제외한다.

## 문맥·압축·재개

압축 전 실제 대화와 native 호출·결과 쌍을 순서대로 전달한다. 원문에 있는 최신 요청을 중복 삽입하지 않는다. 중단·압축으로 짝이 없는 기록은 인용 관측으로 전달한다. 최신 요청이 최근 원문에서 빠졌으면 각 모델 문맥의 요약 뒤에 요청 원문을 한 번 넣는다. 저장 이력에 복제하지 않는다.

중단·실패한 Thinking 원문은 화면·DB에만 보존하고 재개·압축 입력에는 넣지 않는다. 부분 답변은 인용된 미완성 초안으로 구분하며 실행 사실이나 완료 증거로 사용하지 않는다. 사용자 요청·실제 도구 결과·최신 지시를 이어받고 정상 완료된 응답의 reasoning과 native 호출·결과 연결은 유지한다.

압축은 현재 문맥과 여유 토큰으로 판단하고 이전 메모·최신 요청·필요한 실제 결과를 한 번 요약한다. 최근 원문과 호출·결과 묶음을 보존한다. 원본 기록은 DB에 유지한다. [설정](configuration.md#프롬프트와-compaction)이 발동·선택·수용 한도를 소유한다.

Enter로 전달한 방향 수정은 실행 중인 응답·도구를 마친 안전한 경계에서 다음 판단에 반영한다. Compaction 완료 직후에도 대기열을 다시 읽어 압축 중 받은 지시를 첫 후속 모델 요청에 포함한다. 기본 시스템·개발·프로젝트 지침은 매 메인 모델 요청에 함께 제공하고, 압축에는 사용자 요청과 작업 기록을 전달한다. Tab 후속 요청은 본문과 예약 당시 선택 경로를 함께 보관하고 현재 요청이 끝난 뒤 별도로 실행한다. 예약 본문 편집은 캡처한 경로를 바꾸지 않는다. 선택 경로 검증은 요청 worker가 수행하며, 중지·실패 후 초안 복구에도 해당 경로를 보존한다. 미전달 입력은 중지·실패·종료 시 초안으로 복구한다. Esc는 현재 작업을 취소한다.

## 비대화형 실행

--print는 최종 답변, --mode json은 JSONL 이벤트를 출력한다. 첫 JSON session 이벤트는 session_id와 프로젝트 경로를 제공한다. 동일한 agent/session 요청 경로와 도구·저장을 사용한다. --session ID는 현재 프로젝트 세션을 선택하고 --export는 원본 이력을 시간순 JSONL로 내보낸다. stdout은 선택한 형식만 사용하며 실패는 비정상 종료 코드로 알린다. 비대화형 기본 모드는 필수 승인 요청을 중단하고 All Mighty는 외부 전송 외 승인 대상을 자동 승인한다. 외부 전송은 직접 승인을 받을 수 없어 모든 모드에서 실행하지 않는다.

## 플랫폼 실행 경계

모든 셸과 자식 프로그램은 [호스트 실행과 승인 경계](execution-boundary.md)를 따른다. /bin/sh를 현재 프로젝트 디렉터리에서 시작하고 실제 HOME·PATH·DNS·캐시·개발 설정을 사용한다. 파일시스템·네트워크를 별도로 격리하지 않으며 승인된 프로그램은 프로젝트 밖의 사용자 파일에도 접근할 수 있다. 실행기 준비 실패와 실제 명령의 종료·오류·취소를 구분한다.

## 선택적 LAT 검토

!lat를 켠 요청은 활성 명령을 수집한 뒤 첫 최종 응답 초안에 한 번 독립 검토를 적용한다. agent/lat는 검토 문맥·응답, agent/lat/memory는 독립 메모·원본 선택·요약 worker 한 개를 소유한다. agent/run은 전체 예산·실측 통계·취소·피드백 기록을 조율한다. OFF와 도구 없는 대화는 추가 모델 호출·자료 조회를 하지 않는다.

독립 메모의 근거는 세션 DB의 원본 사용자 지시와 실제 실행 결과다. 메인 요약·assistant 답변·Thinking·이전 검토 결론을 자료에 넣지 않는다. SQLite는 남은 입력 예산에 맞춰 실제 결과를 선택한다. 큰 출력·diff는 전체 길이·해시를 검사하면서 필요한 발췌만 메모리에 남기며 숨은 native 인자·원본 capture·이미지를 복원하지 않는다. 과거 요구를 최근 몇 개로 제한하지 않고 메모의 처리 경계 이후를 시간순으로 읽는다. 전송과 저장 전에 현재 비밀정보 마스킹을 적용한다.

실제 원본이 바뀌었을 때 크기를 조회하고 자료가 32KiB 또는 모델별 요약 입력 예산의 절반에 도달하면 다음 도구 실행 구간에서 lat_compaction.md와 이전 LAT 메모·새 원본 prefix를 한 번 요약한다. 전경 생성 중에는 새 요약을 시작하지 않으며 최종 검토 자료가 부족하면 별도로 압축한다. 실행 슬롯은 하나이며 추가 기록은 같은 원본 DB를 대기열로 삼아 최신 경계로 합친다. 입력은 모델 문맥·출력·지침·이전 메모를 먼저 예약하고 16MiB 수용 상한 안에서 선택한다. 형식·목표 분량은 작성 지침이며 별도 합격·불합격 검사로 사용하지 않는다. 실패·취소·게시 충돌에는 이전 메모와 원본을 보존한다. lat_memory는 세션별 최신 메모 한 건·revision·처리 경계·무결성 정보만 저장하며 큰 값은 기존 Codec을 사용한다.

최종 검토는 현재 요청 원문·프로젝트 지침·독립 LAT 메모·이후 원본 증분·답변 초안을 받는다. 완전한 증분이 입력에 들어가면 진행 중인 압축을 취소·합류하고 원문으로 검토한다. 공간이 부족하면 동일 작업을 기다리며 최신 지시·취소를 확인한다. 현재 요청과 미압축 지시를 조용히 잘라내지 않는다. 수용할 수 없으면 검토 불가로 기록한다. 현재 요청을 보존하는 일반 검토 자료 목표는 64KiB이며 필요하면 유효 모델 문맥 안에서 확장한다.

메모 압축은 lat_compaction, 검토는 lat 역할로 실제 사용량과 재시도를 기록한다. 메인·백그라운드의 진행 usage는 별도 슬롯으로 표시해 덮어쓰지 않으며 최종 수신값을 한 번 합산한다. 백그라운드는 전경 호출 한 건을 남겨 공유 모델 예산을 예약한다. 요약 호출도 같은 서버 자원을 사용하므로 추가 시간·토큰·경합 비용이 있다. 별도 작업 파일이나 상시 worker를 만들지 않고 요청 종료 시 취소·합류·통계 확정을 마친다.

검토 무소견은 초안을 확정하고 지적은 원본 이벤트 한 건에서 메인의 다음 판단과 압축 입력으로 투영한다. 보완 뒤 재심사·통과 게이트를 두지 않는다. 검토 오류는 검토 불가 이벤트로 남기고 초안의 종료를 허용한다. 사용자 취소·기록 실패는 기존 중단 경계를 따른다. 검토 중 새 지시는 기존 검토를 취소·합류한 뒤 반영한다. 메인 생성기의 이력 인코더와 메인 Compaction 메모는 독립 메모 처리에서 변경하지 않는다.
