# 에이전트 작동 방식

[← README](../README.md)

V는 사용자 요청 하나를 한 실행 루프에서 처리한다. 내부 Goal/Task 분해와 별도 최종 보고 호출을 제거하고, 메인 모델이 첫 native 호출부터 실제 작업을 진행한다.

## 실행 흐름

1. 프로젝트 루트의 선택적 AGENTS.md, 대화 이력, 현재 Scope·Plan에서 가능한 도구를 전달한다.
2. 일반 답변이면 턴을 마친다. 도구가 있으면 완전한 native 호출 한 개를 검증한다.
3. 호출의 짧은 reason을 실행 인자와 분리하고, 호출 ID·인자 해시에 묶어 self-grounding으로 저장한다.
4. Scope·Plan·snapshot을 검사하고 실제 변경 후보를 고정한다.
5. 내용 변경이면 Conclave 심사를 거친 뒤 사용자 승인 정책을 적용한다.
6. 실행 직전 파일 버전·승인 바인딩을 확인하고 한 번 실행한다.
7. 결과·검사·변경 revision을 저장한 뒤 다음 행동을 요청한다.

메인 응답은 평문이고 진행 설명은 native 호출과 함께 온 본문을 표시한다. 과거의 DONE/WAIT/CONTINUE 제어 헤더는 사용 대상에서 제거했다. Plan 모드는 읽기·검색만 허용하며 완성된 초안을 native submit_plan으로 제출한다. Plan 승인과 각 변경의 사용자 승인은 각각 적용한다.

## Native 도구와 근거

Chat Completions·Ollama의 tool_calls, Responses의 function_call을 사용한다. 도구 목록과 JSON Schema는 매 결정 요청에 제공한다. 스트림이 끝나고 전체 인자 검증이 통과한 뒤 실행을 준비한다. 다중 호출은 전체를 오류 피드백으로 반환한다.

모든 도구에는 필수 reason 문자열이 있다. 한 줄, 256문자·1,024바이트 이내로 현재 요청이나 관측 근거를 설명한다. 근거는 native 이력과 별도 감사 기록으로 보존하며, 별도 모델 호출은 없다. 근거는 모델의 주장이고 승인이나 검증 결과와 구별된다.

execute_command만 선택적 purpose=work/check를 받는다. 읽기·검색 실패는 관측 오류로 반환한다. 실행 전에 거부된 검사 후보는 새로운 필수 검사로 등록하지 않는다. 실제 시작한 검사 실패는 기록에 남는다.

## Conclave

내용 변경 후보 하나에 동일 모델로 심사 1회를 수행한다. 형식 교정 또는 추가 문맥 확보에 1회를 더 쓸 수 있다. 전송 재시도도 전체 모델 호출 예산에 포함한다.

심사 입력은 사용자 요청, 프로젝트 지침, 짧은 의도, 기존 검사 기록, frozen diff와 파일 메타데이터다. 파일 전체 인자와 같은 diff를 중복 전송하지 않는다. 줄 수와 EOF 개행 여부는 실행기가 계산한다. 내용 없는 생성·변경량 0인 후보는 심사를 생략한다.

반환 계약은 다음과 같다.

- pass: 지적 없는 통과.
- reject: 최대 3개의 구체적인 사유. 후보 경로와 before/after 줄 또는 request의 line=0을 지정한다.
- needs_context: 최대 2개의 scoped read_file 요청. offset/limit은 바이트이며 각 limit은 최대 8,192다.

엄격한 로컬 JSON 파서가 계약과 참조를 검사한다. 현재는 모든 Provider에서 이 계약을 사용하며 서버 문법 강제 기능을 자동 협상하지 않는다. 추가 조회·교정 후에도 판정이 불완전하거나 오류가 생기면 실행을 차단한다. 실행 전 심사는 후보를 판단하고 실제 적용·테스트는 실행 이후에 수행한다.

동일 요청·지침·모델·파일 delta·검사·관측 상태에 대한 거절은 실행 내 최대 32개까지 재사용한다. 새 Call ID나 reason만 바꿔 반복해도 재심사 비용이 추가되지 않는다. 승인과 실제 파일 버전 검사는 매번 적용한다.

Monitor는 기존 실행 worker에서 제안·심사·승인·시작·결과를 순서대로 저장한다. 별도 관측 goroutine과 모델 호출은 없다. UI에는 Conclave Pass/Fail과 짧은 부결 안내를 표시한다.

## 검증과 종료

읽기 전용 대화는 정상 답변으로 끝난다. 변경 뒤에는 현재 revision에서 성공한 purpose=check 명령이 필요하다. 문서도 실제 바이트를 비교하는 명령으로 검증할 수 있다. 코드에는 프로젝트에 맞는 실제 테스트·타입 검사 등을 선택한다.

검사 ID는 도구·명령에서 계산한다. 다른 명령의 성공으로 기존 실패를 덮지 않으며, 추가 변경 이후에는 기존 검사도 다시 실행한다. 정상 exited 상태와 종료 코드 0이 필요하다. 선택한 검사가 사용자 요구를 충분히 검증하는지까지 런타임이 증명하는 것은 아니다.

검증이나 심사가 남은 완료 답변에는 한 번 구체적인 교정 안내를 제공한다. 그래도 해결되지 않으면 unverified로 종료하고 남은 검사·심사 사유를 표시한다. 모델의 성공 주장은 감사 기록에 남기되 사용자에게 성공 결과로 표시하지 않는다.

기본 3회 무진전에는 최대 2회의 복구 기회를 준다. 동일 관측, 파일 내용 순환, 실패 반복을 기준으로 하며 Call ID·reason 변경은 진전으로 세지 않는다. 이미 시작한 동일 부작용은 자동 재실행하지 않는다. 사용자 승인 거절과 취소는 실행을 멈춘다.

## 문맥과 예산

압축 전 전체 대화와 호출·결과 쌍을 유지한다. 고아 호출은 실행 가능한 이력 대신 인용 관측으로 남긴다. 반복 조회도 Scope와 실제 파일을 확인하되, 동일 본문이 현재 문맥에 남아 있으면 unchanged와 원본 호출 참조를 반환한다. 원본이 압축됐다면 본문을 다시 제공한다.

누적 256,000 토큰과 마지막 메인 응답의 실제 INPUT 16,384 토큰이 압축 기준이다. 압축 소스 조각은 입력 예산 안에서 묶어 요약한다. 명시적인 context_length_exceeded 계열 오류에는 안전한 경계에서 압축하고 모델 요청만 한 번 재시도한다. 임의 오류 문구를 문맥 초과로 추측하지 않는다. 상세 설정은 [설정 문서](configuration.md)를 따른다.

기본 실행 한도는 다음과 같다.

| 설정 | 기본값 |
| --- | ---: |
| max_iterations | 128 |
| max_model_calls | 1024 |
| max_seconds | 14400 |
| max_model_seconds | 600 |
| max_context_bytes | 4194304 |
| max_argument_bytes | 65536 |
| stall_iterations | 3 |

max_model_seconds는 무수신 제한이다. 데이터가 계속 오는 모델 호출은 완료까지 수신하고 다음 작업 전에 전체 시간 예산을 다시 검사한다. 승인·도구 실행은 남은 실행 시간 내에서 처리한다. Plan 단계들도 예산을 공유한다. Ctrl+C 또는 !quit은 작업을 취소하고 자원을 정리한다.

HTTP·스트림 오류는 기존 최대 3회 전송 시도와 명시적 최종 오류를 유지한다. 실패한 스트림의 부분 응답은 다음 시도에 이어 붙이지 않으며 도구를 재생하지 않는다. INPUT/OUTPUT 표시는 Provider가 실제 보낸 usage만 합산한다.

## 구현 경계

agent/run은 수명과 순서, agent/tool은 호출·실행 사실, agent/conclave는 심사, agent/context는 문맥, agent/verification은 검사 상태, agent/compact는 요약을 소유한다. 저장 계약과 SQLite 어댑터는 분리한다. 모델군의 특화는 provider/profile에서 관리한다.

단기 로컬 사례의 측정 결과는 장시간 수렴이나 모델 전체의 성공률을 보장하지 않는다. 비교 평가는 같은 모델·서버 설정에서 실제 성공 여부와 수신 토큰·호출 수를 함께 확인한다.

## 파일 형식과 검증 명령의 보호

read_file은 실제 FinalNewline과 읽은 범위의 RangeLineEndings(lf/crlf/mixed/none/unknown)를 반환한다. 화면용 줄바꿈과 원본 바이트를 구분한다.

write_file·edit_file의 format_policy 기본값은 preserve다. 기존 파일의 마지막 개행이 빠진 비어 있지 않은 결과에는 기존 종결자를 보충한다. 기존에 없던 EOF 개행 추가나 줄바꿈 형식 변경은 명시적 literal 정책이 필요하다. 빈 파일 생성·내용 전체 삭제는 요청한 빈 내용을 유지한다. partial edit의 균일한 CRLF 범위는 preserve에서 기존 형식으로 처리한다. literal은 의도적인 형식 변경을 허용하며 여전히 실제 diff 심사와 사용자 승인을 거친다.

정규화는 후보 고정 전에 끝낸다. Conclave는 실제 결과의 형식 메타데이터와 diff를 받고, 승인 후에는 그 바이트를 기록한다. 공백과 꼬리 빈 줄을 일괄 삭제하지 않는다. 새로 유입된 줄 번호·해시 표시 패턴은 기본적으로 소스 복사 오류로 거부한다. 해당 표식 자체가 요청된 파일 내용이면 literal로 명시한다. 도구 실패 직후 다시 읽을 때는 동일 본문이라도 원문과 앵커를 반환한다.

purpose=check는 한 개의 전경 명령 또는 && 연결만 허용한다. 인자·리다이렉션은 리터럴이어야 한다. 파이프, 백그라운드, 명령 치환, 셸 래퍼와 실패를 가리는 연결은 분리하도록 오류를 반환한다. 이는 최상위 셸 실패 전달 규칙이며 임의 프로그램 내부 검사의 의미까지 증명하지 않는다. 일반 work 명령은 기존 셸 정책을 따른다. 격리 초기화 실패는 scope_unavailable로 반환하고 실제 검사 실행이나 변경으로 등록하지 않는다.

## 플랫폼 실행 환경

macOS는 명시된 DEVELOPER_DIR 또는 xcode-select -p로 선택된 설치 경로를 검사한다. 해당 설치와 부모 경로의 필요한 메타데이터만 접근시키고 도구 설치는 읽기·실행 전용으로 유지한다. Xcode 앱 경로는 Contents/Developer로 해석한다. 설치가 없는 경우 일반 실행 환경을 유지하며, 잘못 지정된 경로나 보호 경로와의 충돌은 준비 오류로 처리한다. 전역 개발 도구 선택 변경이나 자동 설치는 수행하지 않는다.

프로젝트 격리는 Git의 시스템·사용자 전역 설정을 제외하고 프로젝트 로컬 설정을 사용한다. GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_GLOBAL=/dev/null을 지정한다. 공통 환경의 XDG 설정·캐시와 임시 파일은 실행용 임시 경로를 사용한다.

Linux의 ~/.local/bin과 ~/.local/share/uv/python은 명시적 읽기 전용 런타임 경로다. PATH 보완과 UV_PYTHON_INSTALL_DIR 지정, 디렉터리 우회 심볼릭 링크 거부, 마운트·Landlock 규칙을 함께 적용한다. 지원 범위 밖의 임의 PATH 경로를 통째로 노출하지 않는다. 네임스페이스·마운트·Landlock을 사용할 수 없는 환경에서는 명령 실행 없이 원인을 반환한다.
