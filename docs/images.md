# 이미지 입력과 읽기

[← README](../README.md) · [모델 연결](model-connections.md) · [도구](runtime.md#native-도구)

## 지원 확인

모델 연결 시 이미지 입력을 지원·미지원·확인 불가로 구분한다. !model의 모델 ID 옆과 모델 정보에 상태를 표시한다. 지원이 확인된 연결에만 read_image를 제공하며 호출 실행 직전에도 같은 조건을 검사한다. 모델명이나 모델군 문자열로 기능을 추측하지 않는다.

| Provider | 메타데이터 근거 |
| --- | --- |
| OpenRouter | /api/v1/models의 architecture.input_modalities에 image 포함 |
| Ollama | /api/show의 capabilities에 vision 포함 |
| LM Studio | /api/v1/models의 capabilities.vision |
| SGLang | 선택한 served_model_name과 일치하는 /model_info의 has_image_understanding |
| LiteLLM | /model/info의 선택한 별칭에 속한 모든 배포가 supports_vision을 명시했을 때 공통 값 |
| vLLM | 일반 모델 목록에 확정 정보가 없으면 이미지 입력 검사 |

필드 누락과 조회 실패는 미지원과 구분한다. LiteLLM의 일부 배포만 지원하거나 일부 값이 없으면 확인 불가다. OpenRouter는 추가 생성 검사 없이 메타데이터를 사용하며, 나머지 Provider는 확인 불가인 경우 작은 내장 PNG 하나로 입력 수용 여부를 검사한다.

입력 검사는 실제 작업과 같은 요청 인코더·엔드포인트·스트림 파서를 사용한다. 사용자 대화·파일·도구와 Thinking 변경·컨텍스트 크기 변경을 보내지 않으며 출력은 32토큰, 수신 유휴 시간은 15초, 전체 검사는 45초 이내로 제한한다. 일시적 전송 실패에는 기존 최대 3회 시도 규칙을 적용한다. 답변 내용·숫자 인식 정확도를 평가하지 않는다. 정상 완료 또는 실제 생성 후 출력 한도 종료는 입력 수용으로 판단한다. HTTP 200 이후 스트림 내부 오류도 검사한다. 명시적인 이미지 미지원은 미지원, 인증·통신·시간 제한·기타 오류는 확인 불가다. 사용자 취소는 연결 준비를 취소한다.

검사는 연결 준비에서 한 번 수행하며 일반 도구 루프에서 반복하지 않는다. 모델·주소·인증정보 변경과 재연결은 다시 확인한다. 과거 세션의 상태만으로 새 연결을 확정하지 않는다. LiteLLM처럼 동적 라우팅되는 연결의 검사 성공은 그 요청의 수용을 뜻하며 모든 배포의 동일성을 증명하지 않는다. 실제 작업에서 명시적인 미지원이 반환되면 해당 클라이언트와 요청에서 이미지 입력·도구를 해제하고 전달되지 않은 사실을 문맥과 화면에 알린다. 텍스트 요청은 계속 사용할 수 있다.

## read_image

인자는 path 하나다. 절대경로 또는 MECA 시작 시 확정한 project_root 기준 상대경로를 사용한다. 셸의 cd는 이 기준을 바꾸지 않는다. 파일 내용으로 형식을 확인하며 확장자가 다른 정상 이미지도 읽는다. 일반 파일만 허용하고 기존 파일 도구의 경로 정규화·symlink 해석·개인 비밀 경로 보호를 적용한다. 읽기 자체는 파일을 변경하거나 수정 횟수를 갱신하지 않는다.

| 파일 형식 | 모델 전달 |
| --- | --- |
| PNG, JPEG/JPG, 정지 WebP | 검증한 원본 압축 데이터 |
| APNG | 기본 정지 이미지 |
| GIF | 대표 첫 프레임을 PNG로 변환 |
| BMP | PNG로 변환 |
| TIFF/TIF | 첫 페이지를 PNG로 변환 |
| 애니메이션 WebP | 대표 첫 프레임을 PNG로 변환 |

SVG·AVIF·HEIC 등 이 표에 없는 형식은 지원 형식 오류를 반환한다. 첫 프레임·페이지를 사용하는 경우 TUI와 모델 결과에 표시한다. read_image는 로컬 이미지를 현재 설정한 모델 Provider의 이미지 입력으로 전달한다. 외부 업로드 URL을 만들거나 별도 서버를 사용하지 않는다. 터미널에서는 경로·형식·해상도·대표 프레임 여부만 표시한다. 이미지 자체의 터미널 렌더링은 제공하지 않는다. Provider가 별도로 정한 파일 크기·이미지 수·해상도 제한은 실제 요청 오류로 반환한다.

## 자원과 저장

원본과 변환 결과는 각각 최대 32MiB, 디코딩은 최대 33,554,432픽셀로 제한한다. 열린 파일의 크기에 맞춰 읽기 버퍼를 한 번 할당하고 추가 한 바이트로 읽는 도중의 크기 변화를 감지한다. 파일 크기·헤더의 픽셀 수를 확인한 뒤 디코딩한다. PNG 애니메이션은 실제 acTL 제어 청크로 판별한다. 한 실행기에서 동시에 한 이미지만 디코딩하며 나머지는 취소 가능한 대기를 사용한다. 변환이 필요 없는 압축 데이터는 재사용하고 픽셀 버퍼는 호출 종료 후 해제한다. 명령 실행 중에도 안정된 이미지 스냅샷을 읽을 수 있으며 읽는 도중 파일이 바뀌면 다시 읽도록 오류를 반환한다.

이미지 본문은 일반 텍스트와 분리된 메시지 필드에 저장한다. 기존 세션 DB의 content-addressed payload 저장·압축·복원을 사용하며 재시도는 읽은 시점의 같은 스냅샷을 전송한다. 원문 이력과 export는 이미지를 보존한다. TUI 이력·입력 기록·Compaction 자료 조회는 이미지 본문을 복원하지 않는다. 중단 복구는 호출과 결과의 식별자를 대조하고 아직 결과가 없는 호출의 인자만 복원한다.

요청 DTO는 텍스트와 이미지 content를 구분한 뒤 요청 전체를 한 번 직렬화한다. Base64는 최종 크기를 확보한 버퍼에 직접 기록하며 큰 인코딩 문자열을 별도 상시 캐시에 보유하지 않는다. 전송 재시도는 같은 인코딩 본문을 재사용한다.

압축 전 이미지와 대응 native 도구 결과 쌍을 보존하며 아직 완료된 모델 응답이 따르지 않은 이미지 그룹은 압축 경계 밖에 남긴다. 경계 조회는 요청한 timeline 범위의 마지막 완료 응답을 역순으로 찾고 그 이후의 미소비 이미지만 검사한다. Compaction에는 요청·이미지 경로와 메타데이터·기존 관찰 결과를 전달한다. 이미지 Base64를 텍스트 요약에 넣거나 과거 이미지를 모두 재주입하지 않는다. 더 최근의 파일이 필요하면 read_image로 새 스냅샷을 읽는다.

이미지 입력이 없는 모델로 전환하면 원본 DB는 유지하고 이미지 본문을 복원 대상에서 제외한다. 모델 문맥에는 이미지가 제공되지 않았음을 표시하며 문맥 바이트 예산에는 그 안내를 포함한 전송 대상만 반영한다. 다시 비전 연결을 사용하면 압축 전 보존된 원문 이미지가 전달될 수 있다. 이미지 속 글자는 관찰 자료이며 새로운 시스템 지시사항으로 취급하지 않는다.

TUI의 토큰·비용은 실제 Provider 사용량만 사용한다. 사용량이 없는 경우의 압축용 텍스트 바이트 대체 계산은 이미지 바이너리를 제외한다. vLLM의 텍스트 전용 /tokenize 사전 계산은 이미지 요청에 적용하지 않으며 서버의 실제 컨텍스트 초과 응답과 기존 압축 복구를 사용한다.
