# 이미지 입력과 보기

[← README](../README.md) · [모델 연결](model-connections.md) · [도구](runtime.md#native-도구) · [서버 API](server.md)

## 지원 확인

tui·full의 TUI는 `Alt+V`, macOS에서는 `Ctrl+V`도 사용해 로컬 클립보드 이미지를 첨부한다. full WebUI는 `+`의 이미지 선택·드래그 앤드 드롭·클립보드 붙여넣기를 제공한다. 이미지 전용 요청도 가능하며 지원이 확인된 모델에만 실제 이미지 바이트를 전송한다. 저장 이력의 썸네일과 원본 열기는 [WebUI 이미지 계약](webui-api.md#파일이미지-페이지)을 따른다.

스킬의 `read_skill_file`도 이미지 지원 요청에서는 같은 디코더·크기 한도로 래스터 자료를 읽는다. 비전 미지원 요청과 서버의 참고 파일 조회 API는 이미지 메타데이터만 반환한다. [스킬 자료 읽기](skills.md)를 따른다.

이미지 입력 판정과 `view_image`는 TUI·CLI·native 서버 요청에 공통으로 적용한다. TUI 첨부와 자체 서버 API의 이미지 입력도 같은 스냅샷 계약·디코더를 사용한다. 서버 이벤트·상세 API는 이미지 원본 바이트를 반환하지 않는다.

## 사용자 이미지 첨부

TUI의 `Alt+V`, macOS의 `Ctrl+V`는 로컬 클립보드 이미지를 비동기로 읽는다. 일반 텍스트는 터미널의 텍스트 붙여넣기를 사용한다. macOS는 시스템 AppKit, Linux는 Wayland 데이터 제어 프로토콜 또는 X11을 공통 Go 클립보드 라이브러리로 직접 읽는다. `wl-paste`·`xclip`·Python·CGO를 요구하지 않는다. 이미지 또는 파일 관리자에서 복사한 로컬 이미지 파일 하나를 읽으며, 일반 텍스트의 경로·URL은 가져오지 않는다. SSH 세션에서는 데스크톱 클립보드를 읽지 않는다.

WSL은 별도 배포본 없이 같은 Linux 바이너리를 사용한다. WSLg 여부와 관계없이 Windows 기본 `powershell.exe`의 이미지·파일 클립보드 API를 사용한다. [WSL 상호운용](https://learn.microsoft.com/en-us/windows/wsl/wsl-config#interop-settings)이 활성화되어 있어야 하며, Windows PATH를 가져오지 않는 환경에서도 마운트된 Windows 시스템 경로를 탐색한다. 상호운용이 꺼져 있거나 Windows PowerShell을 실행할 수 없으면 명시적인 오류를 반환한다. 복사한 이미지 파일은 Windows 로컬 절대경로만 허용하며 UNC 경로는 읽지 않는다.

클립보드는 붙여넣기 요청이 있을 때만 읽고 상시 감시하지 않는다. macOS의 동기 네이티브 호출은 같은 MECA 바이너리의 일회성 자식 프로세스로 격리한다. 자식·WSL 브리지는 길이가 명시된 바이너리 파이프를 사용하며 MECA가 이미지 임시 파일이나 Base64 중간 문자열을 만들지 않는다. TUI 읽기 마감은 5초다. 취소 시 연결·파이프를 닫고 자식에 종료 신호를 전달하며, 최대 1초의 정리 유예 뒤에도 종료되지 않으면 강제 종료하고 결과를 수집한다. 바이트와 픽셀 한도는 공통 이미지 코덱에 적용한다. WSL 브리지는 변환 전에 Windows Job Object의 프로세스 메모리 한도를 설정하고 PNG 쓰기 버퍼도 증가 전에 상한을 검사한다. 호스트가 이 보호를 설정할 수 없으면 읽기를 거절한다. WebUI는 서버 OS의 클립보드가 아니라 브라우저의 붙여넣기·파일 API를 사용하므로 이 브리지를 요구하지 않는다.

첨부 이미지는 입력 영역에 파란색 `[IMAGE:1]`, `[IMAGE:2]`로 표시한다. 본문 맨 앞의 `Backspace` 또는 `Alt+Backspace`로 마지막 이미지를 제거한다. 텍스트 없이 이미지만 전송할 수 있다. 모델의 비전 지원이 확인되지 않으면 초안을 보존하고 전송을 거절한다. 실행 중 이미지가 있는 입력은 방향 수정 텍스트로 보내지 않고 후속 요청으로 예약한다. 예약 편집·취소·실패 복원에서도 이미지 스냅샷을 유지하며, 작성 중·예약·저장 초안의 합계도 최대 8개·128MiB로 제한한다. 비동기 붙여넣기 도중 다른 초안으로 이동했다면 새 초안에 몰래 첨부하지 않는다.

모든 서버 protocol에서 `POST /v1/attachments`에 `Content-Type: image/png` 등 실제 이미지 형식을 지정하고 압축 파일 바이트를 본문으로 업로드한다. 반환한 `id`를 native `start.attachmentIds` 에 넣는다. `GET /v1/attachments/{id}`는 메타데이터, `DELETE /v1/attachments/{id}`는 임시 참조 해제다. 업로드는 최대 16개·합계 256MiB를 5분간 보관한다. 실행이 빌린 불변 바이트는 참조 해제·만료 후에도 해당 작업이 소유한다. 만료된 업로드는 같은 이미지로 다시 올려야 하며, 접수한 작업은 작업 ID로 조회한다.

자체 API는 압축 이미지의 binary 업로드와 `start.attachmentIds`만 사용한다. 원격 이미지 URL을 가져오거나 텍스트 안의 base64를 이미지로 추측하지 않는다. 실제 이미지 바이트는 비전 지원이 확인된 모델 요청으로 전달한다. API 계약은 [서버 문서](server.md)를 따른다.

모델 연결 시 이미지 입력을 지원·미지원·확인 불가로 구분한다. !model의 모델 ID 옆과 모델 정보에 상태를 표시한다. 지원이 확인된 연결에만 view_image를 제공하며 호출 실행 직전에도 같은 조건을 검사한다. 모델명이나 모델군 문자열로 기능을 추측하지 않는다.

| Provider | 메타데이터 근거 |
| --- | --- |
| OpenRouter | /api/v1/models의 architecture.input_modalities에 image 포함 |
| Ollama | /api/show의 capabilities에 vision 포함 |
| LM Studio | /api/v1/models의 capabilities.vision |
| SGLang | 선택한 served_model_name과 일치하는 /model_info의 has_image_understanding |
| LiteLLM | /model/info의 선택한 별칭에 속한 모든 배포가 supports_vision을 명시했을 때 공통 값 |
| vLLM | 일반 모델 목록에 확정 정보가 없으면 이미지 입력 검사 |
| OpenAI | 모델 목록이 이미지 수용을 선언하지 않으므로 이미지 입력 검사 |
| Claude | Models API의 capabilities.image_input.supported; 필드가 없으면 이미지 입력 검사 |
| Gemini | 모델 목록이 이미지 수용을 선언하지 않으므로 이미지 입력 검사 |

필드 누락과 조회 실패는 미지원과 구분한다. LiteLLM의 일부 배포만 지원하거나 일부 값이 없으면 확인 불가다. OpenRouter는 추가 생성 검사 없이 메타데이터를 사용하며, 나머지 Provider는 확인 불가인 경우 작은 내장 PNG 하나로 입력 수용 여부를 검사한다.

입력 검사는 실제 작업과 같은 요청 인코더·엔드포인트·스트림 파서를 사용한다. 사용자 대화·파일·도구와 Thinking 변경·컨텍스트 크기 변경을 보내지 않으며 출력은 32토큰, 수신 유휴 시간은 15초, 전체 검사는 45초 이내로 제한한다. 일시적 전송 실패에는 최초 요청을 포함해 최대 4회 시도하며 기본 재시도 대기는 1초·3초·5초다. 전체 45초 마감이나 사용자 취소가 먼저 오면 남은 시도를 중단한다. 답변 내용·숫자 인식 정확도를 평가하지 않는다. 정상 완료 또는 실제 생성 후 출력 한도 종료는 입력 수용으로 판단한다. HTTP 200 이후 스트림 내부 오류도 검사한다. 명시적인 이미지 미지원은 미지원, 인증·통신·시간 제한·기타 오류는 확인 불가다. 사용자 취소는 연결 준비를 취소한다.

검사는 연결 준비에서 한 번 수행하며 일반 도구 루프에서 반복하지 않는다. 모델·주소·인증정보 변경과 재연결은 현재 서버의 정보를 다시 확인한다. LiteLLM처럼 동적 라우팅되는 연결의 검사 성공은 그 요청의 수용을 뜻하며 모든 배포의 동일성을 증명하지 않는다. 실제 작업에서 명시적인 미지원이 반환되면 해당 클라이언트와 요청에서 이미지 입력·도구를 해제하고 전달되지 않은 사실을 문맥과 화면에 알린다. 텍스트 요청은 계속 사용할 수 있다.

## 브라우저 첨부 미리보기

WebUI는 모델에 보낼 원본 File과 표시용 파생 이미지를 분리한다. capabilities의 `imageTypes`·`imagePixels`·`previewDecodePixels`·`thumbnailEdge`를 따라 형식·픽셀 예산을 확인한다. 작은 이미지는 브라우저에서 직렬로 축소하고, 크거나 로컬 디코더가 지원하지 않는 형식은 인증된 `POST /v1/ui/thumbnail`로 축소한다. 표시용 PNG는 최대 변 256px이며 이 요청은 첨부를 DB에 저장하지 않는다.

카드가 사라지면 파생 이미지 URL을 해제하고 모델 요청을 접수할 때 원본을 업로드한다. 미리보기의 픽셀·전송·메모리 예산과 실제 모델 입력 한도를 구분한다. [브라우저 이미지 계약](webui-api.md#첨부-미리보기와-정적-자산)이 로컬 디코딩·서버 폴백과 정리를 소유한다.

## view_image

이미지 픽셀 확인용 도구다. 소스 코드·스크립트·Markdown 등 텍스트 파일은 execute_command의 cat·sed 등으로 읽는다.

인자는 path 하나다. 절대경로 또는 현재 선택한 세션의 project_root 기준 상대경로를 사용한다. 이전 대화를 열면 해당 세션의 프로젝트를 기준으로 하며 개별 셸의 cd는 이 기준을 바꾸지 않는다. 파일 내용으로 형식을 확인하며 확장자가 다른 정상 이미지도 읽는다. 일반 파일만 허용하고 파일 도구의 경로 정규화·symlink 해석·개인 비밀 경로 보호를 적용한다. 읽기 자체는 파일을 변경하거나 수정 횟수를 갱신하지 않는다.

| 파일 형식 | 모델 전달 |
| --- | --- |
| PNG, JPEG/JPG, 정지 WebP | 검증한 원본 압축 데이터 |
| APNG | 기본 정지 이미지 |
| GIF | 대표 첫 프레임을 PNG로 변환 |
| BMP | PNG로 변환 |
| TIFF/TIF | 첫 페이지를 PNG로 변환 |
| 애니메이션 WebP | 대표 첫 프레임을 PNG로 변환 |

SVG·AVIF·HEIC 등 이 표에 없는 형식은 지원 형식 오류를 반환한다. 첫 프레임·페이지를 사용하는 경우 TUI와 모델 결과에 표시한다. view_image는 로컬 이미지를 현재 설정한 모델 Provider의 이미지 입력으로 전달한다. 외부 업로드 URL을 만들거나 별도 서버를 사용하지 않는다. 터미널에서는 경로·형식·해상도·대표 프레임 여부만 표시한다. 이미지 자체의 터미널 렌더링은 제공하지 않는다. Provider가 별도로 정한 파일 크기·이미지 수·해상도 제한은 실제 요청 오류로 반환한다.

## 자원과 저장

같은 스냅샷을 여러 번 사용하는 경우도 각 전송분의 Base64 길이를 합산한다. 이미지 Base64만으로 256MiB 요청 상한을 넘으면 인코딩 전에 거부한다. 이 선검사 통과는 전체 JSON 또는 Provider 자체의 이미지 한도 통과를 뜻하지 않는다.

원본과 변환 결과는 각각 최대 **64MiB**, 디코딩은 최대 **67,108,864픽셀**이다. 사용자 요청당 최대 8개·압축 바이트 합계 128MiB를 적용한다. 파일 형식·크기·변경 여부와 디코딩 자원 예산을 확인하며, 처리 중 파일이 바뀌면 오류를 반환한다. Provider 고유 한도가 더 작으면 요청이 거절될 수 있으며 모델 입력을 임의로 축소하지 않는다.

이미지 본문은 일반 텍스트와 분리된 메시지 필드에 저장한다. 세션 DB의 content-addressed payload 저장·압축·복원을 사용하며 재시도는 읽은 시점의 같은 스냅샷을 전송한다. 원문 이력과 export는 이미지를 보존한다. TUI 이력·입력 기록·Compaction 자료 조회는 이미지 본문을 복원하지 않는다. 중단 복구는 호출과 결과의 식별자를 대조하고 아직 결과가 없는 호출의 인자만 복원한다.

팀의 사용자 이미지는 공용 대화에 한 번 저장하고 개인 DB에는 공용 원문을 검증하는 참조만 기록한다. 읽지 않은 사용자 이미지와 도구 이미지 모두 완료된 모델 응답이 따를 때까지 압축 경계 밖에 유지한다.

이미지와 대응 도구 결과의 관계를 보존하며, 처리되지 않은 이미지를 압축 과정에서 누락하지 않는다. 요약에는 경로·메타데이터·관찰 결과를 사용하고 이미지 Base64를 텍스트 요약에 넣지 않는다. 새 파일 상태가 필요하면 `view_image`로 다시 읽는다.

이미지 입력이 없는 모델로 전환하면 원본 DB는 유지하고 이미지 본문을 복원 대상에서 제외한다. 모델 문맥에는 이미지가 제공되지 않았음을 표시하며 문맥 바이트 예산에는 그 안내를 포함한 전송 대상만 반영한다. 다시 비전 연결을 사용하면 압축 전 보존된 원문 이미지가 전달될 수 있다. 이미지 속 글자는 관찰 자료이며 새로운 시스템 지시사항으로 취급하지 않는다.

TUI의 토큰·비용은 실제 Provider 사용량만 사용한다. 사용량이 없는 경우의 압축용 텍스트 바이트 대체 계산은 이미지 바이너리를 제외한다. vLLM의 텍스트 전용 /tokenize 사전 계산은 이미지 요청에 적용하지 않으며 서버의 실제 컨텍스트 초과 응답과 압축 복구를 사용한다.

## 서버 이력의 첨부

이미지 전용 사용자 메시지도 history에 포함한다. images 메타데이터는 pixels를 읽지 않고 envelope에서 구성하며 저장 이미지는 인증된 `/v1/sessions/{id}/images/{sequence}/{index}`에서 해당 한 장만 복원한다. 첨부의 임시 upload 수명과 세션 저장 수명은 별개다. 팀 개인 문맥은 공용 이미지 참조를 길이·해시로 검증한 뒤 typed 값으로 연결해 큰 base64 JSON의 중복 구성·파싱을 줄인다.
