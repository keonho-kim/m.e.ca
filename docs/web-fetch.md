# 웹 문서 조회

`web_fetch`는 URL을 받아 HTTP(S) 문서 한 건을 읽는다. HTML은 전용 Chromium에서 JavaScript를 실행한 뒤 DOM에서 본문을 고른다. 제목·목록·표·코드를 Markdown으로 전달한다. 텍스트와 Markdown은 직접 읽는다.

## 활성화

MECA가 실행되는 호스트에 Chrome이나 Chromium이 준비되면 대화에서 URL을 바로 요청할 수 있다. 솔로·팀, TUI·서버·비대화형 요청에 같은 정책을 적용한다. [브라우저 설치](browser.md#첫-실행과-설치)

공개 주소는 작업에 필요한 문서의 URL을 지정한다. 로컬 또는 사설망은 사용자가 현재 요청에 직접 넣은 URL을 읽는다. 서버 모드의 로컬 주소는 MECA 서버에서 해석한다.

## 접속 범위

연결은 DNS로 확인한 IP만 사용한다. 메타데이터·링크 로컬·특수 목적 주소와 공개·사설 IP가 섞인 DNS 응답은 거절한다. 공개 URL의 리다이렉트는 공개 주소로만 이어지고, 내부 URL의 리다이렉트는 같은 출처 안에서 처리한다. HTTPS는 MECA 실행 호스트의 신뢰 저장소로 주소와 인증서 체인을 오프라인 검증한다.

Chromium은 독립된 임시 프로필을 사용한다. Go 전송부는 문서를 가져오고, 렌더링에는 최종 문서와 같은 출처의 스크립트·스타일·Fetch/XHR에 필요한 GET·HEAD만 제공한다. 브라우저 쿠키·인증 헤더·Referer는 전달하지 않는다. 직접 요청은 거절 프록시로 보내며 다른 출처의 리소스나 쓰기 요청을 차단한다.

원본 서버에는 조회에 필요한 HTTP 요청만 보낸다. 문서 정제와 페이지 구성은 MECA에서 처리하고, 모델의 판단에 필요한 본문 페이지는 선택한 모델에 전달한다. [네트워크 사용과 데이터 전송](../SYSTEM.md#네트워크-사용과-데이터-전송)

## 이어 읽기

`url`로 조회하면 제목·최종 주소·본문 첫 페이지가 돌아온다. `next_offset`이 있으면 `result_id`·`revision`·`offset`으로 다음 페이지를 읽는다. 첫 페이지는 기본 2 KiB, 다음 페이지는 기본 8 KiB다. 한 페이지는 최대 16 KiB이며, 현재 모델 문맥과 같은 응답에서 요청한 페이지 수에 따라 더 작아질 수 있다.

본문은 외부 입력으로 다룬다. 완료된 모델 판단에서 읽은 페이지는 다음 문맥에서 열람 표시로 바뀐다. 압축은 처리 대기 중인 결과와 활성 커서를 보존한다. 다 읽은 임시 블록은 제거하고, 요청이 끝나면 남은 임시 본문과 커서는 만료된다. 이미 전달된 페이지는 대화 기록에서 조회할 수 있다.

압축 해제한 문서, 렌더링한 HTML, 변환한 본문은 각각 최대 2 MiB다. 스크립트·스타일·데이터 요청은 최대 48건, 응답 합계 4 MiB로 제한한다. 한 요청에 이어 읽기 중인 문서는 최대 8개다. [최적화 구현 전략](optimization-strategies.md#웹-문서-조회)
