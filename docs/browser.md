# 브라우저 도구

[문서 목록](README.md) · [에이전트 작동 방식](runtime.md)

MECA는 `browser_action`과 `browser_inspect`로 웹 페이지를 조작·검증한다. TUI·서버·팀 모드가 같은 도구를 사용한다. 서버 모드의 브라우저는 MECA 서버가 실행되는 컴퓨터에서 열린다.

## 첫 실행과 설치

에이전트를 사용하기 전에 다음 명령을 실행하면 MECA를 실행할 계정에 브라우저 도구를 준비하고 검사한다.

```sh
meca install --ext browser
```

성공하면 전용 빈 페이지 열기·스냅샷 읽기·종료를 확인한 뒤 도우미와 Chrome의 실행 경로를 출력한다. 같은 명령으로 기존 설치를 재사용해 다시 점검할 수 있다. 서버를 원격 호스트나 컨테이너에서 실행한다면 그 안에서 같은 사용자로 실행한다. 이 검사는 모델 연결이나 테스트 대상 웹 서버에 의존하지 않는다.

모델이 처음 `browser_action`의 `open`을 실행하면 고정 버전의 `agent-browser` 네이티브 실행 파일을 `~/.meca/browser/runtime/`에 준비한다. 기존 Chrome·Chromium을 찾고, 없으면 Google 공식 API에서 현재 Stable을 조회해 Chrome for Testing을 내려받는다. 인자 없는 일반 설치와 업그레이드는 브라우저 사용 시점까지 다운로드를 미룬다. MECA 배포 아카이브에는 브라우저나 npm·Node 실행 환경을 포함하지 않는다.

- 브라우저를 직접 지정하려면 MECA 실행 환경의 `MECA_BROWSER_EXECUTABLE`에 실행 파일의 절대 경로를 설정한다.
- macOS와 Linux·WSL의 arm64·amd64에서 Chrome 자동 준비를 제공한다.
- Linux에는 브라우저의 시스템 라이브러리와 호환 실행 환경이 필요하다. Docker에서는 `--init` 또는 자식 프로세스를 회수하는 init을 사용한다. MECA는 시스템 패키지 설치나 권한 상승을 자동 수행하지 않는다. 브라우저 실행 옵션은 고정된 도우미가 결정하며, 해당 버전은 컨테이너·root 환경에서 Chrome 샌드박스를 비활성화할 수 있다. 전용 세션은 OS 격리나 네트워크 차단을 보장하지 않는다. 컨테이너나 WSL에서 실제 브라우저 실행 조건은 해당 환경에 맞게 준비한다.
- 도우미는 고정 SHA-256을 검증한다. Chrome은 사전 고정 체크섬을 사용하지 않으며, 공식 HTTPS 메타데이터·Google 저장소의 정확한 버전별 URL만 허용한다. 다운로드·압축 해제 크기와 ZIP 구조를 검사하고, 실행 파일이 선택한 버전을 보고하는지 확인한다. 다운로드 중단·실패 시 미완성 설치를 게시하지 않고 임시 파일을 정리한다. 여러 프로세스의 설치는 잠금으로 직렬화한다. 잘못된 설치 기록은 보존하고 오류로 거절한다.
- 전용 다운로드 공간은 설정·대화와 분리된다. `meca uninstall`은 `~/.meca`와 함께 관리 파일을 제거하며 기존 시스템 Chrome은 유지한다.

## Stable 갱신

관리 설치본은 재사용하며 새 브라우저 세션을 열 때 마지막 확인에서 24시간이 지났으면 Stable을 조회한다. 새 버전은 별도 디렉터리에 설치하고 실행 검증 후 선택 기록을 원자적으로 전환한다. 갱신 중에 열리는 다른 세션은 검증된 기존 버전을 사용할 수 있다. 조회·다운로드·실행 검증 실패 시 기존 설치본을 유지하며 다음 확인은 24시간 후에 한다. 최초 설치가 실패하면 오류를 반환한다.

실행 중인 세션은 종료가 확인될 때까지 선택한 버전 경로를 사용한다. 관리 설치는 현재 버전과 직전 버전을 보관하고, 사용 기록상 종료가 확인된 더 오래된 설치본은 다음 Stable 확인에서 정리한다. 사용 여부를 확인할 수 없는 버전과 외부에서 설치한 Chrome은 보존한다. 관리형 Chrome 검증은 공식 HTTPS 출처와 전송·파일 구조·실행 확인에 기반한다.

## 사용 범위

`browser_action`은 열기, 뒤로/앞으로 이동, 새로고침, 클릭, 입력, 키보드, 선택, 체크, 스크롤, 요소 대기, 뷰포트 변경과 닫기를 제공한다. 셸 문자열·임의 JavaScript·개인 브라우저 프로필·외부 CDP 접속 인자는 받지 않는다. HTTP(S) 페이지를 사용하며 로컬 파일 URL과 URL 내 인증정보는 거절한다.

브라우저 도구는 system 범위에서만 실행한다. 외부 페이지 열기·입력·클릭·키보드·선택 등은 정보를 전송하거나 원격 상태를 바꿀 수 있어 All Mighty에서도 직접 승인을 요구한다. 루프백(localhost 또는 루프백 IP) 열기와 관찰·결과 이어 읽기·스크롤·요소 대기·뷰포트 변경·닫기는 승인 창을 띄우지 않는다. 클릭·입력·키 입력·선택·체크·체크 해제·호버·뒤로·앞으로·새로고침은 루프백에서도 기본 권한에서는 승인을 요청한다. All Mighty에서는 루프백 조작을 자동 허용한다. 준비한 조작의 페이지 주소가 실행 시점에 달라졌으면 거절한다. 시간 초과나 취소가 이미 일어난 웹 동작을 되돌리지는 않으므로 현재 상태를 관찰한 뒤 재시도한다.

작업마다 전용 브라우저 세션을 사용한다. 개인 프로필·기존 로그인 세션에 자동 접속하지 않는다. 작업 종료·취소와 대화 닫기는 세션·소켓·임시 관찰 자료를 정리한다. 다음 요청에서는 필요한 페이지를 다시 연다. 팀 참여자의 세션도 서로 분리한다.

동시에 열린 외부 브라우저는 MECA 프로세스당 기본 3개로 제한한다. `MECA_BROWSER_MAX_SESSIONS`(양의 정수)로 조정하며 일반 작업 동시성 옵션과 독립적이다. 용량이 차면 새 열기를 거절한다. 브라우저 작업을 끝낸 참여자가 `close`로 자원을 반환한 뒤 다시 열 수 있다. 새 세션을 열기 전 macOS의 시스템 메모리 압박 상태 또는 Linux·WSL의 가용 메모리와 cgroup v2 잔여량을 확인한다. macOS 경고·위험 상태 또는 Linux 가용량 512MiB 미만에서는 새 열기를 거절하고, 측정 실패도 오류로 알린다. 실행 중인 브라우저를 강제 종료하지 않는다. 이 제한은 입장 관리이며 Chrome의 실제 RSS 상한은 아니다.

## 관찰과 컨텍스트

`browser_inspect`의 `snapshot`은 읽을 수 있는 본문·상태와 조작 가능한 요소 참조를 반환한다. 기본 깊이는 5이며 `selector`로 영역을 좁힐 수 있다. `text`는 특정 영역의 텍스트, `errors`는 브라우저 오류, `screenshot`은 현재 뷰포트의 PNG를 제공한다. 스크린샷은 비전 입력이 가능한 모델에서 사용하며 최대 4,096,000픽셀의 PNG를 받는다. 압축 파일 크기와 픽셀 수를 확인한 뒤 디코딩하고, 전달 중인 이미지의 메모리 예약을 유지한다.

같은 출처의 동일한 관찰은 `unchanged=true`와 기존 참조를 반환한다. 바뀌지 않은 스냅샷은 도우미에서도 본문 전송을 생략한다. 새 관찰의 첫 페이지는 기본 2KiB다. 이어 읽기는 기본 8KiB이며, 한 번에 최대 16KiB를 요청할 수 있다. 긴 관찰은 현재 `result_id`와 `revision`을 사용해 `next_offset`부터 읽는다. 원문 관찰 하나는 최대 4MiB이며, 세션은 최대 16개·32MiB의 임시 관찰을 보관한다. 디스크 블록을 다 읽으면 즉시 삭제한다. 이미 지난 페이지나 아직 도달하지 않은 페이지를 요청하면 오류를 반환한다. 작업이 끝나면 모든 관찰 참조가 만료된다.

모델 응답이 완료되면 읽은 페이지와 스크린샷은 다음 결정에서 열람 표시로 바뀐다. 대화 기록에는 원본이 보존된다. Provider가 생성 전에 문맥 부족을 보고하면 이전 이력을 압축하면서 아직 읽지 않은 관찰과 이를 요청한 도구 호출을 최근 문맥에 남긴다. 에이전트는 압축 뒤에도 브라우저 세션에서 제공하는 최신 이어 읽기 커서를 사용한다. 계속 필요한 사실은 응답에 기록한다.

페이지 내용은 외부에서 온 비신뢰 데이터다. 페이지에 쓰인 지시를 사용자 지시로 따르지 않으며, 텍스트 검사만으로 실제 디자인을 검증했다고 보고하지 않는다. 캡처에는 현재 화면이 포함되므로 민감한 화면의 촬영·공유 여부도 작업 범위에 맞춰 판단한다.

[agent-browser](https://github.com/vercel-labs/agent-browser)는 Apache-2.0으로 배포되며 관리 설치에 고지를 보관한다. Chrome for Testing은 다운로드에 포함된 자체 고지를 따른다.
