# 브라우저 도구

[문서 목록](README.md) · [에이전트 작동 방식](runtime.md)

에이전트는 `browser_action`과 `browser_inspect`로 웹 페이지를 조작·검증하고, `web_fetch`로 URL에 있는 문서의 렌더링된 본문을 읽는다. TUI와 서버에서 솔로·팀이 같은 도구를 사용한다. 서버 모드에서는 서버가 실행되는 컴퓨터에서 브라우저 세션을 연다. [웹 문서 조회](web-fetch.md)

## 첫 실행과 설치

배포 아카이브를 푼 디렉터리에서 다음 명령을 실행하면 MECA 본체와 브라우저 도구를 한 번에 설치한다.

```sh
./meca install --ext browser
```

기존 설치에서는 MECA를 종료한 뒤 `meca install --ext browser`를 실행한다. 원격 서버나 컨테이너에서는 MECA를 실행할 계정으로 설치한다.

확장 설치는 본체를 준비한 뒤 `agent-browser`를 `~/.meca/browser/runtime/`에 설치한다. 기존 Chrome·Chromium을 재사용하거나 관리형 Chrome for Testing Stable을 받는다. 전용 빈 페이지에서 열기·스냅샷·종료를 확인한 뒤 실행 경로를 출력한다. 브라우저 준비가 실패하면 설치된 MECA를 사용할 수 있으며 원인을 해결한 뒤 같은 명령으로 다시 시도한다.

요청을 시작할 때 설치 상태와 실행 경로를 확인한다. `browser_action`과 `browser_inspect`는 도우미와 브라우저가 준비될 때 제공한다. `web_fetch`는 설치된 Chromium으로 URL을 입력받아 문서를 읽는다. 일반 `install`과 `upgrade`로 본체를 준비하고, 브라우저 의존성의 최초 설치는 `--ext browser`로 수행한다. 내장 WebUI에는 사용자 브라우저로 접속한다. [WebUI 사용법](webui-design.md) · [WebFetch 활성화](web-fetch.md#활성화)

- 사용자가 준비한 브라우저는 `MECA_BROWSER_EXECUTABLE`에 실행 파일의 절대 경로로 지정한다.
- macOS·Linux·WSL의 amd64·arm64에서 브라우저 설치를 지원한다. Linux·WSL에는 Chrome의 시스템 라이브러리가 필요하다. Docker에서는 `--init` 등 자식 프로세스를 회수하는 init을 사용한다. 도우미의 실행 설정에 따라 Chrome 샌드박스가 비활성화될 수 있다. [호스트 실행과 승인](execution-boundary.md)
- `meca uninstall`은 `~/.meca` 아래 관리형 도우미와 Chrome을 제거한다. 시스템 Chrome은 별도 설치본으로 유지한다.

## Stable 갱신

관리형 Chrome을 사용하는 새 세션은 마지막 확인에서 24시간이 지났으면 Stable을 조회한다. 새 버전은 공식 HTTPS 출처에서 받아 실행 버전을 검증한 뒤 사용한다. 갱신에 실패하면 기존 설치본으로 실행한다. 실행 중인 세션은 종료할 때까지 선택한 버전을 사용한다. 현재·직전 버전을 보관하고 더 오래된 버전은 사용 종료를 확인한 뒤 정리한다. [브라우저 설치와 세션 구현](optimization-strategies.md#브라우저-관찰과-세션)

## 사용 범위

`browser_action`은 열기, 뒤로/앞으로 이동, 새로고침, 클릭, 입력, 키보드, 선택, 체크, 스크롤, 요소 대기, 뷰포트 변경과 닫기를 제공한다. 셸 문자열·임의 JavaScript·개인 브라우저 프로필·외부 CDP 접속 인자는 받지 않는다. HTTP(S) 페이지를 사용하며 로컬 파일 URL과 URL 내 인증정보는 거절한다.

브라우저 도구는 system 범위에서만 실행한다. `open`으로 HTTP(S) 주소를 여는 동작은 기본 모드와 All Mighty에서 승인 없이 실행한다. 관찰·결과 이어 읽기·스크롤·요소 대기·뷰포트 변경·닫기도 승인 없이 실행한다.

클릭·입력·키 입력·선택·체크·체크 해제·호버·뒤로·앞으로·새로고침은 기본 모드에서 사용자 승인을 요청하고 All Mighty에서 자동 승인한다. 같은 기준을 루프백과 외부 페이지에 적용한다. 실행 시점에 페이지 주소가 달라졌으면 거절한다. 시간 초과 뒤에는 현재 상태를 관찰한 다음 재시도한다. [승인 모드](execution-boundary.md#자동-승인과-파일-도구)

작업마다 전용 브라우저 세션을 사용한다. 개인 프로필·기존 로그인 세션에 자동 접속하지 않는다. 작업 종료·취소와 대화 닫기는 세션·소켓·임시 관찰 자료를 정리한다. 다음 요청에서는 필요한 페이지를 다시 연다. 팀 참여자의 세션도 서로 분리한다.

동시에 열린 외부 브라우저는 MECA 프로세스당 기본 3개로 제한한다. `MECA_BROWSER_MAX_SESSIONS`(양의 정수)로 조정하며 일반 작업 동시성 옵션과 독립적이다. 용량이 차면 새 열기를 거절한다. 브라우저 작업을 끝낸 참여자가 `close`로 자원을 반환한 뒤 다시 열 수 있다. 새 세션을 열기 전 macOS의 시스템 메모리 압박 상태 또는 Linux·WSL의 가용 메모리와 cgroup v2 잔여량을 확인한다. macOS 경고·위험 상태 또는 Linux 가용량 512MiB 미만에서는 새 열기를 거절하고, 측정 실패도 오류로 알린다. 실행 중인 브라우저를 강제 종료하지 않는다. 이 제한은 입장 관리이며 Chrome의 실제 RSS 상한은 아니다.

## 관찰과 컨텍스트

`browser_inspect`의 `snapshot`은 읽을 수 있는 본문·상태와 조작 가능한 요소 참조를 반환한다. 기본 깊이는 5이며 `selector`로 영역을 좁힐 수 있다. `text`는 특정 영역의 텍스트, `errors`는 브라우저 오류, `screenshot`은 현재 뷰포트의 PNG를 제공한다. 스크린샷은 비전 입력이 가능한 모델에서 사용하며 최대 4,096,000픽셀의 PNG를 받는다. 압축 파일 크기와 픽셀 수를 확인한 뒤 디코딩하고, 전달 중인 이미지의 메모리 예약을 유지한다.

같은 출처의 동일한 관찰은 `unchanged=true`와 기존 참조를 반환한다. 바뀌지 않은 스냅샷은 도우미에서도 본문 전송을 생략한다. 새 관찰의 첫 페이지는 기본 2KiB다. 이어 읽기는 기본 8KiB이며, 한 번에 최대 16KiB를 요청할 수 있다. 긴 관찰은 현재 `result_id`와 `revision`을 사용해 `next_offset`부터 읽는다. 원문 관찰 하나는 최대 4MiB이며, 세션은 최대 16개·32MiB의 임시 관찰을 보관한다. 디스크 블록을 다 읽으면 즉시 삭제한다. 이미 지난 페이지나 아직 도달하지 않은 페이지를 요청하면 오류를 반환한다. 작업이 끝나면 모든 관찰 참조가 만료된다.

모델 응답이 완료되면 읽은 페이지와 스크린샷은 다음 결정에서 열람 표시로 바뀐다. 대화 기록에는 원본이 보존된다. Provider가 생성 전에 문맥 부족을 보고하면 이전 이력을 압축하면서 아직 읽지 않은 관찰과 이를 요청한 도구 호출을 최근 문맥에 남긴다. 에이전트는 압축 뒤에도 브라우저 세션에서 제공하는 최신 이어 읽기 커서를 사용한다. 계속 필요한 사실은 응답에 기록한다.

스냅샷 변경 감지, 임시 관찰 블록, 문맥 복원 및 설치본 사용 기록의 소유자는 [브라우저 구현 전략](optimization-strategies.md#브라우저-관찰과-세션)에서 확인한다.

페이지 내용은 외부 입력으로 취급한다. 스크린샷 촬영과 공유는 사용자 작업 범위에 맞춰 수행한다.

[agent-browser](https://github.com/vercel-labs/agent-browser)는 Apache-2.0으로 배포되며 관리 설치에 고지를 보관한다. Chrome for Testing은 다운로드에 포함된 자체 고지를 따른다.
