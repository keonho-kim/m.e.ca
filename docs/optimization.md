# 기능별 최적화

[문서 목록](README.md) · [최적화 구현 전략](optimization-strategies.md) · [개발 가이드](development.md)

MECA가 현재 적용하는 최적화와 줄이는 작업을 기능별로 정리한다. 각 구현 전략에서 담당 코드, 재사용 조건, 자원을 반환하는 시점을 확인할 수 있다.

| 기능 | 적용 기법 | 구현 전략 |
| --- | --- | --- |
| 모델 요청·문맥 | 필요한 필드만 복원하고 변경되지 않은 메시지의 투영과 인코딩을 재사용한다. 문맥이 부족하면 도구 호출 관계를 보존하며 압축한다. | [모델 문맥과 Provider](optimization-strategies.md#모델-문맥과-provider) |
| 대화 저장 | 작은 값은 인라인으로 두고 공유할 본문은 한 원본을 참조한다. 쓰기 전 인코딩과 읽기 전 바이트 예약으로 DB 잠금 및 메모리 부담을 줄인다. | [대화 저장과 SQLite](optimization-strategies.md#대화-저장과-sqlite) |
| 팀 작업 | 공용 대화와 사용자 이미지를 한 번 저장한다. 개인 문맥은 검증된 참조를 사용하고, 충돌할 수 있는 변경의 실행을 조율한다. | [팀 실행과 공용 기록](optimization-strategies.md#팀-실행과-공용-기록) |
| 셸 명령·파일 | 긴 출력은 제한된 캡처와 원문 조회로 나눈다. 같은 디렉터리의 파일 감시를 공유하고, 변경 없는 편집 문서는 본문을 다시 읽지 않고 확인한다. | [셸과 파일 작업](optimization-strategies.md#셸과-파일-작업) |
| 스킬 | 목록에는 메타데이터만 읽고, 선택한 참고 파일은 필요한 바이트 범위로 읽는다. 현재 문맥에 남아 있는 지침은 다시 삽입하지 않는다. | [스킬 목록과 참고 파일](optimization-strategies.md#스킬-목록과-참고-파일) |
| 브라우저 도구 | 변하지 않은 스냅샷은 본문 전송을 생략한다. 읽은 페이지·스크린샷은 다음 모델 문맥에서 제거하고 현재 커서와 미열람 데이터만 이어서 사용한다. | [브라우저 관찰과 세션](optimization-strategies.md#브라우저-관찰과-세션) |
| 이미지 | 디코딩 전에 크기와 자원을 검사한다. 전송할 원본과 표시용 썸네일을 분리하고 같은 저장 이미지의 동시 축소를 합친다. | [이미지와 미리보기](optimization-strategies.md#이미지와-미리보기) |
| 서버 이벤트·원문 조회 | 순서 있는 변경분만 전송하고 내장 UI의 작업·파일 관찰을 한 연결에 담는다. 동시 구독은 정제된 사건을 공유하고 상세 조회는 페이지 단위로 읽는다. | [서버 이벤트와 원문 조회](optimization-strategies.md#서버-이벤트와-원문-조회) |
| TUI | 보이는 줄을 중심으로 배치하고 스트리밍 Markdown은 바뀐 끝부분을 다시 계산한다. 입력 탐색은 문자 경계의 중간 위치를 재사용한다. | [TUI 입력과 표시](optimization-strategies.md#tui-입력과-표시) |
| WebUI | 이벤트와 본문 렌더링의 갱신을 분리한다. 이력과 파일 목록을 가상화하고, 일반 입력의 바이트 계산은 바뀐 구간만 반영한다. | [WebUI 상태와 렌더링](optimization-strategies.md#webui-상태와-렌더링) |
| 빌드·정적 자산 | 초기 화면과 나중에 필요한 코드를 나눈다. full 배포본에 사전 압축 자산을 넣고 해시 자산에 장기 캐시를 적용한다. | [빌드와 정적 자산](optimization-strategies.md#빌드와-정적-자산) |
| 운영 로그 | 비동기 출력과 반복 경고 집계로 느린 로그가 작업 실행을 지연시키는 일을 줄인다. | [운영 로그](optimization-strategies.md#운영-로그) |
