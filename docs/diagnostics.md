# 이벤트와 운영 로그

[← README](../README.md) · [서버 API](server.md) · [런타임](runtime.md)

이벤트는 프론트가 소비하는 작업 기록이고 운영 로그는 장애 원인을 추적하는 진단이다. 동일한 작업 식별자를 사용하지만 대화·도구 원문을 운영 로그에 다시 저장하지 않는다.

tui·full의 단일·팀 실행과 스킬 읽기에 같은 진단·기록 규칙을 사용한다. 외부 SSE·WebSocket·gRPC 구독과 내장 WebUI는 full에서 제공하며, tui는 터미널 표시·JSON 출력·이력 조회를 제공한다. 버그 제보에는 버전과 `meca --help`의 종류를 함께 적는다.

## 이벤트

native SSE·WebSocket·gRPC·gRPC-Web·Connect는 공통 이벤트 계약을 사용한다. 커서는 프로세스 epoch와 sequence이며 같은 커서의 재전송을 중복 적용하지 않는다. 보관 범위를 벗어나면 snapshot과 history로 복구한다.

실행 이벤트는 occurredAt과 가능한 errorCode를 제공한다. 시각은 표시용이며 순서 판단에는 커서를 사용한다. 발생 시각이 없는 기록은 조회 시각으로 대체하지 않는다. sessionId·taskId·agent·runId·generation·도구 callId를 해당 사건의 범위에 맞게 사용한다.

skill_loaded는 본문을 읽었다는 사실을 제공한다. 명시 호출은 `notice.code=SKILL_READ`와 `notice.skill`의 id·name·source·revision을, 일반 load_skill의 성공은 `tool.skill`과 도구 참조를 제공한다. 별도 본문 사본을 저장하지 않으며 프론트는 이력 조회로 사용 내역을 복원한다. 전용 활성 상태는 없다.

팀 발언·기여 선언은 작성자 본문으로, 재시도·요약·스킬 읽기는 고정 코드의 알림으로 투영한다. 제어 사건과 완료 측정에는 임의 본문을 복사하지 않는다. 공개 본문 union과 저장 경계는 [서버 계약](server.md#작업공간-자원과-파일-감시)이 소유한다.

영속 사건은 저장 확정 뒤 전달한다. 토큰 델타와 heartbeat는 별도 영속 로그로 쌓지 않는다. heartbeat의 5초 무출력 후 1초 간격, 느린 구독자 분리와 bounded replay 정책은 [서버 문서](server.md#이벤트재접속수명)를 따른다.

## 운영 로그

서버·CLI는 stderr에 JSONL, TUI는 `~/.meca/logs/run-<id>/current.jsonl`에 JSONL을 기록한다. stdout의 최종 답변·JSON 이벤트·export 형식은 유지한다. 서버 준비 로그는 `msg=server_listening`의 listen·protocol로 주소를 알리고 토큰을 포함하지 않는다. 서버 인증 토큰은 준비 완료 시 stdout에 한 번만 표시하며 운영 로그·API 이벤트에는 넣지 않는다.

기본 레벨은 info다. 프로세스 시작 때 환경변수 MECA_LOG_LEVEL=debug|info|warn|error로 선택한다. debug에서는 세부 도구·저장·제어·스트림 종료 기록을 볼 수 있다. 작업 시작·종료와 스킬 읽기, 승인 대기·결정, 느린 모델 호출·저장, 실패·재시도를 작은 메타데이터로 기록한다.

선택적인 브라우저 자동 열기 실패는 `browser_launch_failed` 경고로 구분하며 서버 실행은 유지한다. stdout에 표시한 WebUI 주소를 직접 열 수 있다. 브라우저의 첫 방문은 공개 접속 상태 조회를 사용하므로 로그인 전이라는 이유만으로 `access_rejected`를 기록하지 않는다. 실제 보호 API의 인증·Host·Origin 거절은 계속 기록한다.

주요 필드는 time·level·msg·component·operation과 request_id·session_id·task_id·run_id·agent·call_id다. 모델 호출의 generation·attempt·duration_ms, 오류 분류인 error_code를 필요한 경우 포함한다. error_code는 안전한 분류이며 raw Provider·OS·SQL 오류 전문을 뜻하지 않는다. HTTP 내부 TLS·panic 진단도 원문 대신 분류를 기록한다.

저장 할당이 한도의 90% 이상이면 storage_capacity_low에 count·limit과 near_limit/full 상태를 기록한다. 이 경고는 기존 기록이나 백업의 자동 삭제를 뜻하지 않는다. 운영 로그의 원문·비밀값 제외와 집계 정책을 동일하게 적용한다.

인증 헤더·API Key·요청/응답·Thinking·셸 출력·스킬 본문은 운영 로그에 넣지 않는다. 허용된 메타데이터만 인코딩하고 현재 요청의 자격 증명 마스킹을 적용한 뒤 필드 길이를 제한한다. 본문 원본과 상세 도구 결과는 기존 세션 저장소가 소유한다.

## 중앙 소유권과 오류

`internal/diagnostics/catalog`가 오류 코드·메시지 템플릿·복구 문구·이벤트 이름·레벨·외부 상태 변환을 소유한다. `diagnostics/fault`는 원인 연결을 유지한 오류를 만들고 분류하며, 제품 패키지는 등록한 값으로 오류를 생성하고 `diagnostics.Log`로 사건을 기록한다. slog 구현은 외부로 노출하지 않는다. `diagnostics/logfile`은 private 파일·회전·보관만 담당한다. cmd/meca는 인자 해석·Bootstrap·유지보수 전에 진단 출력을 조립한다.

합쳐진 오류에서는 저장 무결성·완료 저장 실패, 용량·권한 실패가 취소보다 우선한다. SQLite의 busy·read-only·full·corrupt·I/O 실패도 공통 분류를 사용한다. native HTTP·WebSocket·RPC와 로그가 같은 원인 분류를 사용하며, 알려지지 않은 내부 오류는 고정된 공개 문구로 표시한다. 전송 실패를 다른 오류로 바꾸거나 접수 이전 취소를 실행 중인 작업의 취소로 추정하지 않는다.

예상하지 못한 panic은 실행 소유 경계에서 고정된 내부 오류로 변환한다. panic 값은 로그나 응답에 넣지 않는다. 이미 시작했을 수 있는 도구의 효과는 재생하지 않고, 서버는 실행 상태를 신뢰할 수 없으면 새 접수를 막는다. 중앙 선언을 우회한 오류·로거 생성과 진단 필드의 임의 문구·코드는 개발 검사에서 거부한다.

## 수명과 보관

- 프로세스당 writer 하나와 최대 256건, 건당 최대 4KiB의 출력 큐를 사용한다. WARN/ERROR용 슬롯을 분리한다.
- 실행 경로는 느린 출력 완료를 기다리지 않는다. 포화 시 진단을 생략하고 dropped를 집계한다. 반복 경고는 최대 64개 키·1초 창에서 필드 인코딩 전에 집계한다. 높은 레벨 8건 뒤에는 대기 중인 낮은 레벨도 배출한다.
- 생략·집계가 있으면 1분 주기와 종료 시 diagnostics_summary를 남긴다. 출력 장애는 health 신호로 알린다. 파일 출력 장애나 누락 reporter는 준비된 stderr 경로에 고정된 사건을 한 번 시도하며, 실패한 stderr writer를 다시 호출하지 않는다. reporter 누락도 집계한다.
- 종료 시 큐를 정리하고 writer를 합류한다. 2초 안에 끝나지 않으면 소유 출력의 interrupt를 호출한 뒤 합류하며 쓰기 실패는 종료 결과에 드러낸다. 생산 환경은 소유 출력의 닫기 경로를 제공한다. stderr는 상속한 파일 속성을 유지하고 MECA가 소유한 비차단 파이프로 전송한다. 첫 쓰기에 같은 실행 파일의 전용 중계 프로세스를 시작하며, 기본 TUI 파일 로그와 쓰기 없는 실행에는 시작하지 않는다. 중계 프로세스에는 스트림과 부모 식별자만 전달하고 기존 환경변수는 전달하지 않는다. 닫을 때 최대 2초 배출 후 필요하면 종료·합류하며 부모가 비정상 종료해도 중계 프로세스가 이를 확인해 종료한다. 커스텀 Writer는 독립적으로 완료되거나 Interrupt가 쓰기를 해제해야 한다. 이는 커널·장치의 무기한 I/O 정지를 해결하는 OS 시간 보장은 아니다. 불확실하게 일부 쓴 기록은 재생하지 않는다.
- 경고 우선 배출 때문에 운영 로그 파일 순서가 사건 순서와 다를 수 있다. time과 작업 식별자로 연결한다. 작업 이벤트의 순서는 바뀌지 않는다.
- TUI는 프로세스별 private 디렉터리에서 최대 4MiB 파일 3개를 회전한다. 다른 프로세스와 같은 파일을 회전하지 않는다.
- 시작 시 종료된 과거 실행 디렉터리 8개를 남기고 오래된 디렉터리를 정리한 뒤 여유 공간을 검사한다. 회전 중 중단되어 current.jsonl이 없는 디렉터리도 MECA 파일만 있으면 정리 대상이다. 알 수 없는 파일이나 살아 있는 프로세스의 디렉터리는 보존한다. 전체 활성 프로세스에 대한 전역 디스크 quota는 아니다.

운영 로그는 제한된 진단 수단이다. 실행 결과의 영속 원본과 접수 중복 방지 기록을 대신하지 않으며, 로그 실패를 이유로 이미 수행한 작업을 자동 재실행하지 않는다.
