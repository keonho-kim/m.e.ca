# 팀 모드

[문서 목록](README.md) · [사용 가이드](usage.md) · [실행 경계](execution-boundary.md)

팀 모드는 같은 프로젝트에서 여러 에이전트가 공용 대화와 담당 범위를 공유하며 협업하는 기능이다. tui와 full 모두에서 사용할 수 있다.

## 시작과 참여

현재 대화에서 `!team`을 켠 뒤 요청한다. WebUI는 컴포저의 팀 버튼이나 설정에서 전환한다. 선택은 현재 대화에 저장하며 실행 중 변경은 다음 요청부터 적용한다.

```text
!team
API 구현과 테스트를 나눠서 진행하고 결과를 함께 검토해줘.
```

독립 세션 두 개로 시작하고 필요한 동료를 초대·복구해 동시에 최대 여덟 명이 참여한다. 각 참여자는 개인 대화·Thinking·문맥을 가지며 같은 프로젝트와 모델 연결을 사용한다. 서버의 `--concurrency`는 사용자 작업 수이고 팀원 수 설정이 아니다.

## 개발 절차

참여자는 요구사항·담당 범위·공유 규약·선행 조건을 공용 대화에서 조율한다. 한 참여자의 일방적인 선언을 전체 합의로 간주하지 않는다. 공통 선행 작업과 경계 변경은 담당자를 정해 처리한다.

합의한 범위에서 작업하고 관련 변경·실패·완료 근거를 공유한다. 모델의 업무 분할이나 역할 이름이 구현 정확성을 보장하지는 않는다. 사용자 지시와 실제 파일 상태가 작업 판단의 기준이다.

## 대화와 도구

| 팀 도구 | 목적 |
| --- | --- |
| `add_team_member` | 필요한 동료 초대 또는 닫힌 동료 복구 |
| `list_team_members` | 참여 상태·담당 업무 확인 |
| `read_team_messages` | 공용 대화 읽기 |
| `set_work` | 자기 업무·경로·공유 규약 알림 |
| `discuss` | 질문·답변·반론·대안 게시 |
| `leave_team` | 현재 작업 결과를 정리하고 퇴장 |

공개 발언은 작성자와 출처를 유지한다. `reply_to`로 관련 발언에 답하고 `mentions`로 확인할 동료를 지정할 수 있다. 발언만으로 다른 동료의 실행·업무 배정·사용자 승인을 확정하지 않는다. 개인 Thinking과 내부 모델 문맥은 공개 팀 스트림에 포함하지 않는다.

동료의 변경·도구 진행·결과를 읽고 같은 내용을 반복 실행하지 않도록 조율한다. 현재 담당 정보는 관련 작업의 판단을 돕는 정보이며 완료 증명이 아니다.

## 공유 프로젝트와 승인

같은 파일·겹친 경로의 변경은 실행 시점에서 조율한다. 관련 파일 상태가 바뀌면 아직 실행하지 않은 후보를 재검토한다. 독립 작업은 병렬로 진행할 수 있다.

프로젝트는 OS 격리 경계가 아니다. 패키지 설치·빌드·임의 셸 명령이 공유 자원에 미치는 효과는 참여자가 조율해야 한다. 파일·셸·외부 전송은 단일 모드와 같은 승인 정책을 적용한다. [승인과 보장 범위](execution-boundary.md)를 따른다.

## 종료와 재개

참여자는 남은 명령·관련 피드백·작업 결과를 확인하고 종료한다. 사용자 중지나 예산·오류 중단은 확인한 부분 결과를 보존하며, 불확실한 효과를 자동 재실행하지 않는다.

저장 대화를 재개하면 팀 선택과 참여자 기록을 복원한다. 복구가 끝난 작업의 정확성을 인증하거나 이전 프로세스를 그대로 되살리는 것은 아니다. 새 요청과 현재 프로젝트 상태를 기준으로 이어간다.

## 화면

공용 응답·업무·도구 결과는 발신자를 구분해 표시한다. 재시도·스킬 읽기 같은 알림과 완료 통계는 답변 본문과 분리한다. 팀 입·퇴장은 제어 정보이며 통계 행에 자유 문장으로 넣지 않는다.

토큰과 지원되는 비용은 실제 보고된 사용량을 합산한다. TPS는 각 모델 호출의 사용량·시간 기준이며 병렬 팀 전체의 벽시계 처리량과 다르다. 계산·표시는 [사용량 안내](usage.md#화면과-사용량)를 따른다.

## 프롬프트와 저장

팀 시스템 지침은 공통 작업 지침과 협업 규칙을 사용하고 팀 개발 지침은 설계·합의·구현·검증을 연결한다. 설치·업데이트의 프롬프트 처리와 사용자 수정 범위는 [설정 가이드](configuration.md#프롬프트와-compaction)를 따른다.

사용자 대화와 공용 기록, 참여자의 개인 기록은 관련 세션 그룹으로 보존한다. 공용 원문은 참조로 연결하므로 백업·복원에는 사용자 DB뿐 아니라 해당 팀 하위 폴더도 포함한다. [세션 보존](configuration.md#세션-저장과-복원)을 따른다.

## 자원 관리

참여자는 독립 실행 상태를 가지며 사용자 요청의 모델 호출·시간 예산을 공유한다. 공용 대화·개인 문맥·화면 투영은 각각의 목적과 수명을 유지하고 원문을 불필요하게 복제하지 않는다. 동시 작업과 읽기·표시 한도는 [설정](configuration.md)과 [서버 계약](server.md#이벤트재접속수명)을 따른다.
