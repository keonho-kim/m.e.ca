# 팀 모드

[← README](../README.md) · [사용 가이드](usage.md) · [설정과 대화 보존](configuration.md)

## 시작과 참여

`!team`은 현재 대화의 팀 모드를 켜거나 끈다. 새 대화는 단일 모드이며 선택은 해당 대화에 저장한다. 실행 중 전환하면 다음 요청부터 적용한다. 저장된 팀 대화를 비대화형으로 재개해도 같은 모드를 사용한다.

사용자 요청은 `agent-a`·`agent-b`의 독립 세션에서 시작한다. 후속 요청은 두 세션의 이력을 복구하며 필요한 동료를 초대하거나 이전 세션을 다시 열 수 있다. 동시에 열리는 세션은 시작·종료 정리 중인 세션을 포함해 최대 8개다. 별도의 동시 수 설정은 없다.

모든 에이전트는 같은 프로젝트 폴더·모델 연결·요청 시작 시 설정을 사용한다. 각자는 대화·Thinking·압축·명령 실행기를 소유한다. 티켓이나 고정된 지휘자 없이 필요한 역할과 변경 범위를 대화로 정한다.

## 대화와 도구

일반 파일·셸 도구에 다음 native 도구를 추가한다. 단일 모드에서는 이 도구를 제공하지 않는다.

| 도구 | 인자 | 동작 |
| --- | --- | --- |
| `call_friend` | `message`, 선택 `agent_id` | 새 동료 초대 또는 지정한 세션 복구 |
| `say_goodbye` | `message` | 수행 내용·실제 확인·남은 사항을 공유하고 세션 종료 |
| `list_friends` | 선택 `after_peer` | 이름·활성 여부·최근 기여 요약을 32명씩 조회 |
| `read_team_messages` | 선택 `after` | 지정한 순서 이후의 공용 대화 조회 |

일반 응답·진행 안내는 모든 동료가 읽는 공개 발언이다. 파일 변경 전에 무엇을 바꿀지와 정확한 프로젝트 기준 경로를 공유한다. 새 폴더·파일도 이름을 명시하고, 다른 동료가 발표한 변경 범위와 공유 인터페이스를 확인해 겹침을 조율한다.

`call_friend`의 메시지는 새로 초대하거나 닫힌 세션을 복구할 때만 전달한다. 이미 활성인 동료를 지정하면 현재 상태만 반환하며 추가 지시를 보내거나 재실행하지 않는다. 자리가 없으면 도구가 현재 수용 상태를 반환한다. 과거 동료 목록은 필요한 페이지만 읽는다.

공용 대화는 완료한 메시지만 순서대로 저장한다. 각 에이전트는 모델 판단 전·도구 후·압축 직후·최종 응답 확정 전에 읽지 않은 대화를 받는다. 새로운 동료 발언은 생성 중인 응답을 취소하지 않으며 다음 판단에 반영한다. 실제 사용자 방향 수정이 도착하면 이전 요청으로 생성한 미실행 후보를 다시 판단한다. 동료 발언은 출처가 붙은 관측이며 사용자 지시나 실행 승인 권한을 갖지 않는다.

도구 결과·Thinking 전체를 동료에게 방송하지 않는다. 필요한 결과를 짧은 발언으로 공유하고 자신의 원본 기록은 세션에서 유지한다. 공용 대화의 조회는 페이지 단위이며 새 메시지가 없으면 반복 조회하지 않는다.

## 공유 프로젝트와 승인

같은 경로·상하위 경로·동일 inode의 파일 변경은 겹치지 않게 실행하고, 실행 직전 원본 버전을 다시 검사한다. 독립 파일 변경은 제한된 동시 실행으로 처리한다. 대기 중 사용자 방향 수정이 도착하면 해당 후보를 실행하지 않고 재판단을 요청한다.

임의 셸 명령은 부작용 범위를 미리 확정하기 어려우므로 팀 전체에서 한 번에 하나씩 실행하고 전용 파일 변경과도 겹치지 않는다. 공유 접근을 기다리는 호출에는 대기 상태를 표시한다. 큰 파일 후보·diff를 준비하기 전에 대상 접근을 예약하고 준비 실패·승인 거절·취소에서도 예약을 해제한다. 경로 별칭이 바뀌면 실행하지 않고 현재 대상을 다시 확인하도록 반환한다. 실제 명령이 시작한 뒤의 최초 대기는 30초이며, 계속 실행 중이면 기존 `command_id`와 조회·대기·취소 도구를 사용한다. `running`을 반환해도 실제 명령과 출력 보관·캡처 정리가 끝날 때까지 공유 접근을 유지한다. 완료 신호로 예약을 해제하며 에이전트의 결과 수집을 기다리지 않는다. 다른 에이전트의 명령 ID로 프로세스를 제어할 수 없다.

일반 실행 정책·보호 경로·외부 전송 승인·파일 원본 검사를 적용한다. 승인 요청은 한 번에 하나씩 표시하고 같은 요청에서 거절한 후보는 다른 동료를 통해 그대로 실행할 수 없다. 같은 의미의 모든 셸 문자열을 식별하는 보장은 아니다.

이 조율은 MECA가 관리하는 실행 간의 충돌을 줄인다. 공유 폴더를 사용하는 다른 프로그램이나 이미 끝난 변경의 의미적 덮어쓰기까지 방지하는 OS 격리 기능은 아니다. 변경 전 현재 내용을 확인하고 동료와 범위를 조율해야 한다. [실행 경계](execution-boundary.md)를 함께 따른다.

## 종료와 재개

일반 응답은 공개 발언이며 다른 동료의 결과를 기다릴 수 있다. 대기 중에는 같은 실행의 문맥·연결 범위를 유지하고 실제 새 대화가 있을 때만 모델 판단을 재개한다. 이미 소비한 알림은 추가 모델 요청을 만들지 않는다. 기여가 끝난 에이전트는 활성 명령을 정리한 뒤 `say_goodbye`로 나간다. 종료 과정은 원본 호출·결과를 저장하고 실행기·연결 범위·DB·메모리 참조를 정리한 후 자리를 반환한다.

마지막 한 명에게는 도구 결과가 사용자 보고를 요청한다. 새 동료를 부르거나 필요한 작업을 이어갈 수 있으며, 남은 메시지와 종료 중인 동료를 확인한 뒤 최종 답변을 확정한다. 마지막 보고도 한 세션만 수행하고 보고 후 닫는다. 다음 사용자 요청은 초기 두 세션에서 이어간다.

Esc는 현재 요청의 모든 팀 작업·명령을 취소하고 종료를 기다린다. 실제 수행한 변경·관측·부분 응답은 보존한다. 오류로 멈춘 동료를 자동으로 재생성하거나 부작용을 재실행하지 않는다. 공용 저장·전달 오류는 요청을 중지하고 반환한다.

`[loop]`의 모델 요청 수와 전체 시간 예산은 팀 전체가 공유하며 재시도·압축도 포함한다. 에이전트 수만큼 예산을 늘리지 않는다. 독립된 모델 문맥을 사용하므로 실제 토큰·비용은 동료 수와 작업량에 따라 증가한다.

## 화면

하나의 대화 영역에 응답과 도구 결과를 스트리밍한다. 발언은 `agent-a`, 최종 답변은 `agent-c · 작업 결과`로 표시한다. 사용자의 요청은 `> 요청`이며 별도의 전체 수신자 표시는 없다.

참여·퇴장은 흐린 안내로 표시한다. 팀 Thinking은 화면에 표시하지 않고 개인 기록에 보관한다. 모델의 Thinking 설정 자체는 유지한다. 일반 도구 결과는 기본 접힘이며 `Ctrl+O`로 펼친다. 대화·초대·퇴장 도구는 공용 발언과 참여 안내로 표시해 같은 내용을 도구 카드로 반복하지 않는다.

모델 상태에는 현재 활성 수를 `팀 N/8`로 표시한다. 토큰과 OpenRouter 비용은 팀의 실제 수신량을 중복 없이 합산한다. 소요 시간은 요청 전체의 벽시계 시간이다. 평균 TPS는 출력 합계를 각 모델 호출의 측정 시간 합계로 나눈 값이며 병렬 호출의 겹친 시간도 각 호출에 포함한다.

## 프롬프트와 저장

프롬프트는 `~/.meca/prompts/single/`과 `~/.meca/prompts/team/`으로 분리한다. 각 폴더에 `system.md`·`development.md`·`compaction.md`가 있다. 시스템 지침은 역할에 맞게 구분하고 개발·요약 기본본은 같은 내용을 별도 파일로 제공한다. 요청 시작 때 선택한 지침과 프로젝트 `AGENTS.md`를 읽고 압축 이후 모델 요청에도 제공한다.

사용자 대화 DB는 공용 대화·사용량·최종 보고·참여자 이름과 세션 ID를 보관한다. 개인 대화는 해당 프로젝트 세션 폴더의 `.team/<사용자 세션 ID>/<프로젝트 키>/` 아래 별도 DB에 보관한다. 대화 선택 목록에는 사용자 대화만 표시한다.

개인 문맥이 받은 큰 공용 본문과 공용 화면의 도구 이력은 원본을 참조한다. 짧은 본문은 참조의 고정 비용보다 작으므로 직접 저장한다. 개인 문맥은 64건씩 읽고 큰 공용 본문은 일반 문맥과 압축 입력 모두 페이지별로 모아 조회·검증한다. 도구 이력의 개인 원본도 세션별로 모아 읽으며 조회 핸들과 임시 본문 재사용에 한도를 둔다. 확보한 메타데이터는 DB를 다시 열지 않고 투영하며 추가 payload가 필요한 경우만 연결을 사용한다.

참여자 레지스트리는 별도 멤버 행으로 보관하고 팀 모드는 사용자 대화에 저장한다. 새 개인 DB 생성과 멤버 등록은 저장 계층이 함께 수행하며 등록 실패 시 확인된 미등록 새 DB만 정리한다. 수신 위치는 개인 문맥과 한 트랜잭션으로 기록하고 복원 시 원문 길이·해시를 검사한다. 개인 DB만 따로 옮기거나 참조한 원본을 지우면 복원할 수 없으므로 대화를 보존할 때 관련 `.team` 폴더도 함께 보존한다. JSONL 내보내기는 참조한 도구 원본을 복원한다.

## 자원 관리

팀 모델 인코딩 캐시는 개인 실행당 최대 2MiB를 보유하며 8개 실행의 합계 예산은 16MiB다. 입력 수용 한도와 별개이며 초과 입력도 전송한다. 예산을 넘는 대화도 앞부분의 완전한 그룹을 유지하고 초과 조각은 전송 본문 수명 동안만 보유한다. 닫힌 세션은 DB·실행기·인코딩 참조를 해제한다. 공용 발언은 요청이 소유한 최대 128건·2MiB의 불변 창에서 수신자끼리 본문을 공유한다. 수신자 문맥 메타데이터는 각각 복사하고 오래된 기록과 창보다 큰 본문은 SQLite로 읽는다.

팀 화면은 tui/chat/team이 순수 상태로 관리하며 세션은 입력·시계·설정 저장을 연결한다. 팀 스트림은 발신자와 본문을 별도 블록으로 관리하고 본문의 증분 Markdown 상태를 재사용한다. 화면의 파생 캐시는 활성 스트림을 포함해 공통 예산을 적용하고 종료·취소 때 증분 상태를 해제한다. 큰 완료 응답은 텍스트·스타일 경계 배열로 작게 보관해 스크롤 때 전체 문서를 다시 파싱하지 않고 가시 행을 구체화한다. 예산에 들어가는 표현만 유지하고 화면 밖 캐시는 해제한다. 접힌 도구 카드는 요약과 원본 참조만 보유하고 펼칠 때 보이는 결과를 단일 조회 worker로 읽는다. 다시 접으면 상세 문자열과 diff 배치 참조를 해제한다. 화면 원문 예산에는 diff 범위 배열의 보유 용량도 포함하며, 예산 초과 시 화면 밖에서 재조회 가능한 상세 내용부터 해제하고 요약과 원본 참조를 남긴다. 채팅 경계에서 숨길 끝 빈 줄은 행 배열을 만들기 전에 줄이고 저장 원문과 파일 미리보기는 보존한다.
