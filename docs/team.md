# 팀 모드

[← README](../README.md) · [사용 가이드](usage.md) · [설정과 대화 보존](configuration.md)

## 시작과 참여

`!team`은 현재 대화의 팀 모드를 켜거나 끈다. 새 대화는 단일 모드이며 선택은 해당 대화에 저장한다. 실행 중 전환하면 다음 요청부터 적용한다. 저장된 팀 대화를 비대화형으로 재개해도 같은 모드를 사용한다.

사용자 요청은 이름이 부여된 두 독립 세션에서 시작한다. 중국·일본·한국·영어권·인도 이름을 영문 표기로 담은 고정 목록 100개에서 같은 대화에 사용하지 않은 이름을 선택한다. 이름은 멤버 행에 저장하며 재개해도 유지한다. 시스템 지침은 각자의 이름을 알려 주고 현재 동료 이름과 담당 영역은 모델 판단마다 관측으로 제공한다. 후속 요청은 초기 두 세션의 이력을 복구하며 필요한 동료를 초대하거나 이전 세션을 다시 열 수 있다. 동시에 열리는 세션은 시작·종료 정리 중인 세션을 포함해 최대 8개다. 별도의 동시 수 설정은 없다.

모든 에이전트는 같은 프로젝트 폴더·모델 연결·요청 시작 시 설정을 사용한다. 각자는 대화·Thinking·압축·명령 실행기를 소유한다. 티켓이나 고정된 지휘자 없이 필요한 역할과 변경 범위를 대화로 정한다.

## 대화와 도구

일반 파일·셸 도구에 다음 native 도구를 추가한다. 단일 모드에서는 이 도구를 제공하지 않는다.

| 도구 | 인자 | 동작 |
| --- | --- | --- |
| `add_team_member` | `message`, 선택 `member_name` | 새 동료 초대 또는 지정한 세션 복구 |
| `leave_team` | `message` | 수행 내용·실제 확인·남은 사항을 공유하고 세션 종료 |
| `list_team_members` | 선택 `after_member` | 이름·활성 여부·현재 담당 경로·최근 기여 요약을 32명씩 조회 |
| `read_team_messages` | 선택 `after` | 지정한 순서 이후의 공용 대화·실제 작업 관측 조회 |
| `set_work` | `summary`, `paths`, 선택 `contract`, `reply_to` | 자기 업무의 결과·경로·공유 규약을 공개. 빈 경로는 담당 해제 |
| `discuss` | `message`, 선택 `reply_to`, `mentions` | 질문·반론·대안을 전체에 공개하고 즉시 반환 |

일반 응답·진행 안내는 모든 동료가 읽는 공개 발언이다. 시작·재개 시 첫 파일·셸·이미지 도구 전에 맡을 기여와 프로젝트 기준 대상 경로를 짧게 알린다. 경로를 모르면 조사할 범위를 먼저 밝히고 쓰기 전에 실제 변경·경로를 구체화한다. 발언과 도구 호출은 같은 응답에 포함할 수 있다. 일반 응답·성공한 `discuss`·업무 알림을 자기 공개 발언으로 인정한다. 공개 발언 없이 첫 작업을 요청하면 실행 전에 구체적인 피드백을 반환하며, 발언을 포함해 다시 진행할 수 있다. 명령 대기·취소·조회와 동료·대화 조회 도구는 계속 사용할 수 있다.

동료는 수평적으로 자기 작업을 선택하고 서로의 접근법을 자유롭게 검토한다. 담당자가 없는 독립 기여가 추가로 필요하면 `add_team_member`로 동료를 초대한다. 관련된 동료의 실제 발언을 근거로 이름을 부르고 각자 맡을 파일·책임과 의존 관계를 알린다. 미할당 작업은 구체적인 범위를 알리고 같은 차례에 조사·업무 알림·실행으로 이어간다. 등록이 성공하면 별도의 동료 확인을 기다리지 않는다. 공유 인터페이스·이름·기대 동작은 `contract`로 알리며 이는 해당 동료의 현재 제안이다. 다른 동료의 동의나 실제 구현 완료를 뜻하지 않는다.

`discuss`는 구체적인 질문·답변·반론·대안·발견에 사용한다. 동료의 질문에는 `reply_to`로 그 질문을 지정해 답변하며, 일반 진행 발언과 구분해 대기 중인 질문자에게 전달한다. `reply_to`는 같은 사용자 대화의 공개 발언 순서이며 발신자와 당시 관측 범위는 실행기가 지정한다. `mentions`는 확인이 유용한 동료 이름이다. 지목되지 않은 동료도 내용을 읽고 토론에 참여할 수 있다. 게시 후 즉시 반환하며 상대에게 업무를 배정하거나 답변을 기다리지 않는다. 닫힌 동료를 언급해도 세션을 복구하지 않는다. 일반 진행·단순 확인은 응답 텍스트로 전하고 같은 내용을 도구와 본문에 반복하지 않는다. 의견은 근거로 판단하고 수용·반박·추가 확인을 공개한다. 제안을 반영한 `set_work` 갱신도 `reply_to`로 연결할 수 있다.

`add_team_member`의 메시지는 새로 초대하거나 닫힌 세션을 복구할 때만 전달한다. 이미 활성인 동료를 지정하면 현재 상태만 반환하며 추가 지시를 보내거나 재실행하지 않는다. 자리가 없으면 도구가 현재 수용 상태를 반환한다. 과거 동료 목록은 필요한 페이지만 읽는다. 새 개인 세션 준비 중에도 공용 대화와 사용자 지시는 계속 게시할 수 있다. 초대 확정 전에 최신 지시를 다시 확인하며, 게시 전에 취소된 새 세션은 사용 이력이 없는지 확인한 뒤 등록과 DB 파일을 정리한다. 이미 게시했거나 작업 기록이 있는 세션은 보존한다.

공용 대화는 완료한 메시지만 순서대로 저장한다. 각 에이전트는 모델 판단 전·도구 응답 묶음이 끝난 뒤·압축 직후·최종 응답 확정 전에 읽지 않은 대화를 받는다. 같은 native 응답의 호출·결과 묶음 사이에는 동료 대화를 끼워 넣지 않으며, 각 후보의 최신 사용자 지시와 담당 경로 검사는 별도로 유지한다. 발신자가 표시된 대화 본문을 관측으로 제공하며 자신의 응답이나 실행할 도구 호출로 취급하지 않는다. 새로운 동료 발언은 생성 중인 응답을 취소하지 않으며 다음 판단에 반영한다. 사용자 지시의 공개 순서 번호를 모델 판단 시점에 고정한다. 같은 문장의 새 지시도 번호가 바뀌면 미실행 후보를 다시 판단한다. 여러 도구 호출은 각 실행 묶음 사이에서도 새 지시를 확인하고, 이미 완료한 결과를 보존하며 남은 후보를 보류한다. 파일 효과와 동료 초대·업무 변경·토론·퇴장은 같은 판단 기준을 사용한다. 수신 위치만 전진해도 새 모델 판단 전에는 이전 후보가 유효해지지 않는다. 동료 발언은 사용자 지시나 실행 승인 권한을 갖지 않는다.

도구 결과·Thinking 전체를 동료에게 방송하지 않는다. 커밋한 파일 변경·명령 상태·종료 코드·실패 요약과 원본 참조를 짧은 관측으로 자동 공유한다. 담당 경로·실제 파일 변경은 관련 영역의 동료에게 판단 재개를 알린다. 공유 규약의 변경·삭제와 답글 대상·영향 범위가 불명확한 관측은 보수적으로 알린다. 경로와 규약이 같은 설명 문구 변경은 공개 대화로 보존하되 추가 재검토나 퇴장 보류를 유발하지 않는다. 직접 답글은 계속 대상 동료에게 알린다. 모든 동료에게 공개 원문을 전달하는 동작은 동일하다. 새 토론은 지목한 동료에게, 지정이 없으면 전체에 알리며 답변은 원래 발신자와 지목한 동료에게 알린다. 일반 진행 발언은 다음 정상 판단에 전달하고 이것만으로 추가 추론을 요구하지 않는다. 변경 경로나 실패를 관측하지 않은 명령 상태는 활성 멤버별 최신 한 건을 다음 정상 판단에 전달한다. 원본 로그는 보존하고 개인 이력에 반복 추가하지 않으며 그 기록만으로 추가 추론을 요구하지 않는다. 같은 실행 중 상태와 완료된 명령의 보관 결과 재조회는 공개 관측을 반복하지 않는다. 서로 다른 호출의 동일한 실패는 각각 원본 기록과 수신 대화에 보존하면서 최근 근거 창 안에서는 재검토 알림을 반복하지 않는다. 실제 변경 또는 영향 가능 경로가 있으면 같은 결과여도 관련 동료에게 알린다. 자신이 실행한 결과·업무 알림·discuss 발언은 본인에게 다시 주입하지 않는다. 실제 수정 경로를 관측하지 못한 셸 명령은 파일 변경을 추측하지 않는다. 원본 출력은 개인 세션에서 유지하고 필요한 추가 결과를 공개 발언으로 공유한다. 자동 관측은 모델·대화 조회에 제공하고 TUI 전달 큐에 넣지 않아 이미 있는 도구 카드와 중복 출력하지 않는다. 공용 대화의 조회는 페이지 단위이며 새 메시지가 없으면 반복 조회하지 않는다. 수신 페이지는 본문·규약·경로를 포함해 16MiB 예산으로 나누며, 이를 넘는 단일 발언도 누락 없이 한 건씩 전달한다.

현재 현황은 공개 대화와 같은 경계에서 캡처해 모델 판단 동안 고정한다. 현재 원문 대화에 있는 업무·의견은 현황에서 참조 중심으로 제공한다. 압축으로 원문이 빠지면 필요한 짧은 내용을 다시 제공한다. 멤버별 최근 의견은 원문 참조와 짧은 미리보기로 제공하며 제안·반론을 팀 합의로 확정하지 않는다. 압축 직후에도 새 대화와 현황을 다시 수신하며 요약은 사용자 요청·실제 작업·관련 규약·남은 이견을 보존한다.

## 공유 프로젝트와 승인

파일·디렉터리를 변경하기 전에 `set_work`로 구체적인 경로를 등록한다. 프로젝트 전체와 그 상위 경로는 담당 영역으로 등록하지 않는다. 겹치면 담당자의 이름·경로를 반환하고 기존 담당 영역은 유지한다. 현재 기여는 제공된 현황이나 `list_team_members`로 확인한다. 대기열에 넣거나 자동으로 소유권을 가져오지 않으며, 이름을 부르고 인계를 협의하거나 다른 부분을 맡는다. 빈 `paths`로 담당 영역을 해제할 수 있으며 이것만으로 완료를 뜻하지 않는다. 활성 명령이 있으면 경로를 바꾸거나 해제하기 전에 정리한다. 같은 경로의 설명·규약은 실행 중에도 갱신할 수 있다. 읽기·검토는 소유권 없이 가능하다. 요약·경로·규약은 공개 대화로 표시하고 도구 결과에는 이름·경로·공개 순서·업무 revision을 반환한다. 후보를 검증하고 공개 기록을 저장한 뒤 현재 업무를 교체하므로 저장 실패는 기존 영역을 유지한다.

정규화한 대상이 현재 담당 영역에 속하는지 준비 전과 실행 직전에 검사한다. 셸은 기존 AST에서 식별한 변경 경로에 같은 검사를 적용하며 임의 프로그램의 모든 파일 효과를 추정하지 않는다. 식별한 셸 변경 대상은 실행 후 영향 가능 경로로 구분해 공유한다. 다른 동료가 마지막 모델 판단 뒤 관련 경로를 변경했거나 영향을 주었을 수 있으면 후보를 실행하지 않고 최신 결과·파일을 읽어 재생성하도록 반환한다. 관련 없는 발언이나 변경은 후보를 취소하지 않는다.

같은 경로·상하위 경로·동일 inode의 파일 변경은 겹치지 않게 실행하고, 실행 직전 원본 버전을 다시 검사한다. 독립 파일 변경은 제한된 동시 실행으로 처리한다. 대기 중 사용자 방향 수정이 도착하면 해당 후보를 실행하지 않고 재판단을 요청한다.

임의 셸 명령은 부작용 범위를 미리 확정하기 어려우므로 팀 전체에서 한 번에 하나씩 실행하고 전용 파일 변경과도 겹치지 않는다. 자기 세션에 활성 명령이 있으면 다른 명령·파일 변경을 공유 접근 대기에 넣기 전에 `wait_command`·`cancel_command`·`list_command_runs` 안내를 반환한다. 다른 동료의 공유 접근을 기다리는 호출에는 대기 상태를 표시한다. 새 사용자 지시가 도착하면 접근권을 아직 받지 않은 후보의 대기를 즉시 중단해 재판단하도록 반환한다. 다른 동료가 보유한 접근권과 이미 실행 중인 명령은 유지한다. 큰 파일 후보·diff를 준비하기 전에 대상 접근을 예약하고 준비 실패·승인 거절·취소에서도 예약을 해제한다. 경로 별칭이 바뀌면 실행하지 않고 현재 대상을 다시 확인하도록 반환한다. 실제 명령이 시작한 뒤의 최초 대기는 30초이며, 계속 실행 중이면 기존 `command_id`와 조회·대기·취소 도구를 사용한다. `running`을 반환해도 실제 명령과 출력 보관·캡처 정리가 끝날 때까지 공유 접근을 유지한다. 완료 신호로 예약을 해제하며 에이전트의 결과 수집을 기다리지 않는다. 다른 에이전트의 명령 ID로 프로세스를 제어할 수 없다.

요청이 소유한 이미지 디코딩 permit은 한 개이며 파일 변경 예약과 독립적으로 공유한다. 일반 실행 정책·보호 경로·외부 전송 승인·파일 원본 검사를 적용한다. 승인 요청은 한 번에 하나씩 표시하고 같은 요청에서 거절한 후보는 다른 동료를 통해 그대로 실행할 수 없다. 같은 의미의 모든 셸 문자열을 식별하는 보장은 아니다.

이 조율은 MECA가 관리하는 실행 간의 충돌을 줄인다. 공유 폴더를 사용하는 다른 프로그램이나 이미 끝난 변경의 의미적 덮어쓰기까지 방지하는 OS 격리 기능은 아니다. 변경 전 현재 내용을 확인하고 동료와 범위를 조율해야 한다. [실행 경계](execution-boundary.md)를 함께 따른다.

## 종료와 재개

일반 응답은 공개 발언이며 다른 동료의 결과를 기다릴 수 있다. 지침은 가능한 독립 작업을 먼저 진행하고, 다음 필수 작업을 막는 구체적인 결과·담당 경로·결정만 대기하도록 한다. 대기가 필요하면 대상 동료와 의존성을 한 번 밝히고 응답을 마친다. 대기 중에는 같은 실행의 문맥·연결 범위를 유지하고 자신에게 주의가 필요한 토론·사용자 지시·업무 변경·실패가 있을 때 모델 판단을 재개한다. 모든 활성 동료가 대기하고 실행 중인 명령과 미처리 알림이 없으면 한 동료가 남은 작업·종료 여부를 한 번 재판단한다. 새 사용자 지시·담당 경로와 공유 규약·실제 파일 결과·새로운 명령 출력이나 오류·새 참여를 진전 근거로 사용한다. 내용 없는 성공 명령, 같은 결과·규약으로의 반복 복귀, 설명 문구만의 변경은 재판단 기회를 갱신하지 않는다. 최근 근거는 요청별 고정 크기 64개 해시 창으로 중복을 판별한다. 명령 ID·로그 경로·경과 시간은 근거의 동일성에 포함하지 않는다. 명시적인 수집·실행 실패는 출력이 없고 종료 코드가 0이어도 실패 근거에 포함하며 오류 코드와 실제 원인으로 구분한다. 진전 없이 모두 다시 대기하면 정체를 명시적으로 반환하고 요청을 종료한다. 주기적인 재추론은 하지 않는다. 개별 대기는 모델 호출을 만들지 않으며, 진행 중인 모델 생성의 Thinking 길이를 제한하지는 않는다. 이미 소비한 알림과 단순 명령 상태는 추가 모델 요청을 만들지 않는다. 사용자 방향 수정은 입력 알림으로 즉시 읽는다. 답변 경계는 멤버별 최신 알림 순서와 마지막 모델 판단 순서를 비교하며 대화 DB를 조회하지 않는다. 알림은 전달·추론 필요성만 뜻하고 의견 수용이나 동의를 뜻하지 않는다. 기여가 끝난 에이전트는 활성 명령을 정리한 뒤 `leave_team`로 나간다. 다른 동료가 남아 있을 때 마지막 모델 판단 이후 관련 피드백이 있으면 퇴장을 보류하고 이를 검토하도록 반환한다. 마지막 동료의 호출은 종료 대신 최종 보고를 요구하며, 남은 대화를 확인한 뒤 보고한다. 종료 과정은 담당 영역의 요청 내 참조를 해제하고 원본 호출·결과를 저장하며 실행기·연결 범위·DB·메모리 참조를 정리한 후 자리를 반환한다. 명령 관측 상태는 실행 중인 명령만 보유하고 첫 완료 공유 뒤 해제한다.

마지막 한 명에게는 도구 결과가 사용자 보고를 요청한다. 새 동료를 부르거나 필요한 작업을 이어갈 수 있으며, 남은 메시지와 종료 중인 동료를 확인한 뒤 최종 답변을 확정한다. 마지막 보고도 한 세션만 수행하고 보고 후 닫는다. 다음 사용자 요청은 초기 두 세션에서 이어간다.

Esc는 현재 요청의 모든 팀 작업·명령을 취소하고 종료를 기다린다. 실제 수행한 변경·관측·부분 응답은 보존한다. 오류로 멈춘 동료를 자동으로 재생성하거나 부작용을 재실행하지 않는다. 공용 저장·전달 오류는 요청을 중지하고 반환한다.

`[loop]`의 모델 요청 수와 전체 시간 예산은 팀 전체가 공유하며 재시도·압축도 포함한다. 에이전트 수만큼 예산을 늘리지 않는다. 독립된 모델 문맥을 사용하므로 실제 토큰·비용은 동료 수와 작업량에 따라 증가한다.

## 화면

하나의 대화 영역에 응답과 도구 결과를 스트리밍한다. 일반 발언은 `Hana`, 답변·지목된 의견은 `Ren · Hana에게`, 여러 수신자는 `Ren · Hana, Arjun에게`, 최종 답변은 `Arjun · 작업 결과`로 표시한다. 업무 알림은 작업 경로와 함께 맞출 내용을 본문에 보여주며 내부 발언 번호·revision은 기본 화면에 표시하지 않는다. 사용자의 요청은 `> 요청`이며 별도의 전체 수신자 표시는 없다.

응답 내용이 생기면 발신자 이름표와 본문을 함께 표시한다. 이름 아래에는 빈 줄 한 개, 본문 뒤에는 빈 줄 두 개를 표시한다. 여백은 원문 복사·저장 없이 레이아웃으로 구성하며 실시간 응답·도구 카드·저장 이력에 같은 간격을 적용한다. 공백뿐인 응답은 이름표를 만들지 않는다. 에이전트별 스트림과 도구 호출은 독립된 표시 ID를 사용한다. 화면 이력의 수·메모리 예산으로 기록을 정리할 때 이름표와 본문을 함께 제거하며, 계속되는 응답은 같은 발신자와 함께 복원한다. 저장된 이력을 다시 열 때도 같은 규칙으로 표시한다.

참여·퇴장은 흐린 안내로 표시하며 퇴장은 성공·실패와 무관하게 중립적인 문구를 사용한다. 팀 Thinking은 표시용 스트림 처리를 생략하고 종료·취소 시 마스킹한 개인 기록에 보관한다. 모델의 Thinking 설정 자체는 유지한다. 일반 도구 결과는 기본 접힘이며 `Ctrl+O`로 펼친다. 대화·토론·초대·업무 알림·퇴장 도구는 공용 발언과 참여 안내로 표시해 같은 내용을 도구 카드로 반복하지 않는다.

모델 상태에는 현재 활성 수를 `팀 N/8`로 표시한다. 토큰과 OpenRouter 비용은 팀의 실제 수신량을 중복 없이 합산한다. 소요 시간은 요청 전체의 벽시계 시간이다. 평균 TPS는 측정된 출력 합계를 각 모델 호출의 측정 시간 합계로 나눈 값이며 병렬 호출의 겹친 시간도 각 호출에 포함한다. 진행 스냅샷은 교체하고 완료 호출은 한 번 합산하므로 동료 퇴장·새 모델 호출·도구 대기에도 유효한 평균을 유지한다. 첫 측정 전에는 항목을 숨기며 토큰 수를 추정하지 않는다.

## 프롬프트와 저장

프롬프트는 `~/.meca/prompts/single/`과 `~/.meca/prompts/team/`으로 분리한다. 각 폴더에 `system.md`·`development.md`·`compaction.md`가 있다. 시스템 지침은 역할에 맞게 구분하고 개발·요약 기본본은 같은 내용을 별도 파일로 제공한다. 요청 시작 때 선택한 지침과 프로젝트 `AGENTS.md`를 읽고 압축 이후 모델 요청에도 제공한다.

첫 실행은 없는 기본 파일을 생성한다. `meca install`과 업그레이드는 두 프로필을 해당 바이너리의 기본본으로 갱신한다. 기존 프롬프트 파일이 있는 상태에서 바이너리만 교체해 실행하면 저장된 파일을 읽으므로, 새 기본 지침을 사용하려면 새 바이너리로 설치를 수행한다.

사용자 대화 DB는 공용 대화·사용량·최종 보고·참여자 이름과 세션 ID를 보관한다. 개인 대화는 해당 프로젝트 세션 폴더의 `.team/<사용자 세션 ID>/<프로젝트 키>/` 아래 별도 DB에 보관한다. 대화 선택 목록에는 사용자 대화만 표시한다.

개인 실행 결과가 저장되면 공용 DB의 원본 참조와 자동 관측을 한 트랜잭션으로 기록한다. 둘 중 하나가 실패하면 함께 롤백한다. 이미 실행된 결과의 원본 참조는 취소 후에도 제한된 저장 시간 안에서 확정한다. 화면에는 저장을 마친 원본 결과를 전달한다.

자기가 성공적으로 게시한 `discuss`·`set_work`의 압축 자료도 기존 이벤트의 공개 순서 참조로 구성한다. 압축할 때 원문을 모아 읽으며 의견 본문을 별도 요약 컬럼에 복제하지 않는다. 참조가 사라지면 오류를 반환한다. 개인 문맥이 받은 큰 공용 본문과 공용 화면의 도구 이력은 원본을 참조한다. 본문 해시·JSON 인코딩 길이는 최대 128건·본문 2MiB 안에서 공유하고 마지막 실행용 개인 DB 핸들이 닫히면 해제한다. 과거 기록 조회용 연결은 이 사용권을 갖지 않는다. 마스킹으로 내용이 바뀌면 로컬 본문으로 보관한다. 짧은 본문은 참조의 고정 비용보다 작으므로 직접 저장한다. 개인 문맥은 64건씩 읽고 큰 공용 본문은 일반 문맥과 압축 입력 모두 페이지별로 모아 조회·검증한다. 도구 이력의 개인 원본도 세션별로 모아 읽으며 조회 핸들과 임시 본문 재사용에 한도를 둔다. 확보한 메타데이터는 DB를 다시 열지 않고 투영하며 추가 payload가 필요한 경우만 연결을 사용한다.

참여자 레지스트리는 별도 멤버 행으로 보관하고 팀 모드는 사용자 대화에 저장한다. 저장 계층은 개인 DB 준비를 공용 트랜잭션 밖에서 마친 뒤 이름·순서·세션 연결을 짧은 트랜잭션으로 등록한다. 등록 실패 시 확인된 미등록 새 DB만 정리한다. 수신 위치는 개인 문맥과 한 트랜잭션으로 기록하고 복원 시 원문 길이·해시를 검사한다. 개인 DB만 따로 옮기거나 참조한 원본을 지우면 복원할 수 없으므로 대화를 보존할 때 관련 `.team` 폴더도 함께 보존한다. JSONL 내보내기는 참조한 도구 원본을 복원한다.

## 자원 관리

담당 상태는 최대 8명의 현재 기여만 보유하고 교체·퇴장 때 이전 경로 참조를 해제한다. 동일한 담당 선언과 이미 해제된 영역의 재해제는 공개 대화를 추가하거나 동료를 깨우지 않는다. 최신 파일 변경 순서는 경로당 한 건만 유지하며 모든 활성 판단이 확인한 항목은 제거한다. 확인 지점이 그대로면 정리를 반복하지 않고 이미 확인한 변경은 검사에서 전체 순회를 생략한다. 희소해진 큰 인덱스는 남은 항목에 맞춰 줄인다.

현재 담당 현황은 모델 요청에만 투영하고 매 판단마다 SQLite에 복제하지 않는다. 멤버·담당 revision·최신 명령 관측·최근 의견이 같으면 요청이 소유한 불변 현황 하나를 재사용한다. 현황 구성은 공유 상태 잠금 밖에서 한 번에 하나만 수행하며 개인정보 마스킹은 개인 문맥의 비밀키 revision에 맞춰 재사용한다. 반복 주입은 멤버별 요약·공유 규약 각각 4KiB·경로 24KiB·최신 일반 명령 관측·최근 의견 각각 2KiB 예산으로 구성하고 생략 표시를 남긴다. 멤버 조회도 업무 요약을 4KiB로 투영하고 전체 담당 경로는 유지한다. 현재 상태는 멤버별 설명·규약 미리보기와 원문 순서·내용 해시를 보유한다. 긴 설명의 해시·미리보기 구성은 공유 잠금 밖에서 수행한다. 전체 선언은 공개 원문, 전체 담당 경로는 `list_team_members`로 조회하며 실제 소유권 검사는 전체 경로 집합을 사용한다. 입력 수용 한도와 실행 권한을 이 표시 예산으로 제한하지 않는다. 새 테이블·티켓·주기적 추론을 만들지 않으며 요청 종료에서 상태 전체를 해제한다.

팀 모델 인코딩 캐시는 개인 실행당 최대 2MiB를 보유하며 8개 실행의 합계 예산은 16MiB다. 입력 수용 한도와 별개이며 초과 입력도 전송한다. 예산을 넘는 대화도 앞부분의 완전한 그룹을 유지하고 초과 조각은 전송 본문 수명 동안만 보유한다. 닫힌 세션은 DB·실행기·인코딩 참조를 해제한다. 공용 발언은 요청이 소유한 team/channel이 소유한 최대 128건·2MiB의 불변 창에서 수신자끼리 본문을 공유한다. 수신자 문맥 메타데이터는 각각 복사하고 오래된 기록과 창보다 큰 본문은 SQLite로 읽는다. 과거 조회는 최신 창을 교체하지 않으며 DB 읽기 동안 최신 창 조회와 새 발언 게시를 막지 않는다. 동시에 발생한 동일 콜드 조회는 실행 중인 결과를 공유한다. 큰 결과는 조회가 끝난 뒤 캐시에 보유하지 않는다. 다른 조회와 대기 취소는 독립적으로 처리한다. 캐시에 들어갈 수 없는 발언은 게시 시 표시 문맥 문자열을 만들지 않는다. 답글 검증은 캐시의 작성자를 재사용하고, 과거 기록은 작성자·종류·크기만 조회한다.

팀 화면은 tui/chat/team이 순수 상태로 관리하며 세션은 입력·시계·설정 저장을 연결한다. 팀 스트림은 발신자와 본문을 별도 블록으로 관리하고 본문의 증분 Markdown 상태를 재사용한다. 완료 발화는 기존 이름표와 본문을 갱신하며 마스킹·간격 규칙은 저장 이력과 공유한다. 표시 내용·참조·속성이 같은 갱신은 기존 화면 창을 유지하고, 변경된 창은 최종 행 버퍼에 직접 구성한다. 내용이 없는 Markdown에 표시 여백만 추가하지 않는다. 화면의 파생 캐시는 활성 스트림을 포함해 공통 예산을 적용하고 완료 시 일치하는 파싱 결과는 완료 표현으로 인계하고 가변 증분 상태를 해제한다. 취소·화면 종료에서 필요 없는 표시 참조를 해제한다. 큰 완료 응답은 텍스트·스타일 경계 배열로 작게 보관해 스크롤 때 전체 문서를 다시 파싱하지 않고 가시 행을 구체화한다. 예산에 들어가는 표현만 유지하고 화면 밖 캐시는 해제한다. 접힌 도구 카드는 요약과 원본 참조만 보유하고 펼칠 때 보이는 결과를 단일 조회 worker로 읽는다. 다시 접으면 상세 문자열과 diff 배치 참조를 해제한다. 화면 원문 예산에는 diff 범위 배열의 보유 용량도 포함하며, 예산 초과 시 화면 밖에서 재조회 가능한 상세 내용부터 해제하고 요약과 원본 참조를 남긴다. 채팅 경계에서 숨길 끝 빈 줄은 행 배열을 만들기 전에 줄이고 저장 원문과 파일 미리보기는 보존한다.
