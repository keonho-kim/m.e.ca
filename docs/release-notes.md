# 메모리 표시와 병렬 셸 실행

macOS · Linux / amd64 · arm64

### 변경 사항

- 상단 INPUT 왼쪽의 `MEM`에 MECA 프로세스의 현재 상주 메모리를 표시합니다. 작업 중에는 250ms, 대기 중에는 1초마다 확인하고 표시값이 바뀔 때 상단만 갱신합니다. 단일·팀·설정·파일 화면에서 같은 값을 사용합니다.
- `discuss`에서 자기 이름을 지목하면 게시 전 오류를 반환합니다. 자기 이전 글에 대한 후속 설명은 공개 참조를 보존해 동료에게 전달하고, 자동 수신·추가 판단 알림과 TUI 수신자 표시는 작성자 본인을 제외합니다.
- 독립 셸 명령을 단일 모드에서 최대 16개, 팀 모드에서 에이전트당 16개씩 실행합니다. 활성 에이전트 8명 기준 팀 전체 최대 128개이며 경로 대기·실행·출력 정리를 한도에 포함합니다.
- 같은 응답의 독립 명령도 병렬 실행합니다. 팀은 확인된 변경 경로가 겹칠 때만 공유 접근을 기다리며 승인·보호 경로·원본 검사를 실행 시점에 적용합니다.
- 경로 대기를 명령 ID로 조회·취소하고 최초 30초 관측 창에 포함합니다. 대기·실행·출력 정리 상태를 구분하며 취소·종료 시 프로세스와 경로 예약을 정리합니다.
- 팀 동료에게 모든 활성 명령 상태를 공유하고 각 명령의 실제 종료를 화면에 반영합니다. 묶음 결과와 SQLite 기록은 원래 호출 순서를 유지합니다.
- 큰 출력의 구체화·마스킹·보관은 요청 전체가 공유하는 가중 64MiB 처리 예산으로 조율합니다. 작은 출력은 별도 예산 대기 없이 처리하며 완료 결과는 저장할 차례에 한 건씩 읽고 커밋 후 메모리를 해제합니다.
- 명령 출력은 작은 결과 발췌와 정제 로그로 보관합니다. 실행 중 출력과 명령 표시를 재사용하며 캡처·보관·기록 실패는 오류로 반환합니다.
- 셸 AST·상속 환경·변경 없는 협업 현황을 재사용하고 분기별 환경 복사·중복 인자 파싱·반복 경로 조회를 줄입니다. 승인 후 실제 파일 상태 검사는 유지합니다.
- 시스템 지침·도구 설명·사용 가이드에 병렬 실행, 공유 자원 조율과 명령 제어 동작을 반영합니다.

### 업데이트 안내

- 세션 저장 형식은 **schema 26**입니다. 지원하지 않는 형식은 자동 변환·삭제하지 않으므로 새 대화를 시작해야 합니다.
- 기본 프롬프트는 `~/.meca/prompts/single/`과 `~/.meca/prompts/team/`에 각각 `system.md`·`development.md`·`compaction.md`로 생성합니다. 설치·업그레이드 시 배포 기본본으로 갱신합니다.
- 팀 개인 DB는 `~/.meca/sessions/<프로젝트 키>/.team/<사용자 세션 ID>/` 아래에 있습니다. 대화 보존에는 사용자 DB와 해당 하위 폴더를 함께 포함하세요. [전체 저장 구조](https://github.com/keonho-kim/m.e.ca/blob/main/docs/team.md#프롬프트와-저장)를 참고하세요.
