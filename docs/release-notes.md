# M.E.CA v0.0.20261117

솔로·팀 에이전트가 사용할 수 있는 브라우저 도구를 추가하고, 브라우저 설치·관찰·메모리·종료 처리를 보강했습니다.

## 브라우저 도구

- `browser_action`으로 페이지 열기·탐색·클릭·입력·선택·스크롤·요소 대기·뷰포트 변경·닫기를 지원합니다. `browser_inspect`는 요소 참조가 있는 스냅샷, 영역별 텍스트, 오류와 스크린샷을 제공합니다.
- TUI·서버·팀모드에 같은 도구 계약을 제공하고, 솔로·팀 시스템 프롬프트에 사용 순서·페이지 조회·승인·세션 종료 지침을 반영했습니다. 팀 참여자는 별도 브라우저를 사용합니다.
- system 범위에서 실행하며 외부 페이지 열기와 상호작용은 직접 승인을 요구합니다. 임의 JavaScript·브라우저 옵션·개인 프로필·외부 CDP 연결은 받지 않습니다. 스크린샷은 비전 입력이 가능한 모델에서 사용할 수 있습니다.

## 자동 설치와 Stable 갱신

- 첫 사용 시 네이티브 도우미를 준비하고, 기존 Chrome·Chromium이 없으면 Google 공식 API에서 최신 Stable Chrome for Testing을 설치합니다. macOS·Linux·WSL의 amd64·arm64를 지원하며, Linux 시스템 라이브러리는 별도로 필요합니다.
- 관리 Chrome은 설치본을 재사용하고 24시간마다 새 세션에서 업데이트를 확인합니다. 새 버전은 별도 경로에서 실행 검증 후 선택하며, 실패하면 기존 설치본을 유지합니다. 실행 중인 세션과 시스템 브라우저는 교체하지 않습니다.
- Chrome의 사전 고정 체크섬을 제거하고 공식 HTTPS 출처·정확한 버전별 URL·아카이브 크기·경로·실행 버전을 검사합니다. 도우미의 고정 버전·체크섬 검증은 유지합니다. 브라우저와 Node 환경은 MECA 배포 바이너리에 포함하지 않습니다.

## 메모리와 수명

- 관찰 결과를 기본 8KiB 페이지로 반환하고, 동일 결과는 기존 참조를 재사용합니다. 관찰은 하나당 최대 4MiB, 세션당 최대 16개·32MiB를 보관합니다.
- 수집 JSON과 결과 처리의 전체 복사를 줄이고, 동일 관찰의 재파싱을 생략합니다. 스크린샷은 픽셀 수와 파일 크기를 먼저 검사하며, 결과·이미지 전달까지 메모리 예약을 유지합니다.
- 외부 브라우저는 프로세스당 기본 3개로 관리하며 `MECA_BROWSER_MAX_SESSIONS`로 조정합니다. 새 세션 전에 시스템 메모리 압박을 확인하고, 용량·메모리 부족 시 명시적으로 거절합니다.
- 종료·취소·저장 실패 시 예약과 임시 자료를 정리하고, 종료 확인과 파일 삭제를 분리해 정리 재시도가 브라우저를 다시 실행하지 않도록 했습니다. Docker에서는 자식 프로세스 회수를 위해 `--init`을 사용합니다.
