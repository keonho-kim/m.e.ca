# TDD 개발 지침과 팀 역할·Spec 합의

macOS · Linux / amd64 · arm64

### 변경 사항

- 단일 모드의 `development.md`는 최상단에서 TDD의 Red → Green → Refactor 절차를 안내합니다. 요청한 동작별로 테스트를 먼저 작성하고 의도한 실패를 확인한 뒤 최소 구현과 리팩토링을 진행합니다.
- TDD는 테스트 가능한 구현에 요청 규모에 맞춰 적용합니다. 의존성·환경·도구 오류는 동작의 실패 검증과 구분하며, 문구·기계적 수정은 검토와 기존 검사를 사용합니다.
- 팀은 공유 파일을 바꾸기 전에 관련 동료와 역할을 합의하고, 구현 전에 Spec을 합의하도록 안내합니다. 도메인별 결과·변경 경로·공유 인터페이스·선행 조건을 조율하며 일방적인 안내나 담당 등록을 동료의 수락으로 간주하지 않습니다.
- 공통 초기화·의존성 설치·기반 작업에는 한 명의 담당자를 정하고 실제 완료 결과를 공유하도록 합니다. 기존 합의는 재사용하고 바뀐 경계만 조율하며, 준비된 담당 작업은 반복 확인 없이 진행하도록 안내합니다.
- 팀 전용 `development.md`는 DDD·Spec-Driven Development·TDD 절차와 범용 개발 원칙·디자인 패턴 전체를 포함합니다. 도메인별 책임과 공유 계약을 나누고, 수용 기준에 맞는 테스트의 실패 확인 → 최소 구현 → 리팩토링으로 이어집니다.
- 큰 구현은 담당 편집자가 있는 프로젝트 내부의 단일 Spec으로 관리하도록 안내합니다. 작은 수정은 기존 기준과 짧은 공개 합의로 다루며 요청 규모·단계에 맞춰 방법론을 적용합니다.
- 압축 지침은 현재 합의된 역할·수락한 동료·Spec 참조·남은 수용 기준·공통 선행 작업의 담당과 관측된 완료 상태를 보존하도록 합니다. 시스템 지침·협업 도구 설명·사용 가이드는 같은 개발 절차를 따릅니다.
- 하단 모델 상태에 `Team Hana Ren`처럼 활성 멤버 이름을 참여 순서로 표시합니다. 한국어 UI의 라벨은 `팀`이며 입·퇴장 때 목록을 갱신합니다. 표시 문자열은 멤버가 바뀔 때만 만들고 작업 종료 시 참조를 정리합니다.

### 업데이트 안내

- 세션 저장 형식은 **schema 26**입니다. 지원하지 않는 형식은 자동 변환·삭제하지 않으므로 새 대화를 시작해야 합니다.
- 기본 프롬프트는 `~/.meca/prompts/single/`과 `~/.meca/prompts/team/`에 각각 `system.md`·`development.md`·`compaction.md`로 생성합니다. 설치·업그레이드 시 배포 기본본으로 갱신합니다.
- 팀 개인 DB는 `~/.meca/sessions/<프로젝트 키>/.team/<사용자 세션 ID>/` 아래에 있습니다. 대화 보존에는 사용자 DB와 해당 하위 폴더를 함께 포함하세요. [전체 저장 구조](https://github.com/keonho-kim/m.e.ca/blob/main/docs/team.md#프롬프트와-저장)를 참고하세요.
