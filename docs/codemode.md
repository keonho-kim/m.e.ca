# Code Mode

[문서 목록](README.md) · [도구 목록](tools.md) · [승인 경계](execution-boundary.md) · [실행 흐름](runtime.md)

모델은 필요한 계산·도구 작업을 `codemode({code})`의 JavaScript 또는 TypeScript로 실행한다. 코드 안에서 `tools.<도구명>(인자)`를 호출하고, 반복·조건·결과 가공을 수행한 뒤 다음 판단에 필요한 JSON 값을 반환한다. 실행기는 MECA 바이너리에 포함된 QuickJS와 esbuild를 사용한다. 배포본 실행에 Go·Node.js·TypeScript 설치나 외부 코드 실행 서비스가 필요하지 않다.

모델에 노출되는 실행 도구는 `codemode` 하나다. `tools.*`는 그 안에서 호출하는 호스트 함수이며 독립적인 모델 도구가 아니다. 계산·관찰·변경의 필요성은 사용자의 요청과 대화 문맥에서 판단한다. 일반 답변이나 이미 작성한 설명을 전달하기 위해 코드 실행을 거치지 않는다.

공통 시스템 지침은 의도·범위·완료 판단을, Code Mode 명세는 실행 계약을, 각 호스트 함수의 카탈로그는 사용법과 인자를 소유한다. 사용 가능한 카탈로그에서 함수 선언을 생성하므로 등록된 기능과 모델이 받는 명세가 일치한다.

## 코드와 도구 계약

`code`는 비동기 함수의 본문이다. 함수 선언이나 Markdown 코드 블록으로 감싸지 않고 `await`와 `return`을 사용한다. 타입은 본문 안에 선언하며 `import`·`export`는 사용할 수 없다.

`tools` 객체는 이미 제공되어 있다. 단일 호출은 `return await tools.<도구명>({...});` 형태로 결과를 반환하고, 복합 작업은 필요한 관찰과 검증 결과를 모아 반환한다. 정상적인 명시적 반환값은 모델 결과의 `result`에 담긴다. 반환하지 않은 내부 결과도 실행 기록에 보존하며, `undefined`로 끝난 코드에는 [자동 전달](#반환값-누락-시-자동-전달)을 적용한다.

```typescript
const result = await tools.execute_command({
  reason: "작업 위치 확인",
  command: "pwd",
});
return { directory: result.Stdout.trim() };
```

도구 이름·설명·인자 타입은 현재 카탈로그에서 생성하고 요청 수명 동안 재사용한다. 비전 지원과 브라우저 설치 상태, 단일·팀 모드에 따라 사용 가능한 함수가 달라지며 요청 중 이미지 지원이 해제되면 선언도 갱신한다. 실제 인자는 같은 카탈로그로 다시 검증한다. TypeScript는 JavaScript로 변환하며 전체 타입 검사는 수행하지 않는다. 명시적 반환값은 JSON으로 직렬화할 수 있어야 한다. JavaScript의 `undefined`는 `result:null`과 `return_status:undefined`로 표현한다.

각 코드 호출에는 독립된 JavaScript 컨텍스트를 생성한다. 이전 호출의 변수나 전역 상태를 공유하지 않는다. 파일·네트워크·환경변수·프로세스·타이머·외부 모듈 로더를 JavaScript 전역에 제공하지 않는다. 호스트 작업은 제공된 MECA 도구를 통해 수행한다.

## 승인과 실행

코드 자체에는 사용자 승인을 요청하지 않는다. 내부 도구 호출마다 다음 경계를 통과한다.

1. 실제 인자를 확정하고 보호된 자격 증명과 인자 형식을 검사한다.
2. 도구의 현재 대상·정책·작업 범위를 확인한다. 셸 명령은 완성된 문자열에 기존 AST 분석을 적용한다.
3. 승인이 필요한 작업만 기존 승인 모드에 따라 처리한다.
4. 승인한 후보와 실제 대상이 일치하는지 다시 확인하고 실행한다.
5. 실제 결과와 변경 사항을 확정한 뒤 Promise에 결과를 전달한다.

승인 대기 중 JavaScript 객체를 변경해도 이미 제출한 호출 인자는 바뀌지 않는다. 승인 거부·정책 차단·취소·저장 실패는 호스트가 실행을 중단하므로 `try/catch`로 후속 효과를 계속할 수 없다. 일반 도구 실패는 Promise 거절로 전달하며 `Error.output`에서 해당 도구의 결과를 읽을 수 있다.

독립 호출은 `Promise.all`로 묶거나 개별 Promise를 기다릴 수 있다. 완료된 도구는 원문을 저장한 직후 해당 Promise에 결과를 전달하므로, 빠른 결과를 이용한 후속 작업은 무관한 느린 도구를 기다리지 않는다. `Promise.all` 반환 배열은 입력 순서를 유지하고 실행 기록은 결과가 확정된 순서를 따른다. 화면의 호출 위치는 실행 ID에 연결된 표시 순서로 유지한다.

실행 중인 호출과 새 호출을 함께 비교해 같은 파일·별칭·상하위 경로가 충돌하지 않게 하며, 동시에 실행하는 도구는 최대 16개다. 새 묶음은 준비·승인·대상 재확인을 마친 뒤 시작한다. 승인 대기 중 완료된 기존 작업의 결과도 추가 효과를 시작하기 전에 확인한다. 도구 실패가 확인되면 아직 시작하지 않은 호출은 실행하지 않는다. 모든 호출을 기다린 뒤 반환해야 하며, 미완료 호출이 남은 프로그램은 오류로 종료하고 시작한 작업은 취소·회수해 실제 결과를 기록한다.

셸과 하위 프로그램은 호스트 사용자 권한으로 실행한다. 내장 코드 실행기의 기능 제한과 승인 장치는 OS 수준의 파일시스템·네트워크 격리가 아니다.

## 반환과 실행 기록

모델에는 코드 호출 하나와 그 반환 결과가 대응한다. 내부 도구 호출은 각각 별도 실행 ID를 가지며 `parent_execution_id`로 코드 실행에 연결한다. API에서는 `parentExecutionId`로 전달한다.

```json
{"status":"completed","return_status":"value","result":{"directory":"/workspace"},"tool_calls":1}
```

`status`는 정상 반환인 `completed`, 모델의 새 판단이 필요한 `needs_model`, 실패인 `error`, 실행 전에 중단된 `not_executed`를 구분한다. 오류에는 `error`와 필요한 경우 `last_tool_failure`를 포함한다. 마지막 도구 실패의 원본 출력이 크면 제한된 발췌와 실행 ID를 전달하며 원본은 실행 기록에 남긴다.

JS 본문이 정상 종료했을 때 `return_status`는 반환값이 있는 `value`와 결과가 `undefined`인 경우를 구분한다. 명시적인 `return null`, `false`, 빈 객체는 그대로 유효한 반환값이다. `return`을 생략하거나 없는 속성을 반환해 `undefined`가 되어도, 이미 실행된 도구가 미실행으로 바뀌지는 않는다. `needs_model`·오류·실행 전 중단에는 이 필드를 붙이지 않는다.

모델에 반환하지 않은 중간 결과도 기존 보존·비밀값 제거 정책에 따라 실행 기록에 저장한다. 실패나 취소 전에 수행한 작업은 되돌아간 것으로 표시하지 않는다. 결과 저장이 불확실하면 추가 효과를 실행하지 않는다. 재시작이나 대화 복원은 JavaScript 상태 복원이나 코드의 자동 재실행을 뜻하지 않는다.

반환값에 이미 저장된 큰 도구 원문이 그대로 포함되면 SQLite는 원문과 작은 조각 참조를 공유한다. 복원할 때 원문과 전체 결과의 길이·해시·JSON을 확인하므로 대화, 내보내기와 원문 조회의 내용은 동일하다. 참조가 없거나 손상되면 복원을 실패시키며 데이터를 다시 만들지 않는다.

완료 통계의 `code_executions`와 `tool_executions`는 코드 실행과 시작한 내부 도구 실행을 구분한다. 서버 API 필드명은 각각 `codeExecutions`, `toolExecutions`다.

## 반환값 누락 시 자동 전달

코드가 정상 종료했지만 결과가 `undefined`이면, 같은 코드 호출에서 저장이 확인된 성공 결과를 `fallback.outputs`에 완료 순서대로 전달한다. 각 항목은 도구 이름·결과와 필요한 출처를 가진다. 오류로 종료한 코드에는 이 자동 전달을 적용하지 않으며, 기존 오류와 `last_tool_failure`로 실행 상태를 알린다.

```json
{"status":"completed","return_status":"undefined","result":null,"tool_calls":1,"fallback":{"outputs":[{"tool":"execute_command","value":{"Stdout":"5\n","ExitCode":0}}]}}
```

자동 전달 배열은 JSON 인코딩 후 총 512KiB 이하다. 메타데이터·구분자·이스케이프를 포함해 남은 공간에 들어가는 결과는 전부 전달한다. 공백을 정리한 실제 JSON 크기로 판정한다. 초과한 개별 결과의 `value`는 `{"excerpt":"원문 JSON의 일부","truncated":true}`로 바꾸고, 결과가 잘리거나 빠지면 `fallback.truncated`가 `true`다. 발췌는 비밀값 제거 뒤 실제 JSON 문자열의 인코딩 크기를 계산해, 남은 공간에 들어가는 가장 긴 UTF-8 접두부로 만든다. 전체 원문은 기존 실행 기록에 보존한다.

추가 조회나 원래 작업의 재실행 없이 다음 모델 입력에 이 결과를 포함한다. 자동 전달 값은 도구의 실제 출력이며, 반환하지 않은 코드의 지역 변수나 가공 결과를 재구성하지 않는다. 도구 호출 없이 끝난 코드에는 전달할 내부 출력이 없다. 저장 성공이 불확실하면 다음 모델 판단을 중단한다. 모델에 보낼 배열은 실행 결과가 확정될 때 메모리에서 구성하고 코드 호출이 끝나면 해제한다.

명시적인 반환값이 있으면 `null`을 포함해 그 값을 사용하고 자동 전달을 붙이지 않는다. 필요한 정보만 모델에 전달하려면 명시적으로 반환한다. 반환을 생략하면 중간 출력의 일부가 모델 문맥에 들어갈 수 있다.

## 모델 판단이 필요한 입력

스킬·참고 지침·이미지를 읽으면 결과를 `observations` 또는 이미지 첨부로 보존하고 코드 실행을 `needs_model`로 마칠 수 있다. 이 입력은 `return` 없이도 전달되며 반환 누락에 대한 `fallback`과 별도로 처리한다. 모델은 새 입력을 확인한 뒤 필요한 다음 응답이나 작업을 결정한다. 뒤에 작성한 의존 작업은 같은 코드에서 계속 실행하지 않으며, 이미 완료된 호출은 다시 실행하지 않는다.

스킬 읽기도 같은 경로를 사용한다. 다음 본문으로 스킬을 읽고, 반환된 지침을 모델이 확인한 뒤 필요한 후속 작업을 결정한다.

```typescript
return await tools.load_skill({id: "meca:development"});
```

오류 피드백은 검증 실패와 실행 여부를 전달한다. 모델은 원래 요청에서 다음 응답을 다시 판단하며, 여전히 필요한 작업일 때 수정·재시도한다. 대화로 요청을 충족하거나 필요한 결정을 묻고 종료할 수도 있다.

새 사용자 지시는 다음 도구 실행 경계에서 확인한다. 이전 지시로 작성된 코드의 남은 효과를 중단하고, 변경된 지시와 기록된 결과를 다음 판단에 전달한다. 팀 모드의 담당 범위·승인·메시지 출처·퇴장 처리도 같은 도구 경로를 사용한다.

브라우저·웹 문서 페이지만 읽은 코드의 결과는 한 번 읽은 관찰로 관리한다. 코드나 인자를 교정하는 동안 미열람 자료를 유지하고, 정상 처리한 결정 이후에는 모델 문맥에서 상세 페이지를 정리한다. 원본과 이어 읽기 위치는 기존 관찰 소유자가 보관한다.

장시간 명령의 `command_id`와 수명은 기존 명령 등록부가 소유한다. 코드는 `tools.wait_command`와 `tools.cancel_command`로 같은 작업을 관찰·취소한다. 코드 함수의 반환과 호스트 명령의 종료는 별개이며, 요청 종료 시 활성 명령을 확인하고 정리한다.

## 자원 한도

| 대상 | 한도 |
| --- | --- |
| 코드 원문 | 256 KiB UTF-8 |
| 코드 호출별 JS 힙 | 64 MiB |
| 프로세스 전체 JS 힙 예약 | 256 MiB |
| 코드 호출별 JS 평가 시간 | 합계 10초 |
| JS 호출 깊이 | 실행기 스택 슬롯 256개 |
| 코드 호출별 도구 요청 | 256회 |
| 제출 후 결과를 받지 못한 도구 요청 | 32개 |
| 동시에 실행하는 도구 작업 | 16개 |
| 도구 인자 JSON | 호출당 4 MiB |
| JS에 전달하는 개별 도구 결과 | 8 MiB |
| 코드의 반환값 JSON | 1 MiB |
| 모델·스크립트에 전달하는 오류 설명 | 항목당 16 KiB와 축약 표시 |
| 반환 누락 시 자동 전달 배열 | 코드 호출당 JSON 512 KiB |

도구와 요청에 더 작은 한도가 있으면 함께 적용한다. JS 평가 시간에는 도구 실행·승인 대기를 포함하지 않으며 전체 요청 기한은 유지한다. 반환값 한도는 스킬·이미지의 별도 입력 예산과 구분한다. 힙 예약은 JS 엔진의 예산이며 Go 객체·결과 복사·전체 프로세스 RSS를 포함한 상한은 아니다.

반환 JSON의 UTF-8 바이트 수는 JS 힙 안에서 확인한 뒤 Go로 전달한다. 일반 도구 결과의 호스트 임시 참조는 전달 후 해제한다. 자동 전달용 배열만 JSON 512KiB 안에서 코드 호출이 끝날 때까지 보관하며, 초기화 도중 취소돼도 생성된 실행기 자원만 정리한다.

## 구현 소유권

- `internal/tools/codemode`: TS 변환, JS 실행, 카탈로그 타입 투영, JSON·Promise 연결과 실행기 정리.
- `internal/agent/run`: 모델 호출, 내부 도구 검증·승인·배치 실행, 기록, 지시 변경과 크기를 제한한 모델용 결과.
- `internal/processmemory`: 프로세스 전체 JS 힙과 공용 payload 예약.
- 기존 도구·저장·전송·화면 계층: 실제 효과, 원본 보존, 부모·내부 호출의 표시와 복구.
