# 스킬

[← README](../README.md) · [사용 가이드](usage.md) · [서버 API](server.md)

스킬은 에이전트가 읽고 적용하는 작업 지침이다. SKILL.md를 읽은 뒤 기존 도구와 승인 정책으로 작업한다. 별도 실행 단위나 켜기·끄기 상태는 없다.

## 탐색 위치

| 우선순위 | 경로 |
| --- | --- |
| 1 | `<project_root>/.agents/skills/<name>/SKILL.md` |
| 2 | `~/.meca/skills/<name>/SKILL.md` |
| 3 | `~/.agents/skills/<name>/SKILL.md` |

기준은 현재 대화의 고정된 project_root다. 셸의 cd는 이 기준을 바꾸지 않는다. 각 루트의 직접 하위 스킬 디렉터리를 조회하며 프로젝트 전체나 상위 디렉터리를 재귀 탐색하지 않는다. 같은 실제 스킬 디렉터리를 가리키는 링크는 중복 제거하지만, 본문이 같아도 다른 디렉터리는 참고 파일의 기준이 다르므로 구분한다.

## 기본 스킬과 초기화

일반 시작과 install·upgrade의 Bootstrap은 `~/.meca/skills/`에 기본 스킬을 생성한다. `create-skill`은 작성 지침을, `ui-design`은 본문·참고 파일·선택적 검증 스크립트·라이선스·고지를, `backend-design`은 본문·설계 지침·조사 출처를 함께 배포한다. 디렉터리는 0700, 새 파일은 0600이며 기존 파일은 덮어쓰지 않는다. 누락한 기본 파일은 다음 초기화에서 다시 생성한다. 프로젝트·공유 스킬 경로는 자동 생성하지 않는다.

`#create-skill`은 [Agent Skills 표준](https://agentskills.io/specification)에 맞는 스킬 작성·수정 지침을 읽는다. 표준 이름에는 밑줄을 허용하지 않으므로 `create_skill` 대신 `create-skill`을 사용한다. 기본 지침은 필수 YAML 메타데이터, 최소 예시, 참고 자료·스크립트·에셋 구성과 검증 방법을 담는다. 사용자가 경로를 지정하지 않으면 새 스킬은 프로젝트 `.agents/skills/`에 작성하도록 안내한다. 배포 원본은 [기본 SKILL.md](../internal/config/bootstrap/defaults/create-skill/SKILL.md)이며 설치된 수정본은 재설치 때도 보존한다.

`#ui-design`은 **UI DESIGN**의 단일 진입점이다. 서브커맨드·필수 인자·명령 선택 메뉴가 없으며 에이전트가 대화와 프로젝트를 읽고 필요한 자료를 탐색한다. 기본 대상은 데스크톱 WebApp/SaaS다. 사용자 작업과 앱 성향에서 페이지 지도를 정하고, 히어로·앱 셸·검색/결과·목록/상세·대시보드·편집·협업·문서·예약/주문 등 큰 레이아웃의 필수·조건부·생략 영역을 설명한다. 단위 버튼이나 팝업 목록을 중심으로 화면을 구성하지 않는다.

[본문](../internal/config/bootstrap/defaults/ui-design/SKILL.md)은 시나리오·레이아웃 지도와 참고 지침, 앱별 코드·미디어·디자인 기록을 연결한다. 65개 참고 문서는 과업·정보 관계에서 구성과 시각적 표현을 선택하는 기준·장단점·검증 방법을 다룬다. 실제 프로젝트의 요구·기존 디자인 시스템·현재 요청이 우선한다. 에셋과 동봉 DESIGN.md·PRODUCT.md는 가상 사례의 설명이며 대상 프로젝트의 요구, 팔레트, 페이지 수, 프레임워크나 모듈 구조를 지정하지 않는다. 탐색은 **본문 → 분류 지도 → 선택한 자료**의 최대 세 층이며 모든 자료는 두 번 이하의 파일 링크 이동으로 도달한다. 필요한 파일만 읽으며 전체 트리를 재귀 로드하지 않는다. 설명 Markdown은 파일별 8KiB, 코드·미디어는 1MiB까지 허용하고 512KiB 이하를 권장한다. 이는 기본 스킬의 작성 기준이며 Agent Skills 표준이나 엔진의 64KiB 텍스트 페이지 한도를 바꾸지 않는다.

[사용성 판단](../internal/config/bootstrap/defaults/ui-design/references/usability.md)은 과업·빈도·정보 관계·위험·중단/복귀 맥락에서 구성을 도출한다. 무엇을 함께 보여주거나 순서대로 다뤄야 하는지 판단하고, 중요한 선택은 맥락 → 어려움 → 구성 → 예상 이점/비용 → 확인 방법으로 설명한다. 레이아웃·컴포넌트·모션 목록은 비완결적인 예시이므로 조합·변형·생략하거나 목록에 없는 구성을 도출할 수 있다. 새로운 시각적 배치도 학습된 조작·접근성·실제 상태 계약을 유지한다. 가정과 에이전트의 휴리스틱 검토를 사용자 연구 결과로 표현하지 않는다.

UI 개발의 브라우저 검증은 **Playwright CLI (`playwright-cli`)**로 수행한다. [브라우저 도구 지침](../internal/config/bootstrap/defaults/ui-design/references/browser-tools.md)은 실제 서버와 작업별 세션, 화면 캡처·콘솔/네트워크 확인, 두 선택적 진단과 수정 후 재검증을 안내한다. CLI가 없으면 레이아웃·모션 검증 도구에 필요하다고 설명하며 사용자에게 설치를 요청하고 자동 설치하지 않는다. 독립적인 작업은 계속하며 수행하지 못한 브라우저 검사는 미실행으로 보고한다. CLI는 개발 검증 도구이며 MECA나 생성 앱의 런타임 의존성이 아니다.

[레이아웃 검사](../internal/config/bootstrap/defaults/ui-design/scripts/layout-check.js)는 보이는 버튼의 높이·넘침 후보를, [모션 검사](../internal/config/bootstrap/defaults/ui-design/scripts/motion-check.js)는 제한된 프레임의 급격한 위치·크기 변화 후보를 보고한다. 모션 관찰은 같은 페이지에서 시작·종료하고 시간·프레임·대상 수를 제한한다. 미관찰·누락·페이지 이동은 성공으로 취급하지 않으며 스크립트 결과는 직접 화면을 확인할 단서다. 스크립트는 Playwright CLI의 `run-code` 함수로 실행하며 스킬 reader가 자동 실행하지 않는다.

[공개 페이지 지침](../internal/config/bootstrap/defaults/ui-design/references/layouts/public-pages.md)은 제품 시연의 맥락·행동·결과를 실제 표시 크기에 맞춰 구성하고, 축소 모션과 시연용 조작의 접근성·실제 기능 경계를 확인한다.

한국어·혼합문자·IME·업무 밀도·검색/목록/상세 관습은 한국형 데스크톱 맥락으로 다루되 모든 국내 서비스의 공통 스타일로 강제하지 않는다. 글래스모피즘·미니멀리즘·퓨처리즘은 각각 독립된 테마 파일이다. Impeccable의 62개 탐지 항목은 구성·문구, 시각적 완성도, 상태·일관성 분석으로 나누고 실제 결함·문맥상 경고·의도된 테마를 구분한다.

큰 영역을 정한 뒤에는 모달·팝오버·토스트·드롭다운·탭·캐러셀·아코디언·체크박스·입력 박스·플로팅 버튼·Stepper 등 필요한 컴포넌트 파일만 읽는다. 각 파일은 적용 전 맥락 질문과 기본 동작·시각적 변형·애니메이션 예시를 제공한다. 같은 요금 정보도 간헐적 확인에는 선택적 상세, 견적 비교에는 동시 표시가 적절할 수 있다. Price Breakdown·Segment Bar·Swipe·Blinds·Depth Stack 같은 이름에 맞춰 과업을 바꾸지 않는다. 변형명은 응용을 돕는 예시이며 새 명령·표준·API가 아니다.

로딩 자료는 콘텐츠/Skeleton·실제 진행/스트리밍·미디어/점진적 표시로, 모션 자료는 시간/수명·화면 전환·공간/배치·표현 효과로 나눈다. 각 지침은 선택 조건·구성·시각 상태·키보드/접근성·빠른 재조작·실패/취소·축소 모션·실제 데이터 계약을 연결한다. 컴포넌트 라이브러리나 실행 의존성은 추가하지 않는다.

알려진 첫 로딩 구조에는 Skeleton Pulse·Skeleton Shimmer를 고려하고 축소 모션에서는 정적으로 표현한다. 콘텐츠 이미지는 원본에서 만든 실제 미리보기를 사용하는 Blur-up을 기본으로 하며 디코드·캐시·실패를 처리한다. 단계별 작업은 Step Status로 대기·진행·완료·실패·취소·건너뜀·관측 불확실성을 표현한다. 탐색용 Stepper나 실측 Progress bar와 의미를 섞지 않는다.

[색 원칙](../internal/config/bootstrap/defaults/ui-design/references/color-systems.md)은 중성 기반·행동/초점 강조·역할별 강조 분배·콘텐츠/브랜드·상태·데이터·명암 모드·재질/접근성의 8가지 의사결정 방식을 다룬다. 고정 팔레트나 색 선택기는 제공하지 않는다. [코드 지도](../internal/config/bootstrap/defaults/ui-design/references/code-examples.md)는 Fieldwork 결재 8화면과 Querydesk DB 워크벤치 4화면, Archive 자료·학습 4화면, Morrow 소개·예약 4화면과 모션 예시를 연결한다. [제품 워크스페이스 지도](../internal/config/bootstrap/defaults/ui-design/references/product-workspaces.md)는 Databook의 소스·탐색·대화·근거·인사이트 5화면과 Folio의 라이브러리·작성 요청·구조·문서·슬라이드·검토 6화면을 연결한다. 예약 대안 3화면과 캔버스를 합한 총 36개 HTML은 역할별 CSS·최소 Vanilla JS·자체 생성한 가상 공간 사진·파생 미리보기·로컬 Lucide 심볼을 사용한다. 결재·DB·Databook·Folio는 정적 디자인 셸이며 DB·AI·승인·편집·내보내기·저장을 실행하지 않는다. 기존 Archive·Morrow의 제한된 로컬 동작은 유지한다. 외부 CDN·글꼴·API·패키지·빌드 의존성이나 갤러리 화면은 없다. 로컬 HTTP에서 앱과 하위 화면을 직접 연다.

동봉 사례에서 오피스는 파일 제목·도구 모음·문서 목차·슬라이드 필름스트립·흰 작업면의 관계를 보여준다. Archive는 미니멀리즘·에디토리얼 구성과 중성 바탕에 행동·선택/초점·콘텐츠·저장/완료를 구분하는 포인트 색을 조합한다. 일부 사례는 앱별 글래스 표면을 사용하며 Querydesk는 다크 테마다. 이는 테마를 앱 종류에 배정하는 규칙이 아니다. 일반 지침은 전역 탐색·프로젝트 모드·콘텐츠 트리·결과 탭의 역할, 제목·본문·도구의 위계, 색의 의미와 대비, 실제 변화에 맞는 모션을 판단하도록 한다. 미니멀리즘도 의미 있는 복수의 강조색을 사용할 수 있으며 축소 모션·투명도 축소·고대비에서는 의미와 조작을 보존한다.

[시각 시스템 지도](../internal/config/bootstrap/defaults/ui-design/references/visual-system.md)는 시각 언어, 한글 타이포·공간·밀도, 전체 화면 구성 대안, 긍정적인 anti-slop 사례를 선택적으로 연결한다. 색·테마와 독립적으로 정보 순서·형태·여백·이미지 역할·조작·모션을 판단한다. [실전 비교 지도](../internal/config/bootstrap/defaults/ui-design/references/visual-studies.md)는 같은 예약을 공간 탐색형·시간표형·문서형으로 구현하며 세 화면과 기존 예약 화면이 초안·계산·검증·로컬 기록을 공유한다. 자료 검토 캔버스는 실제 포인터 이동, 버튼·키보드 대안, 확대/전체 보기와 변경 순서를 확인하는 되돌리기를 제공하며 배치는 페이지 수명에만 유지한다. 열 개 캡처는 실제 구현을 1440×900으로 기록한 선택적 시각 참고 자료다. 갤러리와 전용 축소 이미지는 배포하지 않는다. assets/examples 아래 approvals·database·databook·office·archive·morrow·booking·canvas·motion·shared·previews로 나누고, 역할별 Markdown 지도에서 선택한 파일로 바로 연결한다. 폴더마다 별도 인덱스를 읽지 않으므로 탐색은 세 층으로 유지된다. 설명이나 렌더링 성공을 사용자 선호·모델 품질 개선의 증거로 표현하지 않는다.

[배치 조사](../internal/config/bootstrap/defaults/ui-design/references/resource-layout.md)는 Agent Skills의 references/assets 권장 역할과 Hallmark 고정 리비전의 실제 배치를 구분한다. Hallmark는 테마 지침·이미지와 코드 조각을 references에, 도구용 HTML을 scripts/fixtures에, 공개 완성 예시를 스킬 밖 site/made에 둔다. 완성 예시의 과업에 맞는 구성과 조작도 분석하되 소스·테마·사진·명령은 포함하지 않는다. [서비스 원칙](../internal/config/bootstrap/defaults/ui-design/references/service-craft.md)은 Apple·Instagram/Meta·Google의 콘텐츠 우선, 익숙한 조작, 계층, 목적 있는 모션을 플랫폼·연구 범위와 함께 정리한다. Product Design의 맥락 파악 → 시각적 근거 → 완전한 흐름 → 실제 렌더링·상호작용 검토도 새 지침으로 반영하며 플러그인이나 의무적인 승인 절차를 요구하지 않는다.

Anti-slop은 발견·구성·구현·검증에서 실제 내용과 과업에 맞는 구조·강조·문구·상태를 만드는 기준이다. 근거 없는 카드·KPI·활동·진행·성공을 만들지 않고, 관찰한 사용성 비용의 원인을 먼저 수정한다. 익숙한 컴포넌트나 요청한 테마를 일률적으로 금지하거나 참신함·적은 탐지 경고를 품질의 증거로 삼지 않는다. 컴포넌트·테마·모션의 변형은 적용 이유와 비용을 비교하는 자료이며, 예시와 다른 구성도 실제 맥락에 맞으면 도출한다.

이전 기본 스킬명은 배포 원본에서 교체하며 별칭이나 자동 이전을 제공하지 않는다. 사용자 홈에 이미 존재하는 스킬 파일은 이름과 관계없이 자동 삭제하거나 덮어쓰지 않는다. 막연한 요청에는 목적 중심의 제안을 제공하고, 확정한 요청에는 불필요한 인터뷰나 승인 단계를 추가하지 않는다.

이 스킬은 사용자가 제공한 교육 자료, `frontend-design`·`Impeccable`의 선별한 원칙, Product Design의 검토 방식과 Stageshow의 선별한 시연·검증 아이디어를 바탕으로 작성한 지침이다. 원본 스킬·명령 체계·실행기·hook·이미지를 함께 넣지 않는다. 별도 Node·Python·네이티브 실행기나 외부 이미지 API를 MECA 의존성으로 추가하지 않으며 프로젝트의 실제 도구와 API를 사용한다. 모델별 디자인 품질이나 기능 완수를 보장하는 기능은 아니다. 출처와 배포 조건은 [고지](../internal/config/bootstrap/defaults/ui-design/NOTICE.md)를 따른다.

### 백엔드 설계

`#backend-design`은 설계 단계부터 성능을 고려하는 단일 진입점이다. 에이전트가 대화·프로젝트·기존 계약을 보고 필요한 자료를 선택하며 서브커맨드나 필수 인자는 없다. 기본 CRUD 강의나 고정된 엔터프라이즈 스택을 제시하지 않는다.

테스트 가능한 구현은 **Red → Green → Refactor의 TDD를 기본**으로 한다. 요구·불변식에서 작은 동작 테스트를 먼저 만들고 의도한 실패를 실제 확인한 뒤, 최소 구현과 테스트를 유지하는 리팩토링을 반복한다. 환경·의존성 오류는 Red로 간주하지 않는다. DB 제약·격리처럼 실제 어댑터가 필요한 검증과 순수 판단 테스트를 구분하고, 성능은 동일한 동작을 유지한 측정으로 확인한다. 설계·검토만 요청하면 인수 조건과 검증 방법을 정의하며, 문구·기계적 변경과 동작 보존 리팩토링은 검토·기존 검증을 활용한다.

[본문](../internal/config/bootstrap/defaults/backend-design/SKILL.md)은 부하·불변식·일관성·자원 예산에서 데이터 흐름·저장 구조·실행 경계를 도출하도록 안내한다. 신규 시스템은 예상 스캔·복사·직렬화·네트워크 왕복·쓰기 증폭과 명시한 부하 가정으로 선택하고, 구현이 있으면 프로파일·부하 시험으로 확인한다. 설계 전 측정 결과가 있어야만 판단할 수 있다고 요구하거나, 추정 비용을 실측 성능처럼 표현하지 않는다.

64개 참고 문서는 아키텍처·실전 구성·설계 비교·저장소·API 실행·보안·성능·운영의 지도와 주제별 지침, 일곱 분야의 출처 목록으로 나눈다. SQLite·PostgreSQL·Redis, 멱등 명령·스트림·작업/웹훅·테넌트 격리, 중앙 진단, 암호화·키 수명, 검색·벡터·메모리·I/O·과부하·복구를 같은 자원/정확성 모델에 연결한다.

[기본 development.md](../internal/agent/prompt/defaults/development.md)의 패턴 선택 원칙을 [실전 구성 지도](../internal/config/bootstrap/defaults/backend-design/references/compositions.md)로 확장한다. 기능 모듈·트랜잭션 명령·조회 모델·내구성 있는 워크플로·자원 한도를 둔 파이프라인·외부 연동·질의/규칙 컴파일의 일곱 구성을 책임 배치, 호출/의존 방향, 상태·트랜잭션·취소·정리 경계와 비용으로 설명한다. 단순 함수·모듈을 우선하고 Strategy 계층을 추가하지 않는 기본 제약을 반영한다. 패턴마다 별도 패키지나 인터페이스를 만들도록 요구하지 않는다.

[설계 비교 사례](../internal/config/bootstrap/defaults/backend-design/references/design-studies.md)는 워크스페이스·재고/결제·검색·암호화 문서의 네 가상 요구를 스키마·흐름·대안·비용 계산으로 연결한다. 수치는 명시한 가정이며 벤치마크 결과가 아니다. 물리 모델, 계층/시계열/집계, 스냅샷과 변경 이벤트의 연결, 오래된 캐시 값 재적재, 작업 배분, 런타임별 취소, 진단 카탈로그 계약과 불변식 검증을 선택적으로 연결한다. 스킬의 모델 평가용 요청/판정 기준도 제공하되 로딩 테스트와 실제 모델 평가 결과를 구분한다.

각 기법은 적용 조건·예상 이점·추가 비용·실패 양상·검증 방법으로 판단한다. 고급 기법이 모든 서비스의 기본 요건은 아니며 실제 프로젝트의 요구와 정책이 우선한다. 코드·메시지·이벤트·필드 정책은 중앙 진단 모듈이, 도메인 판단·재시도·부분 효과는 해당 작업이, sink·큐·종료 수명은 조립부가 소유하도록 구분한다.

참고 자료는 **본문 → 지도 → 선택 자료**의 최대 세 층이고 Markdown은 파일별 8KiB 이하이다. 전체를 모델 문맥에 한 번에 넣지 않는다. [조사 기록](../internal/config/bootstrap/defaults/backend-design/references/sources.md)은 2026-11-09에 확인한 1차 자료의 상태·적용 범위를 구분하고, 접근할 수 없었던 원문과 버전 의존성을 명시한다. 자료는 새로 작성한 지침이며 외부 매뉴얼·코드·실행기나 새 제품 의존성을 동봉하지 않는다. 실제 모델의 준수·상용 성능·보안을 보장하는 기능은 아니다.

## 파일 형식

```text
.agents/skills/review/
  SKILL.md
  references/checklist.md
  scripts/check.sh
  assets/example.png
```

```markdown
---
name: review
description: 변경한 코드의 정확성과 실패 경로를 검토할 때 사용한다.
---
변경 목적과 호출자를 확인한 뒤 references/checklist.md를 읽는다.
관찰한 결과와 확인하지 못한 부분을 구분해 보고한다.
```

SKILL.md라는 이름과 YAML frontmatter의 name·description이 필요하다. name은 실제 스킬 디렉터리 이름과 일치하는 1~64자의 소문자 영숫자·하이픈이다. 처음·마지막·연속 하이픈은 허용하지 않는다. description은 비어 있지 않은 최대 1024자 문자열이다. compatibility가 있으면 최대 500자 문자열이어야 하며 목록·본문·서버 API에 환경 요구사항으로 전달한다. 이 값의 변경도 본문 revision에 반영한다.

실제 YAML 파서를 사용하고 중복 키·잘못된 타입·과도한 중첩·alias·잘못된 UTF-8을 거부한다. README 대체나 자동 형식 보정은 하지 않는다. 잘못된 파일은 목록의 진단에 표시하며 다른 정상 스킬을 계속 조회할 수 있다.

disable-model-invocation: true와 선택적인 agents/openai.yaml의 policy.allow_implicit_invocation: false는 자동 본문 로드를 제한한다. 사용자의 명시 지정과 사용자용 미리보기는 허용한다. hooks·context·allowed-tools 실행 확장은 해석하지 않으며 warnings로 알린다. 스킬 파일이 MECA의 승인·접근 정책을 확대하지 않는다. 다른 클라이언트의 모든 실행 확장을 지원한다는 의미는 아니다.

## 사용자 호출과 모델 도구

!skills는 목록·출처·진단을 표시한다. Enter로 본문을 미리 보고 PgUp/PgDn으로 이동한다. 미리보기는 모델 요청을 시작하지 않는다. #를 입력하면 이름을 자동완성하며 Enter·Tab은 작성 중인 요청에 이름을 삽입한다.

목록의 첫 페이지는 새로 탐색하고 후속 페이지는 같은 메타데이터 snapshot을 읽는다. reader당 최대 8건·합계 8MiB의 독립 snapshot을 보관하므로 다른 요청의 목록 갱신이 기존 탐색을 바꾸지 않는다. 불투명 cursor는 최대 64바이트이며 같은 읽기 범위·마스킹 revision에서 2분 동안 유효하다. 만료·용량 회수 시 빈 cursor로 다시 시작하며 !skills는 한 번 자동 재조회한다. 이름 탐색·자동완성의 메타데이터 재사용 기간은 1초이며 설치 루트의 항목 변경·교체가 확인되면 즉시 다시 탐색한다. 본문은 캐시하지 않는다. 실제 load_skill·참고 파일 읽기는 현재 파일과 접근 정책을 다시 검사한다.

#review는 우선순위에 따라 선택한 본문을 첫 모델 판단 전에 읽는다. 동명 출처를 지정하려면 #project:review, #meca:review, #shared:review를 사용한다. 코드·인용·URL·이스케이프·일반 이슈 번호 #123은 호출로 해석하지 않는다. 숫자로만 된 이름은 출처를 함께 지정한다. 명시한 스킬을 읽지 못하면 모델 작업을 진행하지 않고 오류를 알린다.

심볼릭 링크의 설치 폴더와 실제 스킬 이름이 달라도 목록의 name으로 호출할 수 있다. 반환한 id는 설치 위치를 구분하며 load_skill·참고 파일 읽기에 그대로 사용한다. 동일 이름의 선택은 프로젝트·개인·공유 출처 순서를 따른다.

| 도구 | 역할 |
| --- | --- |
| list_skills | 이름·설명·환경 요구사항·출처·manual_only·warnings 조회. cursor·limit으로 다음 페이지 읽기 |
| load_skill | id 또는 스킬 디렉터리/SKILL.md path 중 하나로 본문 읽기 |
| read_skill_file | id와 스킬 루트 기준 상대 path로 참고 자료 읽기. 첫 페이지의 revision과 next_offset을 다음 offset·revision으로 전달 |

엔진은 모델 요청의 시스템 지침으로 실질적인 작업 전에 설명을 확인하고 필요한 본문을 읽도록 안내한다. 세 도구의 설명·인자별 사용법·JSON Schema를 각 Provider의 native tool 형식으로 함께 전달한다. 경로로 load_skill한 경우 참고 파일 조회에는 반환된 id를 사용한다. 목록에 모든 본문을 싣거나 별도 모델로 스킬을 선택하지 않는다. 선택과 적용은 에이전트가 판단하며 도구 제공 자체가 모델의 지침 준수를 보장하지 않는다.

경로는 project_root 기준이며 ~/는 실행 계정의 홈이다. 경로로 읽은 스킬의 불투명 ID는 reader의 최근 128개·경로 합계 512KiB 안에서 재조회할 수 있다. 사용 시 수명을 갱신하고 오래된 등록은 회수한다. 회수된 ID는 원래 경로로 다시 load_skill하여 등록한다. 참고 파일은 검증한 실제 스킬 루트 안에서 읽으며 manual-only 정책도 본문과 동일하게 적용한다. 명시적으로 지정한 스킬의 참고 파일 읽기 허용은 해당 요청에만 전달한다. 이미지 지원 요청에서는 기존 래스터 디코더로 이미지 자료를 전달하고, 다른 바이너리와 이미지 미지원 요청은 메타데이터만 반환한다. 스크립트를 읽어도 실행하지 않는다. Python·Node 등이 필요한 스킬은 그 환경을 별도로 준비해야 하며 MECA 설치 의존성으로 추가하지 않는다.

참고 파일의 형식 확인·텍스트 페이지·이미지 읽기는 같은 검증한 열린 파일을 사용하고 소유자가 닫는다. 이미지 디코딩 슬롯은 실제 이미지 처리에서만 사용하며 텍스트 조회를 막지 않는다. TUI의 본문 미리보기는 드문 줄 위치와 현재 화면 구간을 계산하고, 닫기·크기 변경·종료에서 해당 작업을 취소한다. 닫은 화면에 늦게 도착한 결과를 적용하거나 본문 참조를 보관하지 않는다.

텍스트 페이지는 원문 offset과 revision에 묶인다. 처음에는 offset 0에서 revision 없이 읽는다. next_offset이 양수이면 같은 id·path에 offset=next_offset과 해당 read_skill_file 결과의 revision을 전달한다. next_offset이 0이거나 없으면 읽기를 마친다. load_skill의 문서 revision은 이 값과 다르다. 파일 정체성·크기·수정/변경 시각 또는 마스킹 revision이 바뀌면 offset 0부터 revision 없이 다시 읽는다. revision은 MECA가 생성하는 읽기 계약이며 SKILL.md나 참고 파일에 작성할 항목은 아니다.

## 문맥과 기록

본문은 기존 메시지·도구 결과·이벤트 기록 경로에 보존한다. 현재 요청에서 읽은 지침은 문맥 압축 뒤에도 정확한 읽기 결과로 유지하며, 원래 결과가 아직 문맥에 있으면 보존용 사본을 추가하지 않는다. 새 요청에 별도 지침 상태를 자동으로 이월하지 않는다.

같은 스킬 ID는 요청 내 최신 읽기 한 건을 보존한다. 같은 ID·revision의 반복 읽기는 보존 항목을 늘리지 않고 다시 읽은 새 버전은 이전 보존 항목을 교체한다. 참고 텍스트는 파일·revision·offset별로 보존하며 파일 revision이 바뀌면 이전 페이지를 제거한다. 지침 보존 본문은 요청당 합계 8MiB 이내이며 초과한 자동 읽기는 일반 도구 실패로 반환한다. 원본 감사 이력은 그대로 보존한다. 모델 문맥용 투영은 메시지·모델·마스킹 revision이 바뀌었을 때 갱신하며, 매 판단마다 같은 지침을 다시 복사·마스킹하지 않는다.

팀에 명시한 스킬은 같은 읽기 결과를 전달하고, 자동 선택은 각 에이전트가 수행한다. 파일 변경은 이미 읽은 내용을 바꾸지 않는다. 다시 읽은 결과는 그 시점의 파일을 반영한다. 원본 기록에 본문을 보존하지만 참고 디렉터리 전체를 백업하지는 않는다.

공개 skill_loaded는 읽기 성공과 ID·이름·출처·버전을 알린다. 실제 지침 준수나 작업 완료를 증명하지 않는다. 본문은 스트림에 반복 전송하지 않으며 재접속 시 기존 history/detail로 읽기 기록을 조회한다. 별도 start.skills·active_skills·활성화 API나 전용 DB는 없다.

## 한도와 보안

| 대상 | 한도 |
| --- | --- |
| frontmatter·선택적 호출 정책 파일 | 각각 64KiB |
| SKILL.md 전체 | 256KiB |
| 목록 페이지 | 32건·약 16KiB, 진단은 제한된 크기로 제공 |
| 탐색 | 전체 루트 합계 4096개 디렉터리 항목·메타데이터 예산 8MiB |
| 참고 텍스트 페이지 | 64KiB. 원문 바이트 기준 next_offset 사용 |
| 경로 기반 등록 | reader당 128개·경로 합계 512KiB |

| 목록 snapshot 보관 | reader당 최대 8건·합계 8MiB, 2분 유효 |
| 현재 요청의 지침·참고 텍스트 보존 | 합계 8MiB |

실제 모델 문맥 예산도 적용하며 초과한 본문을 조용히 자르지 않는다. 페이지 양쪽에 걸친 인증정보도 마스킹한다. private 상태 접근은 스킬 범위에만 제한적으로 허용하고 일반 파일 도구의 보호는 유지한다. 사용자 스킬의 링크 공유는 허용하되 Bootstrap이 직접 관리하는 `~/.meca/skills`와 기본 스킬·참고 파일 디렉터리는 실제 디렉터리여야 한다. 참고 파일의 루트 이탈·보호 경로 우회·특수 파일은 거부한다. 이는 셸을 OS 샌드박스로 바꾸는 기능은 아니다.

설치·업그레이드는 사용자 스킬 디렉터리를 교체하지 않는다. uninstall은 기존 정책대로 ~/.meca 전체를 삭제하므로 그 아래 스킬도 삭제한다. 필요한 사용자 스킬은 백업한다. ~/.agents/skills와 프로젝트 스킬은 유지한다.
