# Study design record

Applies only to this example collection. Use the target application's actual brief, system and constraints when applying the skill. This record is descriptive; its palettes, dimensions, page sets and module structure are not instructions to reproduce another app. CSS theme blocks own exact values.

## Objects and composition

| Owner | Local design choice and reason |
| --- | --- |
| `databook/` | A light research frame with project modes above the work, local source disclosure and answer/evidence regions. This preserves central width at the cost of another step to consult sources. Citations reveal actual records. |
| `office/` | Bright file/tools around white document/slide content. Outline and filmstrip navigate actual objects; document/slides are parallel outputs. Tool titles stay compact while authored content receives more scale. |
| `approvals/` | Forest work navigation and a light operational desk. A single table supports status filtering; documents and itemized amounts sit beside review responsibility. |
| `database/` | Dark neutral smoke material, readable opaque SQL/results and restrained amber. Global destinations, open objects and result views are distinct. The schema tree earns persistent space through real hierarchy. |
| `archive/` | Minimal neutral collection tools and editorial detail with large images, serif subjects, captions and calm reading paper. Image-first detail moves metadata below the main media and increases scrolling. |
| `morrow/` | Photography and warm bounded glass navigation support first-time resource choice before grouped local booking input/review. |
| `booking/` | Space-first, schedule-first and familiar-input interpretations share the same local reservation rules. The leading information changes; object and commitment meanings do not. |
| `canvas/` | Real artifacts have page-local position/selection/scale with a retained inspector and non-drag controls. Placement is meaningful here rather than a decorative substitute for a list. |
| `motion/` | Explicit presentation previews and real local loading make the distinction between effect and observed state visible. |

The 36 routes share familiar native controls while retaining different tasks and composition. The collection is not one product with a different brand on each route. Navigation trees, outlines and filmstrips are task context rather than a reflex global left rail.

## Typography and color

Local Korean/system sans serves UI and reading; mono serves code/identifiers/measurements. Selected subject/wordmark roles use native serif. No font is fetched by these studies. Titles, authored content, metadata and operating labels have different roles; visual size does not mechanically follow HTML heading level.

Each app defines its own ink/surface, boundaries, action, selected context, focus and actual status. Archive illustrates a neutral base with rust action, cobalt selection/focus, plum content and forest saved/completed cues. These are role examples, not a palette for every project. Text/marks accompany state, and supporting facts retain readable contrast.

Dark/light relationships are chosen per study rather than via a global mode selector. Real projects should derive modes and accents from their usage context and existing identity. Do not import all example palettes into one application.

## Material and responsive hierarchy

Glass is opt-in through shared/glass.css with app-owned fill, opaque fallback and bounded blur. Unsupported effects, reduced transparency, increased contrast and forced colors retain readable surfaces and control boundaries. SQL, forms and sustained reading remain stable high-opacity work.

Archive's minimal base uses rules, type, spacing and functional accents. Editorial paper/content can carry more scale than surrounding tools. Other studies may retain material for a real layer; none requires every row to become a floating card.

Capped work regions grow gutters on wide displays; prose measure stays distinct from data width. Narrow windows recompose secondary panes or object navigation while keeping identity, focus and supported actions reachable. A viewport capture and full-page view demonstrate different aspects of that layout.

## Implemented presentation ownership

Shared base/components own native type/geometry and controls; motion.css owns motion/loading/media presentation. interaction.js owns menus/dialogs, bounded presentation motion and page cleanup. preview.js owns actual tabs/deep links and is loaded only by tab screens. The motion study owns its own demonstration drawer.

App styles own composition and identity. Approval form-group rules serve compose/settings; office-studio.css serves actual document/slide work; archive-editorial.css serves the three detail routes. Small controllers own citation reveal, outline navigation and local filtering. These files demonstrate one implementation and are not an architecture requirement for consumer projects.

Logical state changes before the visual cue. Repeated motion on one region cancels the old effect; handles finish/cancel or clear on preference/visibility/departure. Ordinary work does not replay page-load stagger. Selection, real citation emphasis, artifact replacement, saved marks and actual amount changes have localized cues. Direct manipulation stays direct.

Optional cross-document continuity uses real asset/room identity where supported; native navigation remains the fallback. Reduced motion preserves information and the current state without movement. Media uses genuine derivatives, reserved geometry and failure alternatives.

## Scope of evidence

Sample data is illustrative. Local demos do not establish authorization, reliable live availability, AI/SQL execution, persistence or export for a production service. Missing IDs and unsupported state remain explicit. All guidance and copying still follow the actual requested scope.

Markdown maps locate selected source and painted records directly; no overview gallery, copied upstream runtime or recursive load is required. Provenance and license records describe original images/icons and development evidence. Rendered polish, static checks and agent reviews are not whole-product or accessibility certification.
