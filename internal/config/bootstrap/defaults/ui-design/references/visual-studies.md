# Compare a decision with the task held constant

This level-2 map locates implemented comparisons, not presets. Use them to examine what leads, what stays visible and what a composition costs. Real projects need their own content, framework, state and service decisions; do not install all studies as product routes.

## One reservation, different entry points

| Case | Leading decision | Benefit and cost | Source |
| --- | --- | --- | --- |
| Space-first | Appearance, atmosphere, capacity | Rich inspection for an unfamiliar choice; more scrolling before input | [Exploration](../assets/examples/booking/booking-explore.html) |
| Schedule-first | Date, duration, resource/time comparison | Makes chronology comparable; needs space and reliable availability semantics | [Schedule](../assets/examples/booking/booking-schedule.html) |
| Familiar input | Known conditions and a fast commitment path | Groups ordinary fields and summary; offers less discovery for a new visitor | [Quick form](../assets/examples/booking/booking-quick.html) |

These implementations share illustrative resources and bounded local rules so their arrangement can be compared. Their current-tab draft, quote calculation and local result record are properties of the demonstration, not the business model or persistence design for another booking product.

Inspect [presentation styles](../assets/examples/booking/booking-studies.css), [view controller](../assets/examples/booking/booking-views.js), [sample booking rules](../assets/examples/morrow/booking-data.js) and [related presentation](../assets/examples/morrow/booking.js) only when code helps the present decision. Source choices do not establish server availability, payment, authorization or transaction guarantees.

## A spatial task earns a canvas

The [review canvas](../assets/examples/canvas/review-canvas.html) gives actual artifacts position, selection and manipulation. That earns a broad work surface, scale/fit controls and a retained inspector. Use a collection when placement adds no information; a canvas carries orientation and operating cost.

Its [styles](../assets/examples/canvas/review-canvas.css) and [controller](../assets/examples/canvas/review-canvas.js) demonstrate one page-local implementation with keyboard/non-drag paths and revision-aware reset. Transfer continuity and alternative operation, not fixed coordinates, sample artifacts or a required global module.

## Compare design rather than palette

Keep task, representative data, logical state and viewport stable. Examine:

- Information priority and how much comparison stays simultaneous.
- Main action, selected identity, scope and retained return context.
- Proportion, typography, density, geometry and image contribution.
- Material, accent meanings and the attention cost of motion.
- Missing/long content, failure, keyboard/IME, resized width/height and zoom.

A different accent is a valid refinement but not proof of a different structural approach. A more expressive frame can still use familiar controls. The better choice depends on actual context and evidence, not novelty or a diversity score.
