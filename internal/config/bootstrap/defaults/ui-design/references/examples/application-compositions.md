# Derive an application path from an ordinary request

These examples illustrate reasoning, not products to build verbatim. The same category can need another composition when frequency, information, risk or scope changes. State assumptions; do not treat the studies' page count, palette or data as requirements.

## Repeated request processing

A person needs to find, inspect and resolve records while retaining their query. A plausible path is collection → detail/action → confirmed result → restored collection. Scope/query, comparable fields, actual identity and next action lead. An inspector helps frequent consultation but consumes width; an independent detail gives long work more space.

Keep global areas distinct from local status filters and selected records. Use a board only when stage movement helps more than comparison. A KPI home, activity feed, billing suite and promotional hero require another actual job.

## Analysis with evidence

A person needs to decide what deserves attention. Start with question/scope → useful summary → evidence → underlying record/follow-up. Define quantities, units, comparison basis and missingness. A chart earns space when it explains a real relationship; an ordered table may serve better.

Use accent for actual categories, selected evidence or important state with stable meanings. A futuristic or dark brief still needs genuine data. Do not invent a trend to fill the visual frame.

## Grounded research or AI work

A person needs to provide context and inspect a useful result. Compose input/source scope, action, artifact/evidence and actual progress/recovery. Conversation is optional. A structured input and document/data result may be clearer than an empty chatbot.

Sources can be persistent when repeatedly compared, or disclosed locally when consulted occasionally. The first choice costs width; the second costs visibility and another action. Citations remain recognizable and resolve to actual records. Streaming text and transport activity do not confirm artifact completion.

## Authoring several formats

A person organizes a brief and works on a document or presentation. Separate project/file identity, tools, object structure, content and relevant assistance. A document outline and slide filmstrip are task navigation; the artifact can have more scale than the application title.

Parallel formats need not form a compulsory wizard. Keep their shared source meaning while giving each output a suitable composition. A familiar authoring model can be useful without copying another brand's colors or implementing its entire editing engine.

## Content discovery and editorial detail

A person explores objects, then reads or inspects one. A collection may emphasize thumbnails and concise metadata; detail may give a subject, title, genuine image and caption more space. Keep a clear return and supported action. Decide whether metadata must remain alongside the image or can follow it in the reading flow.

A minimal base can carry editorial contrast and several functional accents. That does not require serif, cream or an all-neutral palette. If the person is rapidly administering files, a retained metadata inspector may outperform image-first detail.

## Booking from different knowledge

An unfamiliar visitor compares atmosphere/capacity; a date-driven team compares time/resource; a repeat visitor knows the conditions. Those lead respectively to visual discovery, a schedule matrix or grouped input with summary. Each must keep the actual choice, conditions, commitment and recovery clear.

A local demonstration can illustrate the arrangement. A real service needs actual availability/confirmation semantics when in scope. Selecting a free-looking slot or reaching a final segment does not confirm a reservation.

## A staged import

Choose source → mapping → review → execution/results only if dependencies justify those stages. A stage navigator locates input decisions; actual processing needs separate observed status/progress. Keep valid input and confirmed successes through partial failure. Do not add a stage for symmetry or infer 75% from stage 3 of 4.

## A public explanation

A visitor needs subject, useful evidence and a next action. Let genuine product/media or specific type lead; include only continuation that resolves real adoption questions. A public opening can be expressive without introducing its hero and effects into every working screen.

For any request, walk the smallest complete path and check information visibility, action/state, interruption and return. An attractive fixture is not a demand signal, integration result or optimum design. Loading the skill does not authorize unrelated rebuilding or external publication.
