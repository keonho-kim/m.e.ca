# Keep orientation without letting chrome lead

The shell identifies the product and relevant workspace, exposes useful destinations and leaves room for the work. Choose its information scope before its material. Reuse the target application's navigation language for ordinary feature work.

## Distinguish navigation layers

| Layer | Meaning | Useful representation |
| --- | --- | --- |
| Global area | A substantial product destination | Top links or grouped side navigation |
| Organization/project/environment | Which work and permissions apply | Visible context; a switcher only when switching exists |
| Task object | A schema, document section, slide or file | Tree, outline, filmstrip, list or object tabs |
| Local view | How the same object/collection is inspected | View control, genuine panel tabs or filters according to behavior |
| Workflow stage | A dependent input decision or actual job state | Stage navigator or status representation, not generic location tabs |

A content tree can be valuable beside a canvas even when global destinations sit above it. Do not remove an outline merely to avoid sidebars, or add a global rail because one appears in a SaaS reference. Parallel document/slide outputs are not automatically consecutive wizard stages.

## Choose persistent space by repeated need

A shallow peer set often fits top navigation and preserves width. A substantial hierarchy can earn a grouped rail. Focused authoring/reading can reduce global chrome while keeping an obvious return and object identity. Occasional administration may fit a secondary destination or contextual menu; frequent core work should remain discoverable.

Preserve visible workspace identity when simplifying the header. Avoid competing global, project and local selections that all look equally active. Labels, position and emphasis should make their scopes readable, including when names are long.

## Frame the work

Provide meaningful page/object context, the main action, task controls, work and appropriate feedback/continuation. Merge roles where useful; do not repeat a breadcrumb, title and explanatory card that all say the same thing. A greeting or KPI strip is not a substitute for the person's next task.

Reserve useful minima for the primary object before adding inspectors. Let prose cap its measure and data use comparative width. A filename toolbar can stay compact while the artifact itself has substantial scale.

Use material to explain a real work or navigation layer. A minimal rule, opaque paper or restrained glass can each be appropriate. The shell does not prescribe an accent, light/dark mode, radius or sidebar geometry for every product.

## Adapt and check

Choose clear scroll owners. Sticky context/actions must leave the last field, row and focused control reachable. At narrower width or zoom, recompose secondary context into a temporary panel or route before shrinking essential type. Restore selection, query, draft and return location through the existing navigation model.

Keep the known safe frame usable during local loading; unresolved access is not an enabled account. Check direct/deep links, browser back, scope changes, menus near viewport edges and keyboard access. Add search, notifications or account tools only when their actual service exists.
