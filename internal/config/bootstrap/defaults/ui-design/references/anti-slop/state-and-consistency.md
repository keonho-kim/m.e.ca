# Truthful state, motion and system consistency

Read only the relevant findings; preserve intentional themes and the actual product task. Source revision and finding classification are owned by the [anti-slop map](../anti-slop.md).

## 6. Liveness and motion correspond to real change

Pulsing dots, decorative typing cursors, automatic marquees and habitual bounce can simulate activity. A live indicator should follow actual state; a progress value should follow measured work. An editable field supplies real input and caret behavior.

Use transitions to explain context, selection or outcome, preserving interruption and reduced-motion behavior. Do not animate every region with the same entrance. Expressive motion can be intentional, but it must not invent work or delay the task.

The [loading and progress reference](../loading-and-progress.md) makes this operational: region skeletons end in real content/empty/error states, refresh does not erase useful work, and percentages need measured scope. Do not use page-wide shimmer, fabricated 99% completion, endless placeholder answers or successful-looking step markers to disguise an unresolved state. A stepper needs actual task stages; artificial steps and mandatory tours do not improve a simple form.

Source cues: `pulsing-dot`, `blinking-cursor`, `marquee`, `bounce-easing`.

## 8. The system stays coherent across pages

The source checks font, color, radius and type-size drift. Use the actual project roles. A local exception needs a reason; writing an unreadable size into a token does not make it good.

Distinguish a missing reusable role, a one-off implementation, a conceptual mismatch and a local defect. Fix each at its owner. Refinement preserves the application instead of smuggling a new page map or identity into a small cleanup.

Source cues: `design-system-font`, `design-system-color`, `design-system-radius`, `design-system-font-size`.

## Keep shared rules and local expression distinct

A repeated control should retain its meaning and state cues across routes. Content can change scale: minimal navigation may lead to editorial reading, while a data view keeps compact comparison. That variation does not require a different brand or another global navigation model.

Use one logical collection/form where alternate presentation shares actual identity. Independent facets such as saved scope and file type remain independent. A transition or parallel output choice must not manufacture another data copy, compulsory stage or success state.

The reference guide owns the reasoning. Concrete filenames, palettes, sample numbers and module/lifecycle choices belong to a case study. Copying them without their purpose can create system drift even when the screenshot looks consistent.

## Variation must have a job

Infer information and interaction from the task before choosing a variant. A cost breakdown may stay visible during comparison and be disclosed during occasional inspection. Repeated work may keep a stable inline control while a consequential decision warrants interruption. A coherent system can accommodate both; it need not make different jobs uniform or reproduce a named recipe.

Expressive Swipe, Blinds and Depth Stack need a concrete purpose, preserved focus/input, interruption and reduced-motion alternatives. Keep useful familiar behavior, real content and truthful state. If a polished effect hides a dependency, false success or empty region, correct that cause. Neither unfamiliar novelty, a large recipe count nor fewer detector warnings establishes usability.
