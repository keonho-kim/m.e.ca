# Administrative workspace implementation Q&A

## What happens when an operator changes workspaces during a request?

Bind the proposal and fetch to their original workspace and target. Apply a result only to the matching view or show that earlier operation's result in scoped history. Never direct an earlier approval or bulk action at the newly opened workspace.

## How should invitations behave after permissions change?

Check current invitation state, expiration, recipient eligibility and allowed role at redemption. If the inviter's current authority is part of the product rule, verify it then too. Accept the same intended membership once and route expired or revoked offers to the approved recovery path.

## Which records belong to a bulk operation?

Define visible IDs, an explicit selection or all matches as a user-facing choice when those actions exist. Bind the accepted scope and independently check each record at execution. A partial outcome includes the items that can be checked or retried safely.

## What does approving an edit authorize?

Approve a specific proposed revision and actor or method when relevant. Changes to material data or target cause re-review according to the workflow. Name what the accepted approval can trigger and keep a durable link from approval to outcome.
