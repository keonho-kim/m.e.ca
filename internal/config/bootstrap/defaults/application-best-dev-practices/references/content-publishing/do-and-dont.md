# Content publishing Do & Don’t

| Decision | Do | Don’t |
| --- | --- | --- |
| Draft and public version | Maintain an explicit active publication and identifiable draft revisions. | Expose draft saves to the public route by default. |
| Preview | Use the requested revision and current audience policy. | Provide a preview reference that grants broader or permanent access by accident. |
| Import from a restricted source | Review the selected text, attachment versions and destination audience together. | Publish private discussion links, notes or attachments just because they were visible to the editor. |
| Review | Record reviewer, scope and exact revision when approval matters. | Release edits under an approval for materially different content. |
| Publish | Validate prerequisites and confirm the outcome at the owned boundary. | Replace the visible version while a required asset or check is unready. |
| Scheduling | Specify time basis, revision selection and cancellation behavior. | Assume each scheduled request will run once or pick content according to an undocumented rule. |
| Restore and withdraw | Define effects on active release, routes, previews and history. | Treat editing history as equivalent to making a revision public. |
