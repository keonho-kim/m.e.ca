# Select a useful application path

Use the recurring task to derive the page map. A category suggests questions to investigate, not a mandatory page bundle, palette or navigation frame. Select the smallest complete path within the request.

| Tendency | Representative path | Information that usually leads | Conditional additions |
| --- | --- | --- | --- |
| Operations, CRM, records | Query → inspect → create/change → return | Comparable fields, record identity, next action | Bulk work, saved views, assignment history |
| Analytics | Scope → interpret → inspect evidence → follow up | The question, units, comparison and exceptions | KPI summary, charts, export, schedules |
| Workflow/project work | Find project → inspect work → change stage | Meaningful state/sequence, ownership, dependencies | Board, timeline, workload, automation |
| Inbox/support | Find case → read context → respond/assign → resolve | Case history, draft, current responsibility | Templates, customer context, SLA, knowledge help |
| Knowledge/media | Discover → read/inspect → retain/share → return | Content, source identity, useful metadata | Topic tree, TOC, versions, authoring |
| AI-assisted work | Select context → request → inspect artifact/evidence → refine | Input scope, usable result, actual execution state | Conversation, citations, versions, comparison |
| Document/presentation creation | Brief/input → organize → author → review | The authored artifact and its structure | Outline, filmstrip, preview, collaboration |
| Developer/data tools | Select environment/object → inspect/configure → examine result | Object identity, code/data, result context | Logs, history, credentials, deployment |
| Catalog/commerce | Discover/compare → inspect → supported commitment → result | Decisive content, conditions, actual price/scope | Cart, payment, reviews, fulfillment |
| Booking/scheduling | Date/resource → compare slots → review → reserve/manage | Resource, time, capacity and confirmed selection | Recurrence, waitlist, reminders |
| Learning | Discover → read/practice → continue → review progress | Current material, sequence and actual achievement | Assessment, discussion, subscription |
| Administration/settings | Select scope → inspect grouped values → apply → confirm | Account/workspace/object scope and consequences | Roles, policy, billing, audit |

## Derive screens and regions

For each selected screen name its task, working object, necessary information, main action, return context and applicable empty/loading/error state. Mark supporting regions as conditional. A practical inventory might contain a query/results view, an independent detail, an editor and a result/recovery state; it need not contain four separate routes.

Do not create authentication, onboarding, a dashboard, billing or an activity feed unless that work exists. A useful empty state may lead directly to the first object rather than a promotional tour. A request to improve one existing screen does not authorize the entire matrix.

## Choose the organizing axis

Use rows for repeated-field comparison, a board for meaningful state movement, a timeline for time, a reading surface for sequential content and a canvas for spatial relationships. A conversational input is appropriate when conversation improves the work; AI alone does not imply a chat-first application.

An app can offer distinct modes when each serves a recurring need. A document and a presentation can be parallel outputs of one source rather than successive wizard stages. Source evidence may need concurrent inspection or a local disclosure depending on how often it is consulted.

Keep the public explanation and repeated work distinct. The public surface establishes subject, evidence and a supported next step; the working app retains context and supports decisions without a promotional opening in every route.

## Adapt the visual direction

Choose density, typography, image role, material, accent and light/dark from the use scene. Technical work does not mandate darkness, content does not mandate cream, and SaaS does not mandate a left rail. Different tasks inside one app can have different content scale while retaining shared semantics.

Walk one object through the complete path with representative content. Check whether each page advances the task and whether state, selection and return stay coherent. A polished set of unrelated screens is not a complete application.
