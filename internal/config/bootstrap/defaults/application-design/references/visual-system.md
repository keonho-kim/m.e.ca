## Separate decisions that are often confused

**Task structure** determines what belongs together. **Visual language** determines proportion, type, geometry and emphasis. **Material** determines the treatment of a surface. **Motion** explains selected changes. A theme name does not choose all four.

A minimal base can support editorial detail; a frosted tool layer can surround an opaque work surface; a dense data tool can use a strong accent without neon. Assign a treatment to a real role and keep action/state meanings stable. Different intensity inside one product is useful when it follows content, not a new brand on every route.

## Diagnose weak design at its cause

| Observation | Investigate before adding decoration |
| --- | --- |
| Everything feels flat | Type contrast, region hierarchy, meaningful boundaries and which object should lead |
| Everything feels alike | Repeated frame, information order, density, image role and navigation scope |
| The page feels washed out | Functional text/boundary contrast, accent placement and selected/focus distinctions |
| The page feels busy | Competing primary signals, redundant wrappers, badges and repeated motion |
| The work feels small | Space spent on chrome versus the object, simultaneous comparison and useful minima |

Professional clarity does not require one corporate palette or a global sidebar. Restraint means fewer unjustified decisions, not weak contrast or suppressed action.

## Define roles, then apply them

Use the project's token/component mechanism for canvas, working/raised/overlay surfaces, primary/supporting ink, rules, interactive boundaries, action/paired ink, selection, focus and real status. Define only roles with consumers. Typography, spacing, radii and elevation should describe the same relationships across views.

Keep prose measure separate from data width. Align repeated rows and related actions. An editorial title or authored page can have more scale than its surrounding file toolbar. Dense controls can remain compact while their hit areas and labels stay usable. Inspect actual Korean copy and fallback fonts.

A neutral base may carry several recognizable accents, distributed where actions, categories and state need distinction. Their meanings and contrast matter more than equal area or a fixed color count. Dark/light decisions follow the use scene and intended support, not the app category.

## Carry the system through state and adaptation

Test default, hover, focused, selected, disabled, pending and error where those states exist. Keep focus distinct from selection and information readable when transparency, shadows or motion disappear. A region-level material change must not change navigation semantics or persistence claims.

At different widths and heights, preserve the leading task and recompose supporting panes before shrinking essential text. Review sparse, long, failed and busy content as applicable. If a correction only swaps a color while the information relationship remains wrong, return to composition.

Use [quality checks](quality.md) to connect the direction to observable evidence. Do not treat an attractive asset, static token calculation or detector score as proof of a useful system.
