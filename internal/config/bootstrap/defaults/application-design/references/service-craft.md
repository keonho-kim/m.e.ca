# Learn a design principle from a service, not its skin

Use a real service reference to answer a question about hierarchy, content, learned operation or feedback. Inspect the relevant platform/version or supplied visual instead of recalling a brand palette. Transfer the relationship and adapt it to the current product; a recognizable name does not establish fit.

## Extract what changes the decision

| Reference emphasis | Transferable question | Boundary |
| --- | --- | --- |
| Content and control layers | What should lead, and which tools remain nearby? | A material choice is not the service's entire identity |
| Familiar operation | Which visible controls supplement shortcuts/gestures? | A copied shell may hide different work |
| Expressive hierarchy | How do type, proportion, shape and color direct attention? | Mobile or marketing evidence does not prove a desktop work layout |
| Continuity | What identity/context survives opening, selection or return? | An effect does not establish saved state or routing semantics |
| Authoring workspaces | How do file, tools, object structure and authored content differ? | Familiarity does not require copied logos, exact colors or an editing engine |
| Media/editorial detail | When does image/story scale outweigh metadata density? | More scrolling can be a real cost for repeated inspection |

Editorial, minimal, corporate, technical and tactile are design directions to interpret, not brand recipes. A neutral base can support several meaningful accents; an entire product need not become monochrome to look considered. Conversely, color cannot replace useful information structure.

## Work from evidence to a fitting result

Establish audience, actual task, existing product, scope and intended outcome. Capture the incumbent interface for a redesign and inspect relevant real/supplied material for new work. Name what transfers: density, reading order, navigation scope, tool placement, imagery or state feedback.

Build the requested complete path with representative content, truthful destinations and recovery. Do not add an entire service because a reference contains account, billing, AI or database features. A precise request can proceed from settled context; an unresolved consequential choice needs a concise question rather than an obligatory interview.

Render and compare the real result against the brief, then interact with the principal task. Fix the largest observed hierarchy/behavior problem before adding more decoration. A source screenshot, generated comp and working prototype provide different evidence; an agent inspection is not a user study.

## Recurring lessons to adapt

- Give actual objects useful scale: images for visual choice, aligned fields for comparison, a reading measure for prose and a canvas only for meaningful position.
- Distinguish global navigation, current workspace/project, object navigation and local views. A shallow service can use top links while an outline/tree remains beside its work.
- Keep decisive facts visible; disclose occasional detail. A menu, value choice, route and stage can share appearance without sharing semantics.
- Preserve identity, relevant drafts, applied scope, reading position and return. Motion explains selected change rather than creating its outcome.
- Give action, selected context, category and real status deliberate color roles. Keep labels and focus useful when effects disappear.
- Match loading to the withheld region, preserve usable refresh context and reveal genuine media/output without artificial waiting.

The [case maps](code-examples.md) illustrate some interpretations. They are local original studies, not evidence that the featured companies implement every named effect or that one composition is optimal.

## Sources and scope of inference

[Apple motion](https://developer.apple.com/design/human-interface-guidelines/motion), [sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [materials](https://developer.apple.com/design/human-interface-guidelines/materials) and [color](https://developer.apple.com/design/human-interface-guidelines/color) inform relationship and platform questions. HIG does not prescribe every web application's material.

[Meta's Instagram Lite case](https://www.meta.com/design-at-meta/blog/instagram-lite-a-global-collaboration-between-research-and-design/) is a 2022 mobile study, useful for thinking about content, visible alternatives and constrained conditions; it is not a current desktop benchmark.

[Google's expressive research](https://design.google/library/expressive-material-design-google-research), [paper](https://research.google/pubs/usability-hasnt-peaked-exploring-how-expressive-design-overcomes-the-usability-plateau/) and [motion guidance](https://m3.material.io/styles/motion) inform hierarchy and learned operation, not a guarantee of this app's performance.

[Hallmark's Studio example](https://www.usehallmark.com/themes/studio/) and [pinned completed source](https://github.com/Nutlope/hallmark/blob/407fa689f4a276f2fd389208d271d0fef08f5058/site/made/cobalt-database-client/index.html) informed subject-specific composition. Their commands, source assets and house-style bans are not required by this skill. Product Design informed the evidence → complete path → render/interact → refine method; no plugin, fixed-option ceremony or publishing action is implied.
