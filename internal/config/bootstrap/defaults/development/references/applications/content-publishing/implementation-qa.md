# Content publishing implementation Q&A

## What should stay visible if publishing fails?

Keep the last accepted public release when preparation fails and the workflow promises continuity. Preserve the candidate revision for correction or retry. If projections can lag, show the actual public state and the status of the attempted release.

## Which revision does a scheduled publication release?

Choose whether scheduling pins a selected revision or intentionally follows edits under a defined contract. Show that choice to the editor. When review matters, bind the reviewed revision and re-evaluate any material change before the schedule fires.

## How should a draft preview be shared?

Resolve the authorized audience when a preview opens, with a bounded capability only if the promised expiry and revocation allow it. Include media and generated previews in that scope. Make it clear which version is being reviewed and what action can publish it.

## Does restoring a revision publish it?

Define the two operations in the product. Restoring can create a new draft for review. An explicitly authorized rollback can switch the active release to an eligible prior revision. Verify the intended effect at its own boundary and preserve useful authorship and history.

## How can an internal answer become a public article?

Create a restricted draft sourced from the selected answer revision. Select text and attachments explicitly, and bind review to the intended public release. Check that the editor may release that material and the prepared files may reach the destination audience. Decide whether source withdrawal invalidates a draft or requires later withdrawal. Keep the original source and any private assets under their existing access policy.
