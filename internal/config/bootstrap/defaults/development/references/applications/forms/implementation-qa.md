# Forms implementation Q&A

## What happens to answers in a section that becomes hidden?

Choose whether to retain them in the draft for returning to that branch. On submission, evaluate the active path for the version and include only the data defined for that outcome. Tell people when a change removes already-entered values that cannot be recovered.

## What should happen when the form changes mid-draft?

Use a version-specific policy. Accept a supported older version, or explain the changed fields and allow review against the new version. Keep values that retain their meaning. A renamed choice or changed consent text may require a new explicit answer.

## How should duplicate submissions be handled?

Separate rules for one response per person or invitation from technical retries of one attempt. Carry a stable request identity across retries where the service supports it. If acceptance is uncertain, let the user recover the accepted result before sending again.

## When should an error summary appear?

Use inline explanations for local correction. After a failed final submit, a summary can link to applicable fields when there are several issues or sections. Keep the field-level cause visible and preserve valid input, branching and draft position.
