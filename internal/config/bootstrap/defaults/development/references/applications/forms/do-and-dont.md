# Forms Do & Don’t

| Decision | Do | Don’t |
| --- | --- | --- |
| Branching | Use the same applicable-field rules at entry and final submission. Explain meaningful changes to prior input. | Accept hidden values or demand answers from a section that does not apply. |
| Validation | Associate errors with their fields and reveal the relevant section after a failed submit. | Clear valid values or hide errors in collapsed sections. |
| Form version | Keep enough question and answer metadata to interpret older submissions. | Explain all historical answers using only the latest question text and options. |
| Submission identity | Define the permitted response count and retry identity for the actual actor or invitation. | Treat every repeat click as a fresh response. |
| Confidentiality | Define the audiences for viewing individual answers and aggregate results. | Expose a private answer through an unscoped results or export action. |
| Follow-up | Show the recorded submission and any pending processing distinctly. | Require a resubmission just because a confirmation message was not delivered. |
