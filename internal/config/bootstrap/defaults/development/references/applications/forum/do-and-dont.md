# Forum Do & Don’t

| Decision | Do | Don’t |
| --- | --- | --- |
| Topic and reply references | Preserve stable identities across edits, moves and permalink navigation. | Store display positions as the identity of replies. |
| Moderation | Apply current permissions to create, edit, view, search and export. Record the authorized decision where moderation history is needed. | Rely on hidden buttons or CSS to protect unpublished text. |
| Lock and review | Check the current state again when accepting a reply. Explain the outcome and preserve unsent text when posting becomes unavailable. | Let a stale composer bypass a lock or consume the user's draft. |
| Deletion | Decide the fate of replies, quotes, accepted-answer pointers and generated previews. | Leave removed text visible through quoted snippets, caches or indexes in the scope the app controls. |
| Listing | Define the pin range, sort order and tie breaker. Show the current filter and category on return. | Place the same pinned topic in every page of ordinary results. |
| Q&A | Allow the permitted actor to choose and replace an eligible answer. | Infer an accepted answer from vote count unless the product defines that rule. |
